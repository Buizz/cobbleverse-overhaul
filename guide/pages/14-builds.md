# 14. 빌드 작업

빌드 작업 탭은 허용된 검사·생성·패키징 명령을 브라우저에서 안전하게 실행하고 결과를 확인하는 화면입니다. 자세한 배포 절차는 [빌드와 배포](../build-and-deploy.md)를 함께 참고하세요.

[사진: 빌드 작업 전체 화면. 독립 건축 월드, 명령 카드, 실행 결과 터미널 표시]

## 일반 명령 실행

웹 화면에서 다음 명령을 실행할 수 있습니다.

| 버튼 ID | 설명 | 권장 시점 |
|---|---|---|
| `validate` | 콘텐츠와 의존성 검사 | 편집 전후, 빌드 전 |
| `test` | Python 도구 회귀 테스트 | 기능 변경 후, 배포 전 |
| `generate` | RCT와 게임용 AI 프로필 생성 | NPC·배틀 변경 후 |
| `pack-smoke` | 최소 CurseForge 임포트 ZIP 생성 | 임포트 환경 점검 |
| `pack` | 개발용 CurseForge ZIP 생성 | 통합 테스트용 패키지 필요 시 |
| `validate-pack` | 실제 모드팩 빌드 준비 상태 엄격 검사 | 정식 배포 준비 시 |

1. 실행할 카드의 `실행`을 누릅니다.
2. `실행 결과`의 상태가 대기 중에서 실행 중으로 바뀌는지 확인합니다.
3. 작업이 끝날 때까지 같은 명령을 다시 누르지 않습니다.
4. 터미널 출력의 첫 오류부터 해결합니다.

[사진: validate 성공 결과가 표시된 웹 터미널]

`pack`은 여러 생성·빌드 단계를 포함하므로 PC에 따라 오래 걸릴 수 있습니다. 브라우저를 닫거나 서버를 종료하지 마세요.

## 독립 건축 월드 연결

### 최초 설정

1. CurseForge에서 건축 프로필을 둘 인스턴스 폴더를 준비합니다.
2. `CurseForge 건축 프로필 인스턴스 경로`에 **프로필 폴더**를 지정합니다.
3. `경로 저장`을 누릅니다.
4. 요약에서 건축 팩, 월드, 내보낸 NBT, 저장소 NBT 상태를 확인합니다.

월드는 지정 폴더 아래 `saves/Cobbleventure Structure Builder`에서 자동으로 찾습니다.

### 건축과 가져오기

1. `건축 팩 빌드`를 눌러 독립 CurseForge ZIP과 월드를 생성합니다.
2. CurseForge로 팩을 임포트하고 게임에서 건축 월드를 엽니다.
3. 관리 대상 구조물을 편집합니다.
4. 게임 명령 `/cobbleventure_builder save all`로 NBT를 내보냅니다.
5. 게임을 종료하거나 월드 저장이 완료됐는지 확인합니다.
6. Content Studio에서 `게임 NBT 자동 가져오기`를 누릅니다.
7. 가져온 파일 수와 터미널 결과를 확인합니다.
8. `NBT 건물 설정`에서 목록을 갱신하고 3D 모델을 확인합니다.

[사진: CurseForge 인스턴스 경로와 건축 월드 상태가 모두 연결된 화면]

가져오기는 저장소의 관리 NBT를 바꾸는 작업입니다. 예상한 구조물만 내보냈는지 먼저 확인하고, 가져온 뒤 Git 변경 목록을 검토하세요.

## 권장 실행 순서

일반 콘텐츠 작업:

1. `validate`
2. `generate`
3. `test`
4. `pack`

건축 작업:

1. 건축 팩 빌드
2. 게임에서 건축 및 `save all`
3. 게임 NBT 자동 가져오기
4. NBT 3D 확인
5. `validate`
6. `test`
7. `pack`

## 결과 해석

- 종료 코드 0 / 성공: 다음 단계로 진행
- 경고만 있음: 개발 작업은 가능할 수 있으나 배포 조건인지 확인
- 오류 또는 비정상 종료: ZIP이 있더라도 사용하지 말고 원인 수정 후 재실행
- `validate-pack` 실패: 의존성 Lock이나 모드 버전·CurseForge ID가 미확정일 수 있음

현재 `pack-release`는 웹 버튼에 없으며 정식 배포 내보내기도 아직 완성 전입니다. 개발 팩을 정식 릴리스로 배포하지 마세요.
