# 전투 AI 아키텍처 기준

## 참고 기준

- 참고 저장소: `Buizz/Cobblemon-RunAndBunAI`
- 조사 브랜치: `0.15.3_beta`
- 조사 커밋: `f40ecb909d9743cdf6754bac2b282c534dd153ab`
- 참고 저장소 라이선스: MIT
- 조사 시점 구성: Java 21, Gradle 8.14.3, Minecraft 1.21.1, Cobblemon 1.7, Fabric와 NeoForge, RCT API
- 실제 연동 목표: 정식 출시된 Cobblemon 안정 버전. 정확한 패치 버전은 게임 어댑터 착수 시 확정.

참고 저장소의 소스는 복사하지 않는다. 구조와 실패 지점을 조사해 Cobbleventure 요구사항에 맞는 새 계약과 엔진을 작성한다.

독립 전투 규칙 엔진, JVM·웹 공통 실행과 AI 가상전 계획은 [AI 엔진 개선 계획](IMPROVEMENT_PLAN.md)을 기준으로 한다.
특수 효과의 구현 완전성은 [전투 규칙 완전성 계획](MECHANICS_COVERAGE_PLAN.md), 에이스·판깔이·막이와 난수 전략은 [전략 AI 계획](STRATEGIC_AI_PLAN.md), 팀별 성향 선택은 [전략 아키타입 및 팀 분석 계획](STRATEGY_ARCHETYPES_AND_TEAM_ANALYSIS.md), 팀 프리뷰·전투 상태 승률과 자기대전 학습은 [승률 모델 계획](WIN_PROBABILITY_MODEL.md)에서 관리한다.

## 참고할 부분

- Minecraft 의존성이 없는 AI 코어 모듈
- 불변 전투 스냅샷과 명시적인 행동 후보
- 선택 점수뿐 아니라 규칙별 판단 근거를 남기는 방식
- CLI·가상 전투·고정 시나리오를 통한 회귀 테스트
- 기술과 교체를 동일한 결정 목록에서 비교하는 방향

## 새로 설계할 부분

참고 구현의 메인 Cobblemon AI 진입점은 전투 상태 추적, Cobblemon 변환, 후보 생성, 예측, 결정과 응답 생성을 넓게 소유한다. 프로젝트가 커질수록 다음 문제가 생길 수 있으므로 책임을 분리한다.

```text
Cobblemon/RCT 전투 객체
  → BattleObservationAdapter
  → 공개 정보만 가진 BattleObservation
  → 난이도 정책이 허용한 OpponentKnowledge
  → ActionCandidateGenerator
  → OutcomePredictor
  → DecisionEngine
  → DecisionResult + 설명 추적
  → BattleCommandAdapter
  → Cobblemon/RCT 행동 응답
```

| 경계 | 책임 |
|------|------|
| 관측 어댑터 | 게임 객체를 플랫폼 독립 공개 정보로 변환 |
| 정보 정책 | 공개 정보 예측 또는 최고 난이도의 잠긴 상대 행동을 권한에 따라 제공 |
| 후보 생성기 | 현재 턴에 가능한 기술·교체·아이템·기믹 생성 |
| 결과 예측기 | 후보별 피해, 생존, 상태 변화와 불확실성 계산 |
| 결정 엔진 | 동일 효용 척도로 후보 비교 |
| 명령 어댑터 | 선택 결과를 실제 Cobblemon 응답으로 변환 |
| 전투 세션 | 상대가 공개한 정보와 턴 사이 기억만 보존 |
| AI 작업 실행기 | 메인 틱 밖에서 판단하고 동시성·시간 초과·취소·폴백 관리 |
| 회귀 도구 | 고정 입력의 선택, 순위, 근거와 성능 비교 |

## 실행 권위와 계산 위치

Minecraft 서버가 전투 상태와 최종 행동의 권위를 유지한다. AI 계산은 불변 관측 스냅샷을 받아 서버 내부 Worker Pool이나 별도 신뢰 프로세스에서 실행하며, 완료 결과는 원래 상태의 입력 해시와 일치할 때만 적용한다.

플레이어 클라이언트는 공개 멀티플레이에서 NPC의 최종 행동을 확정하지 않는다. 클라이언트 위임은 싱글플레이·웹 실험실·공개 정보 기반 보조 계산으로 제한하고, 서버가 없어도 되는 실행 모드와 서버 권위 모드를 같은 계약 위에서 분리한다.

시간 초과, 워커 장애 또는 오래된 결과에는 결정론적 안전 AI를 사용한다. 자세한 부하 제어와 배치 선택지는 [승률 모델 계획](WIN_PROBABILITY_MODEL.md)을 따른다.

## 현재 골격의 의도

`ai-api`에는 게임 플랫폼과 무관한 최소 계약만 둔다. `ai-engine`은 합법 후보 필터와 결정론적 순위 계산만 담당한다. `WeightedFeatureRule`은 엔진 확장 지점을 검증하기 위한 임시 일반 규칙이며 실제 전술 밸런스를 확정한 것이 아니다.

현재 모델의 `features` 맵 역시 초기 골격용이다. 행동 결과 스키마가 정해지면 문자열 기반 특징을 타입이 있는 예측 모델로 교체한다.

## 금지할 결합

- AI 엔진에서 Cobblemon 전역 싱글턴 직접 조회
- 전투 기믹을 AI 선택 밖에서 자동 발동
- 후보 생성기가 실제 게임 명령까지 실행
- 시뮬레이터만 사용하는 별도 전술 규칙
- 상대의 공개되지 않은 기술·아이템·교체 후보를 확정 정보로 전달
- 플레이어 클라이언트에 미공개 팀 정보나 잠긴 상대 명령 전달
- 공개 멀티플레이 클라이언트의 AI 결과를 검증 없이 최종 행동으로 채택
- AI 탐색으로 Minecraft 메인 틱 스레드 블로킹
- 난수 시드와 동점 규칙을 기록하지 않는 비결정적 선택
- 이유가 남지 않는 임의 점수 보정

## 단계별 확장

### 1단계: 계약

- 포켓몬, 필드, 날씨, 상태와 공개 정보 스키마
- 행동별 타입 모델
- 불확실성을 포함한 결과 예측

### 2단계: 단일 전투

- 피해·선후공·KO·교체 위험
- 상태기와 랭크 변화
- 상대 행동 분포

### 3단계: 게임 비의존 어댑터 계약

- 공통 트레이너, 파티, 공개 전투 상태와 행동 응답 계약
- 지원되지 않는 게임 기능의 명시적인 오류 모델
- 가짜 어댑터를 이용한 세션 수명주기와 회귀 테스트

### 4단계: 실제 게임 연결

- Cobblemon/RCT 관측 어댑터
- 명령 응답 어댑터
- 전투별 세션 수명주기와 정리

### 5단계: 확장 전투

- 아이템과 메가진화 등 명시적 복합 행동
- 더블 배틀 공동 행동
- 제한 시간과 탐색 예산

### 6단계: 검증

- 관장별 고정 시나리오
- 실제 로그 재생
- 이전 버전 대비 선택 변화 보고서
- 평균·최악 판단 시간과 메모리 측정
