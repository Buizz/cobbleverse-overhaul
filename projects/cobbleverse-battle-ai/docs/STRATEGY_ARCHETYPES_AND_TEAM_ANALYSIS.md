# 전략 아키타입 및 팀 분석 계획

> 상태: 설계 초안
>
> 목표: 같은 팀도 서로 다른 전투 성향을 보이게 하고, 팀 구성과 잘 맞는 전략 타입을 가상 대전으로 선별한다.

## 1. 핵심 개념

AI마다 하나의 고정된 최적 정책만 사용하지 않는다. 전투 전에 `StrategyArchetype`을 선택해 위험 허용도, 에이스 운용, 교체, 판 설치와 장기 계획의 우선순위를 바꾼다.

전략 타입은 행동을 강제하는 규칙이 아니라 **의사결정 힌트와 초기 전략 사전확률**이다.

- 불법 행동이나 정보 정책을 무시할 수 없다.
- 명백한 패배 행동을 성격 표현이라는 이유로 선택하지 않는다.
- 현재 상태 승률 `V(s)`와 행동 이후 기대 승률 `Q(s, a)`를 공통 척도로 사용한다.
- 전략 타입은 후보 생성, 안전 제약, 탐색 깊이, 위험 페널티와 비슷한 행동의 선택 확률을 조정한다.
- 전투 상황이 크게 변하면 시작 전략을 고집하지 않고 계획을 수정할 수 있다.

## 2. 초기 전략 타입

| ID | 성향 | 주요 힌트 |
|----|------|-----------|
| `BALANCED` | 균형형 | 공격·방어·자원 보존을 평균적으로 평가 |
| `OFFENSIVE_PRESSURE` | 공격형 | 유리한 대면, 직접 피해, 교체 압박과 템포 우선 |
| `DEFENSIVE_CONTROL` | 방어형 | 회복, 상태, 막이 순환과 장기 자원 우위 중시 |
| `ACE_DENIAL` | 에이스 견제형 | 상대 에이스 카운터 보존, 누적 피해와 진입 차단 우선 |
| `ACE_RUSH` | 저돌적 에이스 사용형 | 자신의 에이스 조기 투입과 돌파 기회에 높은 가치 |
| `SETUP_SWEEP` | 랭크업 전개형 | 안전한 랭크업 턴과 스위프 조건 조성 중시 |
| `HAZARD_CONTROL` | 판 장악형 | 설치물 누적 가치, 제거와 교체 강제 중시 |
| `TEMPO_PIVOT` | 템포·피벗형 | 교체 기술, 유리 대면 연결과 정보 획득 중시 |

초기에는 타입 수를 무리하게 늘리지 않는다. 실제 행동 분포가 구분되지 않는 타입은 합치고, 팀·관장 테마에 필요한 타입만 추가한다.

### 2.1 힌트가 바꾸는 값

```text
StrategyHint
  aggression
  risk_tolerance
  horizon
  switch_tendency
  recovery_priority
  hazard_priority
  ace_preservation
  enemy_ace_pressure
  setup_priority
  information_value
```

각 값은 `0.0~1.0`의 정규화된 힌트다. 실제 기술별 점수를 직접 저장하지 않고 탐색과 가치 보정이 해석하는 의미 있는 축만 제공한다.

예를 들어 `ACE_RUSH`는 에이스 보존을 완전히 끄는 타입이 아니다. 에이스가 조기에 이득을 만들 수 있는 장면의 위험 허용도를 높이되, 유일한 승리 조건을 확정적으로 잃는 행동은 여전히 금지한다.

## 3. 팀 분석

AI 멤버 후보가 만들어지면 `TeamProfileAnalyzer`가 구성의 강점, 약점과 전략 적합도를 계산한다.

```text
TeamAnalysisReport
  team_id
  feature_schema_version
  role_assignments
  team_features
  matchup_coverage
  vulnerabilities
  ace_candidates
  strategy_compatibility
  confidence
  explanations
```

### 3.1 분석 특징

- 물리·특수 공격력과 돌파력
- 속도 분포, 선공기와 속도 제어
- 타입·기술 공격 범위
- 물리·특수 내구와 반복 교체 가능 횟수
- 회복, 상태 회복과 장기전 자원
- 판 설치·제거 수단과 예상 누적 가치
- 피벗·강제 교체·도발·앙코르 등 템포 수단
- 랭크업 사용자와 랭크업을 위한 안전한 대면
- 에이스 후보와 팀의 에이스 의존도
- 상대 에이스를 막을 카운터의 수와 중복성
- 주요 타입·역할에 대한 대응 공백
- 도구·기믹·날씨·필드 의존도
- 한 포켓몬에 집중된 역할 수와 조기 손실 위험

### 3.2 점수의 의미

팀 점수 하나만으로 좋은 팀을 판단하지 않는다.

```text
TeamScoreCard
  overall_baseline
  offense
  defense
  speed_control
  role_coverage
  matchup_coverage
  resource_depth
  strategy_scores
  uncertainty
```

`overall_baseline`은 비교를 위한 요약값이고, 실제 전략 선택에는 타입별 `strategy_scores`와 가상 대전 결과를 사용한다. 같은 팀이 방어형으로는 낮고 에이스 견제형으로는 높을 수 있다.

## 4. 팀과 전략의 가상 평가

### 4.1 평가 시점

두 단계를 구분한다.

1. **팀 확정 전:** 여러 후보 팀과 전략 타입의 조합을 가상 대전해 최종 멤버 구성에 참고한다.
2. **팀 확정 후:** 확정된 팀으로 전략 타입별 승률을 다시 계산하고, 해당 전투에서 사용할 타입 후보를 선별한다.

고정 스토리 관장처럼 멤버가 콘텐츠로 확정된 경우에는 2단계만 수행한다. 랜덤 트레이너나 배틀타워 팀 생성에서는 두 단계를 모두 사용할 수 있다.

### 4.2 평가 상대군

현재 도전자의 미공개 파티를 몰래 읽어 전략이나 팀을 만들지 않는다. 기본 평가는 버전이 고정된 `OpponentBenchmarkPool`을 사용한다.

- 해당 지역에서 일반적으로 가능한 대표 플레이어 팀
- 공격·방어·판·랭크업·날씨 등 주요 전략 팀
- 타입과 속도 구간이 다양한 절차 생성 팀
- 이전 AI 버전과 고정 악용 스크립트
- 진영과 선발 위치를 바꾼 미러 조건

플레이어의 현재 공개 파티를 사용해 적응하는 콘텐츠가 필요하면 UI와 규칙에 명시한다. 미공개 정보까지 사용한 정확한 카운터 팀 생성은 일반 관장과 `expert` 이하 난이도에서 금지한다.

### 4.3 가상 대전 절차

```text
후보 팀 생성
  → TeamProfileAnalyzer
  → 명백히 부적합한 전략 제거
  → 팀 × 전략 × 대표 상대 × 고정 시드 가상 대전
  → 승률·신뢰 구간·전략 장면·시간 초과 집계
  → 전략별 SelectionScore
  → 상위 3개 전략 후보
  → 시드 기반 가중 무작위 선택
```

단순 표본 승률만 사용하면 적은 경기에서 우연히 이긴 타입이 선택될 수 있다. 초기 선택 점수는 다음 요소를 조합한다.

```text
SelectionScore
  = 승률 신뢰구간 하한
  - 불법 행동 페널티
  - 정보 정책 위반 페널티
  - 시간 초과·폴백 페널티
  - 치명적 전략 장면 실패 페널티
  + 전략 다양성 보정
```

정확한 통계 방식과 가중치는 시뮬레이터가 완성된 뒤 확정한다.

## 5. 상위 3개 전략 선택

가상 평가 결과가 높은 전략 세 개를 후보로 유지한다. 최고 승률 하나를 항상 고르지 않고 `strategy_seed`를 사용한 가중 무작위로 하나를 선택한다.

```text
P(strategy)
  = softmax(SelectionScore / strategy_temperature)
```

- 같은 팀이라도 전투마다 성향이 조금 달라질 수 있다.
- 점수 차이가 크면 가장 적합한 전략이 자주 선택된다.
- 점수가 비슷하면 세 전략이 고르게 나타난다.
- 관장 재대결에서 이전과 다른 운영을 보여줄 수 있다.
- 리플레이에는 후보 세 개, 점수, 확률, 시드와 최종 선택을 기록한다.

`top_k`의 기본값은 3으로 두되 설정에서 변경할 수 있게 한다. 호환되는 전략이 세 개보다 적으면 억지로 낮은 전략을 채우지 않는다.

## 6. 전투 중 전략 변경

선택된 타입은 시작 힌트이며 영구 잠금이 아니다.

다음 상황에서는 `StrategicPlanner`가 계획을 재평가한다.

- 에이스 또는 유일 카운터가 쓰러짐
- 예상하지 못한 기술·특성·도구 공개
- 판·날씨·필드 상태의 큰 변화
- 랭크업으로 즉시 전멸 위험 발생
- 시작 전략의 핵심 조건 상실
- 다른 승리 조건의 확률이 크게 상승

예를 들어 `ACE_RUSH`로 시작했더라도 에이스가 상태 이상에 걸리면 `DEFENSIVE_CONTROL` 성향의 계획으로 전환할 수 있다. 이때 타입 자체를 매 턴 무작위로 다시 뽑지는 않고, 변경 이유와 적용된 보정만 기록한다.

## 7. 데이터 계약

```text
StrategyArchetype
  id
  hint_vector
  allowed_difficulties
  minimum_compatibility
  description_key

StrategyEvaluation
  team_id
  archetype_id
  benchmark_pool_version
  engine_version
  model_version
  battle_count
  wins
  losses
  confidence_interval
  selection_score
  failure_metrics

StrategySelection
  candidates
  probabilities
  selected_id
  strategy_seed
```

팀 분석 특징, 전략 힌트와 평가 결과는 각각 스키마 버전을 가진다. 엔진이나 팀 데이터가 바뀌면 오래된 결과를 자동으로 재사용하지 않는다.

## 8. 캐시와 서버 부하

모든 실제 전투 시작 시 수천 번의 가상전을 다시 실행하지 않는다.

- 콘텐츠 빌드·서버 준비 단계에서 고정 관장 팀을 미리 평가한다.
- 절차 생성 팀은 팀 해시·규칙·엔진·모델·상대군 버전별로 결과를 캐시한다.
- 캐시가 없으면 서버 측 AI 워커에서 제한된 경기만 실행한다.
- 제한 시간 안에 평가하지 못하면 `TeamProfileAnalyzer`의 호환도 기준선을 사용한다.
- 플레이어별 현재 파티를 키에 넣어 무제한 캐시가 생기지 않게 한다.
- 서버 운영 중 학습하지 않고 평가 결과와 모델 승격은 오프라인에서 관리한다.

## 9. 테스트

### 9.1 팀 분석 테스트

- 같은 팀·스키마에서 동일한 점수와 설명 생성
- 에이스·막이·판 제거 등 복수 역할 판정
- 제거 수단이 없는 판 약점과 속도 제어 공백 탐지
- 한 포켓몬에 역할이 집중된 위험 탐지
- 진영을 뒤집은 특징의 일관성

### 9.2 전략 평가 테스트

- 공격형 팀에서 공격 계열 전략이 부적합 전략보다 높은지 검증
- 방어형 팀에서 회복·막이 자원 가치가 반영되는지 검증
- 상대 에이스가 강한 평가군에서 `ACE_DENIAL`이 카운터를 보존하는지 검증
- `ACE_RUSH`가 유리한 돌파 기회와 무모한 확정 희생을 구분하는지 검증
- 같은 시드에서 상위 3개와 최종 선택이 재현되는지 검증
- 여러 시드에서 설정된 확률에 가까운 선택 분포가 나오는지 검증
- 현재 플레이어의 미공개 정보가 평가 입력에 들어오지 않는지 검증

### 9.3 장기 지표

- 전략 타입별 승률과 95% 신뢰 구간
- 팀 특징 구간별 전략 선택률
- 선택된 전략과 실제 가장 높은 성과 전략의 차이
- 시작 전략 유지·전환 비율과 전환 이유
- 전략 타입 사이 행동 분포의 구분도
- 같은 상대가 AI 패턴을 반복 유도한 성공률

## 10. 구현 순서

1. `TeamAnalysisReport`와 타입이 있는 팀 특징 계약
2. 역할·대응 공백·에이스 의존도를 계산하는 `TeamProfileAnalyzer`
3. 데이터 기반 `StrategyArchetype`과 힌트 벡터
4. 힌트를 전략 계획과 승률 탐색에 적용
5. 고정 장면으로 타입별 행동 차이 검증
6. 대표 상대군과 배치 가상 대전 실행기
7. 상위 3개 가중 선택과 리플레이 기록
8. 팀·엔진·모델 버전별 평가 캐시
9. 팀 생성기와 전략 공동 평가

## 11. 완료 기준

- 생성되거나 고정된 팀의 역할·강점·약점·에이스 의존도를 분석할 수 있다.
- 같은 팀에 여러 전략 타입을 적용했을 때 행동 분포가 실제로 구분된다.
- 대표 상대군 가상 대전으로 전략별 승률과 신뢰 구간을 계산한다.
- 상위 전략 세 개에서 재현 가능한 가중 무작위 선택을 한다.
- 일반 AI가 현재 플레이어의 미공개 팀 정보를 이용해 카운터 팀을 만들지 않는다.
- 실제 전투 시작 시 과도한 동기 가상 대전으로 서버 틱을 막지 않는다.

## 12. 미결정 사항

- 첫 버전에서 활성화할 전략 타입은 몇 개인가?
- 후보 팀은 규칙 기반 생성, 사전 제작 목록과 최적화 생성 중 무엇을 사용하는가?
- 대표 상대군을 지역별·난이도별로 얼마나 나눌 것인가?
- 전략별 최소 가상 대전 수와 신뢰 구간 기준은 얼마인가?
- 상위 3개 선택 온도와 관장별 고정·랜덤 허용 범위는 얼마인가?
- 전투 중 시작 전략에서 벗어날 수 있는 최대 보정 범위는 얼마인가?
