# Cobbleverse Battle AI 개선 계획

> 기준일: 2026-07-24
>
> 참고 구현: Cobblemon 1.7 계열의 `Buizz/Cobblemon-RunAndBunAI`
>
> 실제 연동 목표: Cobblemon 1.8 계열. 정확한 1.8.x 버전과 RCT API는 개발 착수 시 고정.
>
> 문서 상태: 아키텍처 방향 확정 / 전투 규칙 범위·웹 UI 프레임워크·1.8 API 미정

## 1 목표

현재 Java 골격과 참고 AI를 그대로 확장하지 않는다. 다음 세 결과물을 하나의 공통 규칙 엔진 위에 만든다.

1. Minecraft 서버에서 트레이너가 사용하는 전투 AI
2. 브라우저에서 직접 가상 배틀과 AI 대전을 실행하는 웹 실험실
3. 대량 시뮬레이션으로 AI 수준과 변경 영향을 측정하는 테스트 도구

```text
공통 포켓몬 전투 규칙·시뮬레이션 엔진
  ├─ AI 의사결정과 탐색
  ├─ Minecraft/Cobblemon 1.8 어댑터
  ├─ 브라우저 전투 실험실
  └─ CLI·CI 대량 평가기
```

Minecraft와 웹이 서로 다른 피해 계산기나 전투 규칙을 구현하지 않는 것이 핵심이다.

## 2 현재 참고 엔진의 문제

### 2.1 `PokeMathMax` 결합

참고 AI의 `PokeMathMax`는 단순 피해 공식만 제공하지 않는다. Cobblemon의 `BattlePokemon`, RCT의 `BattleEffects`와 `BattleStates`, 특성 억제, 타입, 도구, 날씨, 필드, 속도, 다중 타격과 전투 기록을 한 클래스에서 직접 조회한다.

그 결과 다음 문제가 생긴다.

- AI 판단을 Minecraft 없이 독립 실행하기 어렵다.
- Cobblemon 내부 상태가 계산 입력에서 누락되거나 잘못 해석되면 예측 피해와 실제 피해가 달라진다.
- 웹과 JVM에서 같은 계산 코드를 사용할 수 없다.
- 기술·특성·도구 예외가 한 유틸리티에 계속 누적된다.
- 한 턴의 피해량은 계산해도 전후 상태 변화와 턴 종료 효과를 정확히 재현하기 어렵다.
- Cobblemon 업데이트가 계산 코드 전반에 직접 영향을 준다.

따라서 `PokeMathMax`를 보수하는 것이 아니라 Cobblemon 객체에 의존하지 않는 별도 전투 엔진으로 대체한다.

### 2.2 현재 추가한 엔진 골격의 한계

현재 `ai-api`와 `ai-engine`은 책임 분리와 테스트 환경을 확인하는 초기 골격이다.

- 문자열 기반 `features`는 정식 전투 상태 모델이 아니다.
- `WeightedFeatureRule`은 확장 지점 확인용이며 AI 전술을 확정하지 않는다.
- 피해, 명중, 우선도, 상태이상과 턴 진행을 계산하지 않는다.
- 상대 행동 예측과 다중 턴 탐색이 없다.
- Java 전용 프로젝트이므로 아직 브라우저에서 실행할 수 없다.

이 골격은 폐기 대상이라기보다 새 공통 계약으로 옮길 프로토타입이다.

## 3 확정 아키텍처 방향

### 3.1 Kotlin Multiplatform

공통 엔진은 Kotlin Multiplatform으로 전환한다.

| 대상 | 출력 | 용도 |
|------|------|------|
| `jvm` | JVM 라이브러리 | Minecraft 서버, Cobblemon 어댑터, JVM 테스트 |
| `js(IR)` | JavaScript 모듈 | 브라우저 UI, Node.js 대량 테스트 |
| `wasmJs` | WebAssembly | 성능 검증 후 선택적으로 추가 |

1차 웹 타깃은 안정 상태인 Kotlin/JS로 한다. Kotlin/Wasm은 현재 베타이며 최신 브라우저 기능 요구사항도 있으므로 필수 기반으로 삼지 않는다. 실제 대량 시뮬레이션에서 JavaScript 성능이 부족하다는 측정 결과가 있을 때만 추가한다.

웹 UI는 생성된 JavaScript 엔진 패키지를 호출하는 얇은 셸로 만든다. UI 프레임워크를 바꿔도 전투 규칙과 AI 코어에는 영향이 없어야 한다.

### 3.2 계층

```text
battle-data
  → 종족·기술·특성·도구·타입·규칙 프로필

battle-engine
  → 합법 행동, 턴 순서, 피해, 효과, 턴 종료와 승패

ai-core
  → 관측 정보, 상대 행동 분포, 후보 탐색과 효용 평가

platform adapters
  ├─ cobblemon-1.8-adapter
  ├─ web-api
  └─ simulation-cli

applications
  ├─ Minecraft 서버 모드
  └─ 브라우저 AI 실험실
```

### 3.3 Minecraft 실행 배치

AI 판단은 Minecraft 메인 틱 스레드에서 직접 탐색하지 않는다. 서버는 불변 전투 관측을 만들고 서버 측 Worker Pool 또는 별도 신뢰 AI 프로세스에 전달한 뒤, 반환된 행동의 상태 버전·합법성·정보 정책을 검증해 최종 제출한다.

플레이어 클라이언트 위임은 싱글플레이, 웹 실험실과 공개 정보 기반 보조 표시에만 우선 허용한다. 공개 멀티플레이의 NPC 최종 행동을 클라이언트가 확정하게 하거나 미공개 팀 정보·잠긴 상대 명령을 전송하지 않는다. 자세한 배치안과 폴백은 [승률 모델 계획](WIN_PROBABILITY_MODEL.md)의 계산 실행 위치 절을 따른다.

### 3.4 예정 모듈

| 모듈 | 책임 | 플랫폼 의존 |
|------|------|-------------|
| `shared-model` | ID, 전투 상태, 명령, 이벤트와 직렬화 형식 | 없음 |
| `battle-data` | 버전이 있는 기술·특성·도구·종족 데이터 | 없음 |
| `battle-engine` | 결정론적 턴 상태기계와 규칙 처리 | 없음 |
| `ai-api` | 관측, 후보와 결정 계약 | 없음 |
| `ai-engine` | 상대 예측, 탐색, 평가와 설명 추적 | 없음 |
| `simulation-runner` | AI 대 AI, 리플레이와 배치 시뮬레이션 | 없음 |
| `mechanics-conformance` | 기술·특성·도구 적합성 목록과 차등 테스트 | JVM·JS·Cobblemon 하네스 |
| `cobblemon-1.8-adapter` | Cobblemon 상태·행동 변환과 차이 계측 | JVM/Cobblemon |
| `ai-worker` | 비동기 판단 큐, 동시 실행 제한, 시간 초과와 안전 폴백 | JVM 또는 신뢰 서비스 |
| `web-lab` | 팀 구성, 가상전, 로그·판단 시각화 | 브라우저 |

## 4 내장 포켓몬 전투 엔진

### 4.1 엔진의 역할

내장 엔진은 피해 계산기보다 넓은 범위를 담당한다.

- 현재 상태에서 가능한 행동 목록 생성
- 기술·교체·아이템·기믹 명령 검증
- 우선도, 속도, 트릭룸과 동점 순서 결정
- 명중, 급소, 피해 범위와 다중 타격 계산
- 타입, 자속, 특성, 도구, 날씨, 필드와 상태 반영
- 기술 전후 효과와 교체 진입 효과
- 턴 종료 피해·회복·지속 시간 처리
- 기절, 강제 교체, 승패와 종료 처리
- 모든 난수 소비와 상태 변경을 이벤트 로그로 기록

Minecraft 안에서는 Cobblemon이 실제 전투의 최종 권위를 유지한다. 내장 엔진은 AI 예측과 탐색에 사용하고, 실제 결과와 계속 비교한다. 웹 가상전과 테스트에서는 내장 엔진이 전투의 권위가 된다.

### 4.2 결정론

```text
BattleState + 양측 명령 + ruleset_id + RNG seed
  → BattleEvent 목록
  → 다음 BattleState
```

같은 입력은 JVM, JavaScript와 CI에서 같은 사건 순서와 결과를 만들어야 한다.

- 난수 생성 알고리즘과 시드를 직접 관리한다.
- 명중·급소·피해 난수·다중 타격마다 RNG 소비 이유를 기록한다.
- 맵과 집합의 순회 순서에 결과가 의존하지 않게 한다.
- 리플레이에는 엔진 버전, 데이터 버전, 규칙 프로필과 시드를 저장한다.
- JVM/JS 교차 골든 테스트로 직렬화된 이벤트 로그가 같은지 비교한다.

### 4.3 피해 계산 파이프라인

```text
기술과 대상 검증
  → 공격·방어 능력치와 랭크 계산
  → 기술 위력과 동적 위력 계산
  → 기본 피해
  → 복수 대상·날씨·급소·난수·자속·타입
  → 화상·특성·도구·기타 최종 보정
  → 타격별 피해와 부가 효과
  → 반동·흡수·기절·후속 사건
```

각 보정은 이름이 있는 독립 단계와 이벤트를 가져야 한다. 최종 숫자만 반환하지 않고 어떤 규칙이 얼마를 바꿨는지 추적할 수 있어야 한다.

### 4.4 규칙과 데이터 버전

```text
ruleset_id: cobbleverse:cobblemon_1_8
data_version: generation-data-YYYY.MM.DD
engine_version: semantic version
```

- Cobblemon 1.8의 실제 동작을 기준 프로필로 만든다.
- 본가·Pokémon Showdown과 다른 Cobblemon 동작은 명시적인 호환성 규칙으로 둔다.
- 프로젝트 전용 기술·특성·기믹은 별도 네임스페이스로 추가한다.
- 코드에 기술 이름을 나열하기보다 데이터와 효과 핸들러를 조합한다.
- 데이터 출처, 생성 절차와 라이선스를 기록한다.

### 4.5 구현 순서

1. 타입, 능력치, 랭크, 명중과 기본 피해
2. 단일 배틀의 기술 사용·기절·교체·턴 종료
3. 핵심 상태이상, 날씨, 필드와 진입 효과
4. 우선 사용 빈도가 높은 특성·도구·기술
5. 전체 Cobbleverse 관장 팀이 사용하는 규칙
6. 아이템과 메가진화 등 프로젝트 채택 기믹
7. 더블 배틀과 복수 대상 규칙

처음부터 모든 포켓몬 기술을 완성하려고 하지 않는다. 실제 관장 팀과 회귀 시나리오에 필요한 규칙부터 수직으로 닫는다.

다만 최종 지원 목표는 일부 기술의 근사가 아니다. Cobbleverse에서 사용 가능한 기술·특성·도구 전체가 구현·상호작용·차등·JVM/JS 테스트를 통과해야 한다. 소금절이 같은 특수 효과의 누락을 자동 검출하는 기준은 [전투 규칙 완전성 계획](MECHANICS_COVERAGE_PLAN.md)을 따른다.

## 5 Cobblemon 1.8 연동

참고 저장소의 1.7 의존 버전은 조사 기준일 뿐 새 프로젝트의 런타임 기준이 아니다.

### 5.1 어댑터 원칙

```text
Cobblemon 1.8 전투 상태
  → CobblemonObservationAdapter
  → 공통 BattleState/BattleObservation
  → 내장 엔진 예측과 AI 결정
  → CobblemonCommandAdapter
  → Cobblemon 합법 행동 응답
```

- Cobblemon 클래스는 `cobblemon-1.8-adapter` 밖으로 나오지 않는다.
- 정확한 1.8.x와 RCT API 버전은 개발 시작 시 고정한다.
- 1.7 호환 계층은 만들지 않는다.
- 서버에서만 AI를 실행하고 클라이언트 모드는 UI가 필요할 때만 추가한다.
- 엔진 오류나 제한 시간 초과 시 사용할 안전한 기본 AI를 둔다.

### 5.2 실제 결과 차이 계측

AI가 예상한 결과와 Cobblemon이 실행한 결과를 같은 형식으로 남긴다.

| 비교 항목 | 예시 |
|-----------|------|
| 합법 행동 | 엔진에는 가능하지만 Cobblemon이 거부한 행동 |
| 턴 순서 | 예상 선공과 실제 선공 |
| 피해 | 최소·최대·기대 피해와 실제 피해 |
| 효과 | 예상 상태·랭크 변화와 실제 변화 |
| 종료 상태 | 기절, 강제 교체와 승패 |

차이는 `mechanics_diff` 로그와 회귀 케이스로 자동 변환한다. 차이를 임의 점수 보정으로 숨기지 않고 전투 규칙 또는 어댑터 결함으로 수정한다.

## 6 웹 전투 실험실

### 6.1 목표 기능

- 포켓몬, 기술, 특성, 도구와 능력치로 팀 구성
- AI 대 AI, 사람 대 AI와 사람 대 사람 로컬 가상전
- 한 턴 실행, 자동 진행, 일시 정지와 지정 턴 되감기
- 현재 필드·파티·공개 정보 표시
- 피해 범위와 적용된 계산 단계 표시
- AI 후보 순위, 효용, 판단 근거와 예상 상대 행동 표시
- 동일 장면에서 AI 프로필 두 개 비교
- 시드 고정·변경과 리플레이 JSON 가져오기·내보내기
- 수백·수천 경기 배치 실행과 통계 표시

### 6.2 실행 구조

```text
브라우저 UI
  → Web Worker
  → Kotlin/JS battle-engine + ai-engine
  → 전투 이벤트·AI 추적·집계 결과
```

대량 시뮬레이션은 UI 스레드를 막지 않도록 Web Worker에서 실행한다. 정적 사이트로 빌드해 별도 서버 없이 열거나 정적 호스팅에 배포할 수 있게 한다.

### 6.3 웹과 Minecraft의 동일성

- 같은 팀·규칙·시드 JSON 스키마를 사용한다.
- 브라우저에서 만든 회귀 케이스를 JVM 테스트가 그대로 읽는다.
- Minecraft에서 기록한 전투 관측을 웹에서 재생할 수 있게 한다.
- 웹 전용 간이 피해 공식이나 별도 AI 규칙을 만들지 않는다.

## 7 AI 난이도와 정보 정책

난이도는 같은 AI에 단순 점수 배율만 적용하지 않는다. 행동 습관, 허용 기능, 탐색 비용, 실수 정책과 정보 접근 범위를 하나의 `DifficultyProfile`로 정의한다.

```text
DifficultyProfile
  profile_id
  information_policy
  search_depth
  node_budget
  time_budget
  enabled_action_types
  behavior_weights
  mistake_policy
  risk_policy
  fallback_profile
```

### 7.1 기준 난이도

| 프로필 | 행동 패턴 | 탐색·예측 | 정보 정책 |
|--------|-----------|-----------|-----------|
| `novice` | 공격 기술 위주, 교체·상태기·아이템 사용 제한, 의도적인 비최적 선택 허용 | 현재 턴의 단순 효용 | 공개 정보만 |
| `standard` | 타입 상성, 마무리, 기본 교체와 회복 사용 | 1턴 평가, 단순 상대 행동 분포 | 공개 정보만 |
| `advanced` | 랭크업, 상태, 교체 압박과 자원 보존 활용 | 제한된 다중 턴 탐색 | 공개 정보 기반 예측 |
| `expert` | 전체 행동을 일관된 효용으로 비교하고 반복 패턴에 적응 | 더 큰 탐색 예산과 상대 모델 | 공개 정보 기반 예측 |
| `cheater` | 상대가 확정한 행동에 가장 유리한 카운터 선택 | 정확한 상대 행동을 조건으로 탐색 | 잠긴 상대 행동 열람 |

실제 표시 이름과 트레이너 배치는 콘텐츠 데이터에서 바꿀 수 있다. 일반 트레이너, 체육관 트레이너, 관장과 리그를 반드시 위 순서에 일대일 대응시키지는 않는다.

### 7.2 행동 패턴 차이

난이도별 차이는 다음 축을 조합한다.

- 공격, 교체, 상태기, 랭크업, 아이템과 기믹의 허용 여부
- 확정 KO, 생존, 장기 이득과 자원 보존의 가중치
- 위험한 고보상 기술을 선택하는 성향
- 불리한 대면을 버티거나 교체하는 임계값
- 같은 기술과 교체를 반복하는 것에 대한 페널티
- 상대의 반복 행동을 학습하는 기억 길이
- 상대 행동 후보를 몇 개까지 탐색하는지
- 탐색 깊이, 노드 수와 턴당 시간 예산
- 상위 후보 중 비최적 행동을 선택하는 실수율

낮은 난이도는 거짓 피해 계산이나 불법 행동을 사용하지 않는다. 정확한 전투 엔진 위에서 제한된 판단과 의도적인 실수 정책으로 약해진다.

### 7.3 정보 정책

```text
InformationPolicy
  PUBLIC_ONLY
  PREDICT_FROM_PUBLIC
  PEEK_LOCKED_ACTION
```

| 정책 | 접근 가능한 정보 |
|------|------------------|
| `PUBLIC_ONLY` | 현재 필드, 공개된 포켓몬·기술·특성·도구와 관측 기록 |
| `PREDICT_FROM_PUBLIC` | 공개 정보와 관측 기록으로 계산한 상대 행동 확률 |
| `PEEK_LOCKED_ACTION` | 위 정보와 플레이어가 이번 턴에 확정한 정확한 명령 |

`PEEK_LOCKED_ACTION`은 최고 난이도만 사용한다. 일반 `BattleObservation`에 몰래 필드를 추가하지 않고 별도의 권한 있는 `OpponentKnowledge` 객체로 전달해 다른 프로필의 정보 누출을 막는다.

### 7.4 최고 난이도 치터 동작

```text
플레이어가 기술·교체·아이템 명령 제출
  → 서버가 명령을 변경 불가능한 상태로 잠금
  → 최고 난이도 AI에 잠긴 명령 전달
  → AI가 정확한 행동을 조건으로 카운터 계산
  → AI 명령 잠금
  → 양측 행동을 전투 엔진 또는 Cobblemon에 제출
```

- AI가 상대 행동을 읽은 뒤 플레이어가 명령을 바꿀 수 없다.
- 제한 시간 종료로 자동 선택된 행동도 먼저 잠근 뒤 AI에 전달한다.
- 더블 배틀에서는 대상과 기믹을 포함한 공동 명령 전체를 전달한다.
- 치터 AI는 미래 명중·급소·피해 난수 결과를 알지 못한다.
- 이번 턴 행동에 포함되지 않은 미공개 기술·도구·후열 파티 정보는 자동으로 알지 못한다.
- RNG 열람이나 전체 팀 열람이 필요하면 별도의 치트 권한으로 추가하며 기본 최고 난이도에는 포함하지 않는다.
- 플레이어 대 플레이어 전투와 일반 관장 프로필에는 이 정책을 적용하지 않는다.

서버와 웹 UI에는 최고 난이도가 행동 열람형 치트를 사용한다는 사실을 명확히 표시한다. 공정한 고난도 AI인 `expert`와 치터 난이도를 같은 이름으로 숨기지 않는다.

### 7.5 Minecraft 통합 조건

Cobblemon의 기본 명령 수집 순서가 상대 행동을 잠근 뒤 AI를 호출할 수 있는지 확인해야 한다. 불가능하면 RCT/Cobblemon 전투 요청 계층에 다음 두 단계 프로토콜이 필요하다.

1. 인간 참가자의 명령 수집과 잠금
2. 잠긴 명령을 포함한 AI 결정 요청

치터 기능은 서버 권위로만 실행한다. 클라이언트가 상대 명령을 받거나 난이도 플래그를 조작할 수 없어야 한다. 전투 로그에는 사용한 `difficulty_profile`, `information_policy`와 AI가 열람한 명령의 해시를 기록한다.

### 7.6 난이도 테스트

- 같은 상태에서 난이도별 허용 행동과 선택 경향이 달라지는지 검증
- `novice`의 실수가 불법 행동이나 전투 엔진 오류를 만들지 않는지 검증
- `expert`가 미공개 정보와 잠긴 행동에 접근하지 못하는지 검증
- `cheater`가 정확히 잠긴 행동만 읽고 유효한 카운터를 고르는지 검증
- AI 열람 후 플레이어 명령 변경이 거부되는지 검증
- 재접속·시간 초과·더블 배틀에서도 명령 잠금 순서가 유지되는지 검증
- 리플레이가 같은 난이도·정보 정책과 선택을 재현하는지 검증
- 난이도별 승률, 선택 분포와 판단 시간을 별도로 집계

치터 AI의 승률은 공정한 AI 성능 지표와 분리한다. `expert`는 순수 AI 품질 비교용이고 `cheater`는 특수 보스 경험과 카운터 퍼즐용이다.

## 8 역할·승리 조건 기반 전략

AI는 단일 행동의 점수만 합산하지 않는다. 팀 역할과 승리 조건을 먼저 분석하고, 그 전략 안에서 전술 행동을 선택한다.

```text
TeamRoleAnalyzer
  → 에이스·판깔이·막이·피벗·돌파·복수 역할
  → 자신의 승리 조건과 보호 자원
  → 상대 에이스 후보와 대응 자원
  → 랭크업·판·교체 위협
  → StrategicPlan
  → 전술 탐색과 제한적 확률 선택
```

핵심 요구사항은 다음과 같다.

- 자신의 에이스를 불필요한 피해·상태·희생으로 잃지 않는다.
- 상대 에이스를 막는 유일한 대응 포켓몬을 보존한다.
- 상대 에이스에게 설치물·상태·견제 피해를 누적해 마무리 범위로 만든다.
- 판깔이·막이·피벗의 역할 완료 여부와 남은 가치를 추적한다.
- 상대가 랭크업으로 팀을 무너뜨릴 수 있는 무료 턴을 강하게 억제한다.
- 양쪽 멤버와 공개된 구성만으로 전투 시작 전 상성 승률을 추정한다.
- 전투 중에는 현재 승률 `V(s)`와 행동 이후 기대 승률 `Q(s, a)`의 차이로 후보를 비교한다.
- 공격형·방어형·에이스 견제형·저돌적 에이스형 등 전략 힌트를 팀별로 평가한다.
- 후보 팀을 대표 상대군과 가상 대전하고, 확정 팀에서는 적합도가 높은 전략 세 개를 시드 기반으로 선택한다.
- 비슷하게 좋은 전략 행동은 시드가 있는 확률 정책으로 혼합해 고정 패턴 악용을 막는다.
- 확정 KO와 유일 생존 수단처럼 명백한 행동은 불필요하게 무작위화하지 않는다.

점수제는 제거하지 않고 전략 계획이 허용한 후보를 비교하는 하위 전술 계층으로 내린다. 상세 역할, 계획, 난수와 테스트는 [전략 AI 계획](STRATEGIC_AI_PLAN.md), 팀 분석과 성향 선택은 [전략 아키타입 계획](STRATEGY_ARCHETYPES_AND_TEAM_ANALYSIS.md), 승률 평가·자기대전 학습·보정은 [승률 모델 계획](WIN_PROBABILITY_MODEL.md)을 따른다.

## 9 AI 수준 평가

### 9.1 가상 배틀 모드

| 모드 | 목적 |
|------|------|
| 단일 장면 | 특정 턴에서 올바른 기술·교체를 고르는지 확인 |
| 고정 대전 | 동일 팀·시드로 변경 전후 선택 비교 |
| 랜덤 시드 반복 | 명중·급소·피해 난수에 대한 평균 성능 확인 |
| AI 대 기준 AI | 랜덤, 최고 피해, 교체하지 않는 AI 대비 성능 |
| AI 미러전 | 선후공·팀 위치 편향과 비결정성 확인 |
| 리그전 | 여러 팀·AI 프로필의 라운드 로빈 |
| 실제 로그 재생 | Minecraft에서 발생한 판단과 결과 재현 |

### 9.2 지표

- 승률과 95% 신뢰 구간
- 상대·팀·선발 위치별 승률
- 평균 턴 수와 남은 포켓몬·HP
- 불법 행동과 안전 기본 AI 전환 횟수
- 확정 KO 누락, 무의미한 교체와 반복 교체 횟수
- 상태기·아이템·기믹 사용 효율
- 예상 피해와 실제 피해 오차
- 판단 시간의 평균, p95, p99와 최악값
- 탐색 노드 수와 메모리 사용량
- 동시 전투별 작업 큐 대기, 시간 초과와 안전 AI 전환 횟수
- 이전 엔진 버전 대비 선택 변경률
- 자신의 에이스 생존율과 상대 에이스 제거율
- 유일 카운터 조기 손실과 무상 랭크업 허용 횟수
- 동일 장면의 행동 엔트로피와 고정 패턴 유도 성공률
- 팀 프리뷰·현재 상태 승률의 Brier score, log loss와 보정 오차
- 선택 행동의 평균 기대 승률 변화 `Q(s, a) - V(s)`

단순 전체 승률 하나로 AI 수준을 판단하지 않는다. 팀 상성, 선발 위치와 난수 시드를 맞춘 쌍대 비교를 기본으로 한다.

### 9.3 테스트 계층

1. **규칙 단위 테스트:** 피해 보정, 우선도, 상태와 턴 종료
2. **골든 테스트:** 입력 상태·명령·시드에 대한 사건 로그
3. **교차 플랫폼 테스트:** JVM과 JS 결과 일치
4. **차등 테스트:** Cobblemon 1.8 실제 결과와 엔진 결과 비교
5. **속성 테스트:** HP 범위, 불법 상태, 사건 순서 등 불변 조건
6. **AI 장면 테스트:** 기대 행동군과 금지 행동 검증
7. **대량 리그 테스트:** 통계적 수준과 성능 회귀 검증
8. **브라우저 E2E:** 팀 입력, 전투 실행, 리플레이 내보내기

AI 장면 테스트는 하나의 행동만 정답으로 강제하지 않는다. 전술적으로 허용되는 행동 집합, 명백히 나쁜 행동 집합과 최소 효용 차이를 함께 정의한다.

완료 기준: 엔진 변경 PR마다 에이스 보존·견제, 랭크업 억제, 난이도별 승률, 승률 모델 보정과 판단 시간 회귀를 확인할 수 있다.

### P5 Cobblemon 1.8 연결

- 관측·명령 어댑터와 전투 세션
- 메인 틱 스레드 밖 AI Worker Pool, 제한 시간과 결정론적 안전 폴백
- 인간 명령 잠금과 최고 난이도 행동 열람 프로토콜
- 실제 결과 차이 계측과 안전 기본 AI

완료 기준: 실제 Minecraft 관장전이 끝까지 진행되고, 동시 전투 부하에서도 메인 틱을 막지 않으며 주요 계산 차이가 허용 범위 안이다.

### P6 확장

- 아이템·기믹과 더블 배틀
- 탐색 최적화와 선택적 Kotlin/Wasm 성능 실험

완료 기준: 채택 콘텐츠의 규칙·성능·회귀 게이트를 모두 통과한다.

## 12 외부 엔진과 자료의 역할

### Pokémon Showdown

현대 세대 규칙과 다양한 전투 형식을 지원하므로 표준 규칙의 비교 오라클과 테스트 벡터 참고 자료로 사용한다. Cobblemon의 실제 동작과 프로젝트 커스텀 규칙을 그대로 대체하는 런타임 엔진으로 고정하지 않는다.

### `pkmn/engine`

AI와 도구를 위한 고성능 전투 엔진 및 WebAssembly 구조를 참고할 가치가 있다. 그러나 공식 저장소가 아직 초기 릴리스 전의 큰 변경과 현대 세대 지원 범위를 경고하고 있으므로 현재 프로젝트의 필수 의존성으로 사용하지 않는다.

### 기존 RunAndBunAI

AI 행동 후보, 판단 근거, 가상전과 회귀 시나리오에서 유용한 아이디어를 참고한다. `PokeMathMax`, Cobblemon 1.7 결합 코드와 기존 점수 상수는 이식하지 않는다.
