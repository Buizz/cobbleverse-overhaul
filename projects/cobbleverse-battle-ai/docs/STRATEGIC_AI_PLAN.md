# 팀 역할·승리 조건 기반 전략 AI 계획

> 목표: 단일 행동 점수 합산을 넘어 팀 전체의 승리 조건을 보존하고 상대 계획을 방해하는 AI
>
> 상태: 전략 계층 설계 / 역할 판정·탐색 알고리즘 미구현

## 1 문제

현재 점수 규칙은 눈앞의 피해, KO, 교체와 상태기 가치를 행동별로 더한다. 이 방식만으로는 다음 판단이 약하다.

- 자신의 에이스를 불필요한 피해나 상태이상에 노출
- 상대 에이스를 막을 유일한 포켓몬을 조기에 희생
- 판깔이 포켓몬의 임무가 끝났는지 판단하지 못함
- 막이와 피벗을 단순 저피해 포켓몬으로만 평가
- 상대가 자유롭게 랭크업할 수 있는 수동적 행동 반복
- 몇 턴 뒤의 승리 조건보다 현재 턴 점수를 우선
- 같은 장면에서 항상 같은 행동을 골라 플레이어가 쉽게 유도

점수 규칙은 필요하지만 전략을 대신할 수 없다.

## 2 계층형 의사결정

```text
팀 구성과 현재 전투 상태
  → TeamRoleAnalyzer
  → WinConditionAnalyzer
  → ThreatAndCounterMap
  → StrategicPlanner
  → TacticalSearch
  → 제한된 확률 정책
  → 최종 행동
```

| 계층 | 책임 |
|------|------|
| 역할 분석 | 포켓몬과 기술 구성이 팀에서 맡는 기능 판정 |
| 승리 조건 | 이번 대전에서 보존·제거해야 할 핵심 자원 판정 |
| 위협 맵 | 상대마다 아군의 대응 수단과 교환 비용 계산 |
| 전략 계획 | 에이스 보존, 상대 에이스 견제, 판 설치·제거 등 목표 선택 |
| 전술 탐색 | 전략을 만족하는 기술·교체·아이템 행동 비교 |
| 확률 정책 | 비슷하게 좋은 행동을 재현 가능한 확률로 혼합 |

모든 계층이 사용하는 공통 척도는 [팀 프리뷰 및 전투 상태 승률 모델](WIN_PROBABILITY_MODEL.md)의 승률 가치다.
AI별 공격성·방어성·에이스 운용 성향과 팀 적합도 평가는 [전략 아키타입 및 팀 분석 계획](STRATEGY_ARCHETYPES_AND_TEAM_ANALYSIS.md)을 따른다.

## 3 팀 역할 모델

역할은 종족에 고정하지 않고 실제 기술, 특성, 도구, 능력치, 팀 조합과 현재 상태를 보고 복수로 판정한다.

```text
TeamRoleProfile
  pokemon_id
  roles
  role_confidence
  required_resources
  key_matchups
  expendability
  current_role_state
```

| 역할 | 의미 |
|------|------|
| `ACE` | 최종 승리 또는 핵심 돌파를 담당하는 에이스 |
| `LEAD` | 초반 대면·정보 수집·판 설치에 유리한 선봉 |
| `HAZARD_SETTER` | 스텔스록·압정 등 판을 설치 |
| `HAZARD_REMOVER` | 고속스핀·안개제거 등 판 제거 |
| `WALL` | 특정 공격 축을 반복해서 받아내는 막이 |
| `PIVOT` | 교체 기술과 내구로 유리한 대면을 연결 |
| `BREAKER` | 상대 막이 구조를 무너뜨리는 돌파 역할 |
| `SETUP_SWEEPER` | 랭크업 뒤 마무리를 노리는 스위퍼 |
| `REVENGE_KILLER` | 속도·우선도·스카프로 위협을 마무리 |
| `CLERIC` | 상태 회복·소생·지원 담당 |
| `DISRUPTOR` | 도발·앙코르·트릭·강제 교체로 계획 방해 |
| `SACRIFICE_CANDIDATE` | 현재 승리 조건에서 교환 가능한 자원 |

포켓몬 한 마리가 `ACE + SETUP_SWEEPER`, `WALL + PIVOT`처럼 여러 역할을 가질 수 있다. 역할과 희생 가능성은 전투 중 다시 계산한다.

팀 전체 분석은 단일 종합 점수에 머물지 않는다. 공격·방어·속도 제어·역할 범위·에이스 의존도와 전략별 적합도를 분리하고, 후보 팀과 전략 타입 조합을 대표 상대군과 가상 평가한다.

## 4 승률 가치 함수

전투 시작 전에는 `TeamPreviewValue`가 양쪽 멤버와 공개된 구성만 보고 초기 상성 승률과 신뢰도를 추정한다. 전투 중에는 `BattleStateValue`가 HP, 상태, 판, 랭크와 남은 자원을 반영해 현재 승률 `V(s)`를 갱신한다.

각 행동은 고정 보너스의 합이 아니라 가능한 다음 상태의 기대 승률 `Q(s, a)`로 비교한다. 전략 계층은 에이스 보존과 랭크업 방지 같은 안전 제약을 만들고, 전술 계층은 그 제약 안에서 `Q(s, a) - V(s)`를 높이는 행동을 찾는다. 학습·보정·웹 표시와 자기대전 순환은 [승률 모델 계획](WIN_PROBABILITY_MODEL.md)을 따른다.

## 5 승리 조건 분석

### 5.1 자신의 에이스 보존

AI는 에이스의 현재 HP만 보지 않고 승리에 필요한 조건을 추적한다.

- 상대 팀에서 에이스를 막는 포켓몬과 남은 대응 수단
- 진입 시 받는 설치물 피해와 필요한 최소 HP
- 상태이상, 도구 소비와 기믹 사용 여부
- 에이스를 안전하게 투입할 피벗 또는 기절 후 진입 경로
- 에이스 대신 현재 위협을 받을 수 있는 포켓몬
- 에이스가 공격을 시작하기 전 필요한 판 설치·제거

에이스를 살리기 위한 교체가 단기 피해 점수에서 손해더라도 장기 승리 확률이 높으면 선택한다. 반대로 에이스의 역할이 사라졌거나 다른 승리 조건이 더 강하면 과도하게 보존하지 않는다.

### 5.2 상대 에이스 견제

```text
상대 에이스 후보
  → 완전 저지·임시 저지·마무리 가능한 아군 식별
  → 해당 대응 자원의 HP·상태·도구 보존
  → 설치물·상태·견제 피해 누적
  → 안전한 랭크업·진입 기회 차단
  → 마무리 범위에 들어오면 제거
```

- 상대 에이스를 막는 유일한 포켓몬을 다른 용도로 희생하지 않는다.
- 완전한 카운터가 없으면 여러 포켓몬의 연속 견제로 제거 계획을 만든다.
- 스텔스록·독·소금절이 같은 누적 피해가 실제 교체 압박에 주는 가치를 계산한다.
- 상대 에이스가 아직 공개되지 않았어도 팀 구성과 공개 정보로 후보 분포를 유지한다.
- 치터 난이도 외에는 미공개 정보를 확정 사실로 사용하지 않는다.

### 5.3 판깔이와 판 제거

판 설치 여부는 기술 자체의 고정 점수가 아니라 예상 교체 횟수와 상대 구성으로 판단한다.

- 상대 팀의 설치물 약점과 제거 수단
- 설치 후 예상되는 유효 피해
- 설치하는 턴에 상대가 얻는 랭크업 기회
- 아군 에이스가 받는 설치물 피해와 제거 필요성
- 판깔이 포켓몬이 임무 후 피벗·희생 자원으로 바뀌는 시점

같은 설치물을 의미 없이 반복하거나, 상대가 즉시 제거할 상황에서 자동으로 설치하지 않는다.

### 5.4 막이와 피벗

막이는 단순히 받는 피해가 낮은 포켓몬이 아니다.

- 어떤 공격 축과 상대를 담당하는지
- 회복 PP와 상태이상 내성
- 반복 진입 가능한 횟수
- 도발·트릭·랭크업에 무너지는지
- 피벗 뒤 어떤 아군에게 주도권을 연결하는지

막이가 담당해야 할 상대 에이스가 살아 있다면 HP와 도구를 우선 보존한다.

## 6 랭크업 견제

AI는 수동적인 행동이 상대에게 주는 `무료 랭크업 턴`을 명시적으로 평가한다.

```text
상대 랭크업 가능성
  × 랭크업 후 돌파 범위
  × 현재 대응 수단의 수
  × 즉시 처벌 가능성
  → SetupThreatLevel
```

위협 수준이 높으면 다음 행동을 우선 후보로 올린다.

- 즉시 KO 또는 마무리 범위 진입
- 도발, 앙코르, 클리어스모그, 흑안개
- 울부짖기 등 강제 교체
- 마비·화상·수면 등 기능 저하
- 기띠·옹골참 제거를 위한 선행 피해
- 랭크업 뒤에도 선공 가능한 복수 포켓몬 보존
- 상대가 랭크업하기 어려운 공격적 대면 유지

회복, 판 설치와 소극적 교체는 상대의 랭크업 후 결과까지 탐색한 뒤 허용한다. 한 번의 랭크업으로 팀 전체가 무너지는 장면에서는 현재 턴의 작은 이득보다 견제를 우선한다.

## 7 전략 계획 모델

```text
StrategicPlan
  plan_id
  primary_goal
  secondary_goals
  protected_resources
  expendable_resources
  target_threats
  required_sequence
  invalidation_conditions
  horizon
```

계획 예시:

- `PRESERVE_ACE_UNTIL_WALL_REMOVED`
- `KEEP_WALL_FOR_ENEMY_ACE`
- `CHIP_ENEMY_ACE_INTO_PRIORITY_RANGE`
- `DENY_SETUP_WINDOW`
- `ESTABLISH_HAZARDS_FOR_SWITCH_HEAVY_TEAM`
- `REMOVE_HAZARDS_BEFORE_ACE_ENTRY`
- `TRADE_LOW_VALUE_POKEMON_FOR_TEMPO`

매 턴 계획을 무조건 새로 고르지 않는다. 상태가 크게 변하거나 무효 조건이 발생할 때 재계획하고, 계획 변경 이유를 판단 로그에 남긴다.

## 8 점수제의 새 역할

```text
하드 제약
  → 전략 목표와 금지 행동
  → 제한 깊이 상태 탐색
  → 후보별 기대 승리 기여도
  → 전술 점수와 확률 선택
```

- 에이스의 불필요한 희생처럼 전략적으로 금지된 행동은 높은 즉시 피해 점수로 되살릴 수 없다.
- 점수는 같은 전략을 만족하는 후보 사이의 비교에 사용한다.
- 기술, 교체, 아이템과 기믹을 공통 상태 전이 결과로 비교한다.
- 최종 비교는 경험적 상수 대신 `Q(s, a) - V(s)`를 중심으로 정규화하고, 자원 가치는 가치 모델의 상태 특징으로 반영한다.

## 9 제한적 난수와 패턴 방지

AI는 항상 최고 점수 행동 하나를 고르지 않는다. 그렇다고 모든 행동을 무작위로 섞지도 않는다.

### 9.1 후보 집합

1. 불법·전략 위반·치명적 행동 제거
2. 최고 기대 효용에서 허용 범위 안의 후보만 유지
3. 상황과 난이도에 따른 온도로 확률 분포 계산
4. 전투 RNG와 분리된 `decision_seed`로 선택

```text
P(action) = softmax(utility / temperature)
```

- `novice`는 후보 범위와 온도가 넓고 실수 정책이 추가된다.
- `standard`와 `advanced`는 안전한 대안 사이에서 변주한다.
- `expert`는 거의 동등한 전략 후보만 혼합한다.
- `cheater`도 정확한 카운터가 여러 개면 패턴을 섞는다.

### 9.2 악용 방지

- 같은 상대·상태에서 최근 선택 이력을 기억한다.
- 플레이어가 특정 행동을 반복해 AI의 고정 반응을 유도하는지 감지한다.
- 상대 전략이 반복되면 대응 분포를 갱신한다.
- 반복 페널티만으로 나쁜 행동을 고르지 않고 전략 허용 집합 안에서만 변주한다.
- 확정 KO, 유일 생존 수단과 강제 행동은 불필요하게 랜덤화하지 않는다.

### 9.3 재현성

- 전투 시드와 AI 결정 시드를 분리한다.
- 리플레이에 난이도, 정책 버전, 후보 확률과 선택 난수를 기록한다.
- 같은 입력·정책·시드는 JVM과 JS에서 같은 행동을 선택한다.
- 평가에서는 여러 고정 시드 묶음을 사용해 운 좋은 한 경기로 판단하지 않는다.

## 10 전략 테스트

### 10.1 장면 테스트

- 에이스가 불필요한 공격에 쓰러지는 행동 금지
- 에이스 진입 전에 설치물을 제거하거나 필요한 HP 확보
- 상대 에이스의 유일한 카운터를 보존
- 상대 에이스를 복수 기술 범위로 만드는 누적 피해 계획
- 위험한 랭크업 장면에서 수동적 기술 대신 견제
- 판 설치가 유효한 팀과 무의미한 팀 구분
- 막이의 회복 자원과 담당 대면 보존
- 역할을 마친 포켓몬을 합리적으로 교환

### 10.2 대전 테스트

- 전략 AI 대 기존 단순 점수 AI
- 전략 AI 대 고정 패턴을 악용하는 스크립트
- 에이스·막이·판 설치 중심의 대표 팀 조합
- 같은 팀의 선발·좌우 위치 교환
- 공개 정보만 사용하는 평가와 치터 평가 분리

### 10.3 지표

- 자신의 에이스 생존율과 유효 투입 횟수
- 상대 에이스 제거율과 제거까지 걸린 턴
- 유일 카운터의 조기 손실 횟수
- 상대에게 허용한 무상 랭크업 횟수
- 랭크업 직후 전멸·대량 손실 횟수
- 설치물의 실제 누적 피해와 제거 가치
- 전략 계획 유지·변경·실패 이유
- 동일 장면의 행동 엔트로피와 플레이어 유도 성공률
- 기존 점수 AI 대비 승률과 최악 매치업 성능
- 팀 프리뷰·전투 상태 승률의 Brier score와 보정 오차
- 선택 행동의 평균 기대 승률 변화 `Q(s, a) - V(s)`

## 11 구현 순서

1. 역할 태그, 팀 분석기와 `TeamPreviewValue`
