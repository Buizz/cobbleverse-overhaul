# 전투 규칙 완전성 및 특수 효과 테스트 계획

> 대상: Cobblemon 1.8 계열에서 Cobbleverse가 허용하는 기술·특성·도구·기믹
>
> 목표: 특수 효과를 일반 피해로 근사하거나 조용히 무시하는 항목 0개
>
> 상태: 적합성 체계 설계 / Cobblemon 1.8 카탈로그 미확정

## 1 목표

소금절이처럼 일반 피해 공식만으로 표현할 수 없는 효과를 포함해 지원 대상의 전투 규칙을 하나도 빠짐없이 구현하고 테스트한다.

```text
Cobblemon 1.8 지원 카탈로그
  → 효과 요구사항 추출
  → 엔진 핸들러 연결
  → 단위·상호작용·차등 테스트 연결
  → JVM·JS 동일성 검증
  → 지원 현황 보고서 생성
```

정의되지 않은 효과를 위력·명중률만 사용해 실행하는 폴백은 금지한다. 엔진이 모르는 효과를 만나면 개발·테스트 환경에서는 명확히 실패하고, Minecraft 운영 환경에서는 안전 기본 AI로 전환하면서 누락 ID를 기록한다.

## 2 완전성 범위

최종 목표는 선택한 Cobblemon 1.8 버전에서 Cobbleverse가 획득·사용 가능하게 둔 다음 카탈로그의 100%다.

- 기술
- 특성
- 도구
- 상태이상과 휘발성 상태
- 날씨, 필드, 방·사이드 상태와 설치물
- 교체·기절·턴 종료 효과
- 메가진화 등 프로젝트가 채택한 기믹
- 싱글과 프로젝트가 지원하는 더블 배틀 상호작용

개발 중에는 관장 팀 단위로 범위를 확장할 수 있지만, 미구현 항목이 포함된 팀·전투 데이터는 활성화할 수 없다.

## 3 적합성 목록

각 항목은 자동 생성되는 목록에서 다음 상태를 가진다.

```text
MechanicsCoverageEntry
  kind
  id
  source_version
  handler_ids
  unit_test_ids
  interaction_test_ids
  differential_test_ids
  jvm_js_golden_ids
  support_status
  known_differences
```

| 상태 | 의미 |
|------|------|
| `DISCOVERED` | Cobblemon 데이터에서 발견했으나 분석 전 |
| `SPECIFIED` | 효과와 상호작용 요구사항 작성 |
| `IMPLEMENTED` | 엔진 핸들러 연결 |
| `UNIT_TESTED` | 독립 규칙 테스트 통과 |
| `INTERACTION_TESTED` | 관련 효과 조합 테스트 통과 |
| `DIFF_TESTED` | Cobblemon 실제 결과와 비교 |
| `COMPLETE` | JVM·JS 골든 테스트까지 통과 |
| `INTENTIONALLY_UNSUPPORTED` | 명시적 사유로 콘텐츠에서 비활성화 |

출시 보고서에는 전체 개수, 상태별 개수와 미완료 ID를 출력한다. `COMPLETE` 또는 승인된 `INTENTIONALLY_UNSUPPORTED`가 아닌 항목이 사용 가능 데이터에 남아 있으면 품질 게이트를 실패시킨다.

## 4 특수 효과 분류

효과를 기술 이름별 거대한 조건문으로 만들지 않고 재사용 가능한 핸들러와 상태 전이로 분류한다.

| 분류 | 예시 |
|------|------|
| 동적 위력 | 현재 HP, 속도, 랭크, 연속 사용과 상대 상태에 따른 위력 |
| 고정·비표준 피해 | 레벨 피해, HP 비율 피해, 일격기 |
| 지속 효과 | 소금절이, 씨뿌리기, 조이기 계열 |
| 다중 턴 | 구르기, 역린, 미래예지, 충전·반동 |
| 다중 타격 | 2~5회, 명중 개별 판정, 위력 증가형 타격 |
| 교체 연동 | 유턴, 볼트체인지, 배턴터치, 강제 교체 |
| 필드 설치 | 스텔스록, 압정, 벽, 순풍과 룸 |
| 보호·우선도 | 방어 연속 실패, 기습, 도우미, 사이코필드 |
| 타입·특성 변경 | 테라스탈, 물붓기, 기술 타입 변경 |
| 복사·봉인 | 앵콜, 도발, 사슬묶기, 흉내내기 |
| 대상·더블 | 광역 피해, 아군 대상, 리다이렉션, 아군 공격 |
| 도구·특성 상호작용 | 틀깨기, 우격다짐, 은밀망토, 매직가드 |

## 5 소금절이 적합성 예시

콜로솔트의 전용기 소금절이는 단순 위력 40 공격으로만 구현하면 안 된다. 기준 프로필에는 최소 다음 테스트가 필요하다.

| 테스트 | 확인 내용 |
|--------|-----------|
| 기본 타격 | 명중·직접 피해 후 지속 상태 부여 |
| 일반 대상 | 턴 종료 시 최대 HP의 1/8 피해 |
| 물 또는 강철 | 턴 종료 피해가 최대 HP의 1/4 |
| 물·강철 복합 | 두 타입 보정이 중복 곱해지지 않음 |
| 교체 | 영향을 받은 포켓몬이 교체되면 효과 제거 |
| 사용자 교체 | 사용자가 교체되어도 대상의 효과는 유지 |
| 재사용 | 중복 상태와 피해가 의도치 않게 중첩되지 않음 |
| 타입 변경 | 효과 적용 중 타입이 변할 때 Cobblemon 1.8 기준 피해 확인 |
| 방어·빗나감 | 기술이 성공하지 않으면 효과를 부여하지 않음 |
| 특성·도구 | 관련 피해·부가 효과 차단 규칙 확인 |
| 기절·턴 종료 | 직접 피해로 기절한 경우 불필요한 지속 사건이 없음 |
| 리플레이 | 적용·잔여 피해·제거 사건이 직렬화됨 |
| 플랫폼 | JVM과 JS 사건 로그가 동일 |
| 차등 | 동일 장면의 Cobblemon 1.8 실제 결과와 일치 |

본가나 Pokémon Showdown과 Cobblemon의 결과가 다르면 `cobblemon_1_8` 규칙 프로필에 차이를 명시한다. 외부 자료의 값을 무조건 복사하지 않는다.

## 6 테스트 생성 규칙

### 6.1 항목별 최소 테스트

모든 기술은 최소 다음을 가져야 한다.

- 정상 성공
- 실패 또는 무효
- 최소·최대 피해나 효과 경계
- 사용자·대상 기절
- 교체와 턴 종료
- 직렬화·리플레이
- JVM·JS 동일성

특수 핸들러가 있는 항목은 관련 상호작용 테스트를 추가한다. 특성·도구도 활성, 억제, 소비, 복구와 중복 적용 테스트를 가진다.

### 6.2 조합 테스트

모든 가능한 조합의 전수 곱은 현실적이지 않으므로 효과 태그로 위험 조합을 자동 생성한다.

```text
effect:residual_damage
  × ability:damage_immunity
  × item:secondary_effect_block
  × event:switch
  × event:type_change
```

- 같은 이벤트 우선순위를 공유하는 효과
- 피해 공식을 수정하는 효과가 둘 이상인 경우
- 교체·기절·폼·타입 변경 경계
- 더블 배틀의 대상 수와 리다이렉션
- 지속 상태의 적용·갱신·제거

### 6.3 차등 테스트

동일한 초기 상태와 명령을 Cobblemon 1.8과 내장 엔진에서 실행해 사건을 비교한다.

- 행동 가능 여부
- 행동 순서
- HP 변화
- 상태·랭크·필드 변화
- 도구 소비
- 교체와 기절
- 다음 턴 요청 종류

난수 결과를 직접 맞출 수 없으면 가능한 결과 집합과 분포를 비교하고, 고정 가능한 장면은 정확한 사건 로그를 비교한다.

## 7 데이터와 CI

- Cobblemon 1.8 데이터에서 ID 카탈로그를 생성한다.
- 프로젝트 규칙 파일에 효과 핸들러 ID를 선언한다.
- 테스트 파일은 대응하는 카탈로그 ID를 메타데이터로 가진다.
- CI가 카탈로그·핸들러·테스트의 양방향 누락을 검사한다.
- ID가 삭제·변경되면 명시적인 마이그레이션 없이는 빌드를 실패시킨다.
- PR마다 적합성 비율과 새 미지원 항목을 요약한다.

```text
enabled move without handler       → FAIL
handler without test               → FAIL
test for unknown data id           → FAIL
JVM/JS golden mismatch             → FAIL
unreviewed Cobblemon diff           → FAIL
```

## 8 단계별 완료 기준

1. 첫 관장 팀이 사용하는 모든 효과 `COMPLETE`
2. 첫 지방의 모든 트레이너 팀 효과 `COMPLETE`
3. Cobbleverse에서 획득 가능한 전체 카탈로그 `COMPLETE`
4. 프로젝트가 공식 지원한다고 선언한 Cobblemon 1.8 전체 범위 `COMPLETE`

기술 수만 세지 않는다. 동일 기술의 특성·도구·타입·교체 상호작용까지 적합성 기준에 포함한다.
