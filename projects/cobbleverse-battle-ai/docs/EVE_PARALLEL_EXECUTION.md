# EvE 반복 전투 병렬 실행

## 목표

승률 및 전략 성향 분석에서 서로 독립적인 전투를 CPU 코어에 분배한다.
동일 시드와 동일 AI 설정은 병렬 실행 여부와 관계없이 같은 결과를 내야 한다.

## 실행 구조

- 로컬 개발 서버: Node.js `worker_threads`
- 배포 환경: Cloudflare 호환 순차 폴백
- 지원 병렬 수: 자동, 1, 2, 4, 8
- 자동 병렬 수: `min(8, 논리 프로세서 수 - 1)`
- 작업 분배: 전투 인덱스를 기준으로 워커에 라운드 로빈 분배
- 결과 결합: 원래 작업 인덱스로 정렬
- 상세 전투 로그: 승률 집계가 끝난 뒤 대표 전투 한 건만 별도 생성

## AI 내부 병렬화 검토

한 전투 안에서도 다음 구간은 이론상 병렬화할 수 있다.

- 양쪽 AI의 기본 후보 평가
- 1턴 탐색의 아군 후보와 상대 후보 조합
- 2턴 연장 빔의 후속 상태 평가

현재는 이 구간을 별도 워커로 분리하지 않는다.

1. 후보 상태 하나의 계산 시간이 짧아 상태 직렬화와 워커 통신 비용 비중이 크다.
2. 현재 전투 엔진과 AI 선택 API가 동기식이라 비동기 워커 도입 시 호출 경로 전체가 바뀐다.
3. 반복 전투 워커와 내부 워커를 동시에 사용하면 코어 수가 곱으로 늘어 과도한 경쟁이 발생한다.
4. 각 워커의 상태 전이 캐시가 분리되어 기존 캐시 적중 이점이 줄어든다.

따라서 현재 단계에서는 전투 단위 병렬화를 우선 사용한다. 단일 전투의 지연 시간을
줄여야 할 때는 지속형 AI 전용 워커 풀과 비동기 전투 실행기를 별도 실험하고,
다음 기준을 모두 만족할 때만 기본 경로에 적용한다.

- 단일 전문가(2턴 탐색) 전투가 20% 이상 빨라질 것
- 동일 시드 결과가 완전히 일치할 것
- 4개 이상 반복 전투에서는 내부 워커를 자동 비활성화할 것
- 상태 전이 캐시 적중률 저하를 포함해도 총 시간이 감소할 것
