# 월드 서식지 탐색과 포켓몬 스폰 설계

## 결정

Cobbleventure는 **어떤 포켓몬이 현재 월드의 어느 서식지에 나오는지** 결정한다.
실제 야생 포켓몬 생성, 개체 수 제한, 위치 검사와 엔티티 수명주기는 Cobblemon의
스폰 엔진을 사용한다.

Cobblemon 스폰 엔진을 완전히 대체하지 않는다. 현재 서식지 카탈로그에는 포켓몬의
지역 적합성은 있지만 레벨 범위, 지상·수중·공중 위치 타입, 광량, 블록 조건과 무리
스폰 정보가 없다. 이 값을 새로 복제하면 Cobblemon 및 애드온과의 호환 비용이 크고,
도감에 표시되는 정보와 실제 스폰 규칙이 서로 달라질 가능성도 높다.

## 단일 데이터 흐름

1. `pokemon-habitats.json`이 포켓몬의 최초 등장 세대, 시리즈별 지역도감 출현 여부, 전설·환상 분류, 주·보조 서식지, 기후, 시간과 희귀도를 정의한다.
2. `biome-profiles.json`이 월드 바이옴 프로필과 강제 포함·제외를 정의한다.
3. `build_spawn_index.py`가 Cobblemon 원본의 레벨, 버킷, 가중치, 위치 타입과 조건을 보존한다.
4. 마을 생성기가 실제로 배치한 구역을 `GeneratedHabitatZone` 스냅샷으로 확정한다.
5. `HabitatIndex`가 각 구역의 출현 후보를 계산한다.
6. `WorldHabitatIndex`가 구역→포켓몬과 포켓몬→실제 위치 조회를 동시에 제공한다.
7. `HabitatMapQueryService`가 발견 상태와 원본 스폰 규칙을 합쳐 우측 패널 데이터를 만든다.
8. 지도형 탐색 UI와 Cobblemon 스폰 어댑터가 같은 인덱스를 읽는다.

`generation`은 포켓몬이 처음 추가된 세대를 설명하는 메타데이터다. 특정 세대 월드의
출현 후보는 같은 번호의 신규 포켓몬 목록이 아니라 `series_appearances`에 기록된 지역도감
수록 여부로 제한한다. 예를 들어 성도 시리즈는 2세대 신규 포켓몬뿐 아니라
`original-johto` 지역도감에 수록된 1세대 포켓몬도 포함한다. `SpawnSettings.series`가
지정되면 이 기준을 우선하고, 비어 있을 때만 기존 `generation` 필터를 호환용으로 사용한다.

`is_legendary` 또는 `is_mythical`이 참인 포켓몬은 레어도 설정과 무관하게 일반
서식지 후보에서 제외한다. 스토리, 이벤트, 고정 심볼 인카운터처럼 의도적으로
배치할 때만 `unconditional_spawns` 또는 프로필의 `forced_includes`로 명시한다.

## 번호형 서식지 분할

기후 조건으로 후보를 잘게 거르지 않고, 지역도감과 주·보조 서식지 조건을 통과한
일반 후보를 도감 번호 순으로 균등 분할한다. `max_pokemon_per_habitat_variant`의
기본값은 40이며 이를 넘으면 `숲1`, `숲2`, `숲3`처럼 필요한 수만큼 번호를 만든다.

분할 수는 전체 1,025종이 아니라 현재 월드의 지역도감 후보 수로 계산한다. 따라서
관동의 숲과 팔데아의 숲은 서로 다른 개수의 번호를 가질 수 있다. 월드 구역은 같은
프로필의 활성 번호를 라운드로빈으로 빠짐없이 순환하며, 마을이나 이벤트는
`spawn_settings.habitat_variant`에 1 이상의 값을 넣어 특정 번호를 고정할 수 있다.
값이 0이면 자동 배정이다. 전설·환상 및 강제 출현은 이 일반 후보 분할과 별도로 처리한다.

`biome_layout.zones`는 생성 전 의도이고 `GeneratedHabitatZone`은 생성 후 실제 결과다.
탐색 UI는 반드시 후자를 사용해야 아직 생성되지 않았거나 이번 시드에 배치되지 않은
장소를 안내하지 않는다.

## 지도형 탐색 UI

기존 포켓네비를 그대로 복제하지 않고 현재 월드 중심의 **서식지 지도**를 제공한다.
본가 포켓몬 지도의 큰 지도+지역 상세 패널이라는 정보 구조는 차용하되 원본 지도,
아이콘, 프레임과 기타 그래픽 자산은 복사하지 않고 Cobbleventure 리소스로 제작한다.

```text
┌──────────────────────────── 현재 월드 지도 ────────────────────────────┬──────── 출현 정보 ────────┐
│  미발견 영역: 안개                                                   │ 시작 마을 외곽 숲          │
│                                                                     │ 구구        기본 풀 18.2%  │
│        [시작 마을] ── [외곽 숲] ── [강변]                            │ 이상해씨    기본 풀  2.4%  │
│                         ▲ 선택                                      │ 캐터피      기본 풀 14.8%  │
│                                                                     │ 낮 · 맑음 · 지상           │
│  드래그: 이동 / 휠: 확대 / 아이콘: 지역 선택                         │ [도감 보기] [추적하기]      │
└─────────────────────────────────────────────────────────────────────┴───────────────────────────┘
```

| 화면 | 표시 내용 |
|---|---|
| 월드 지도 | 발견한 마을과 서식지 구역, 중심 좌표, 대략적인 반경 |
| 구역 상세 | 현재 조건에서 출현 가능한 포켓몬, 희귀도, 낮·밤·날씨 조건 |
| 포켓몬 상세 | 현재 월드에 실제 존재하는 출현 구역 목록과 가장 가까운 발견 지점 |
| 미발견 항목 | 실루엣과 넓은 지역 힌트만 표시하고 정확한 좌표는 숨김 |

도감의 포획·관찰 상태는 Cobblemon의 기존 도감 데이터를 그대로 사용하고,
Cobbleventure는 도감 상세 화면에서 열 수 있는 `서식지` 탭 또는 별도 지도 화면만
추가한다. 서버는 플레이어가 발견한 위치만 전송해 미탐험 지역 누출을 막는다.

지도 클라이언트는 월드 전체 스폰 데이터를 직접 받지 않는다. 서버가 플레이어의
발견 위치 ID 집합을 적용한 `visibleZones`와 선택 위치의 `HabitatMapPanel`만 보낸다.
따라서 리소스팩이나 클라이언트 화면을 조사해도 미발견 마을 좌표가 노출되지 않는다.

## 확률 표시

Cobblemon의 `weight`는 전체 자연 스폰 확률이 아니라 `common`, `uncommon`, `rare`,
`ultra-rare` 버킷 안의 상대 가중치다. 우측 패널은 두 값을 구분한다.

- 기본 풀 비중: 같은 구역 후보들의 Cobblemon 원본 가중치로 미리 계산하며 항상 표시 가능
- 현재 예상 확률: 시간·날씨·광량·위치·동적 배율과 현재 버킷 선택률을 서버에서 계산할 때만 표시

원본 자연 스폰 규칙이 없는 포켓몬은 임의 확률을 만들지 않고 `특수 출현`으로 표시한다.
현재 대조에서는 구현 표시된 851종 중 823종에 자연 스폰 규칙이 있고 28종은 규칙이
없다. 이 28종은 퀘스트·화석 복원·전설 이벤트 또는 명시적 커스텀 스폰이 필요하다.

## Cobblemon 어댑터

어댑터는 다음 두 단계로 나눈다.

- 후보 필터: 현재 플레이어 주변의 `GeneratedHabitatZone`을 찾아
  `WorldHabitatIndex.encountersAt(locationId)` 결과만 허용한다.
- 실제 생성: 선택된 포켓몬의 Cobblemon 원본 스폰 상세에서 레벨, 프리셋,
  위치 타입과 세부 조건을 유지한 채 Cobblemon 생성 파이프라인에 위임한다.

원본 규칙이 존재하면 카탈로그의 희귀도보다 Cobblemon 버킷과 가중치를 우선한다.
원본이 없는 전설·환상·화석 포켓몬은 일반 자연 스폰에 바로 넣지 않고 퀘스트,
이벤트 또는 별도의 명시적 커스텀 규칙이 있을 때만 허용한다.

## 다음 수직 프로토타입

1. 마을 생성 완료 시 실제 구역 중심·반경을 월드 저장 데이터에 기록한다.
2. 생성 결과에서 플레이어별 발견 위치 ID를 월드 저장 데이터에 기록한다.
3. NeoForge/Cobblemon 1.7.3 어댑터에서 한 개 구역의 후보 제한을 적용한다.
4. 서버 명령으로 `위치 → 후보`와 `포켓몬 → 위치` 결과를 비교한다.
5. 위 와이어프레임의 최소 지도 화면과 서버 패킷을 구현한다.
6. 스폰 결과와 화면 결과가 동일한 인덱스 버전을 사용했는지 자동 검증한다.
