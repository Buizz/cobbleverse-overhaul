## 1 프로젝트 개요
코블버스의 기존 콘텐츠를 대체하기보다, 지역 탐험과 서버 장기 목표를 강화하는 확장 계층을 목표로 한다.

### 1.1 비전
플레이어는 월드에 흩어진 “체육관 도시”를 찾아 지역별 리그를 공략한다. 각 도시는 체육관, 마을, 상점, 영구 트레이너가 하나의 랜드마크로 구성되며, 지역을 완료할수록 새로운 포켓몬과 경제 선택지가 열린다. 최종적으로 서버의 플레이어 챔피언 자리를 놓고 경쟁하고, 챔피언은 유지 조건을 충족하는 동안 일일 보상을 받는다.

### 1.2 프로젝트 목표
- 탐험 목표를 명확하게 만든다: 체육관과 마을을 우연히 따로 찾는 대신, 지역별 핵심 도시를 찾아가는 여정을 제공한다.
- 진행을 압축한다: 한 지방에 필요한 관장 수를 줄이고, 각 관장전의 정체성과 보상을 강화한다.
- 서버 플레이를 장기화한다: 지역 해금, 배틀타워, 병뚜껑 경제, 플레이어 챔피언을 연결한다.
- NPC 생태를 통제한다: 자연 트레이너는 최소화하고, 필요한 트레이너는 도시 구성원으로 영구 배치한다.
- 운영 가능한 시스템을 만든다: 구조물 누락, NPC 삭제, 진행 꼬임, 챔피언 공석을 관리자가 복구할 수 있어야 한다.

### 1.3 성공의 정의
| **영역**       | **성공 조건**                                                                                       |
|----------------|-----------------------------------------------------------------------------------------------------|
| **탐험**       | 각 지방의 체육관 도시가 예측 가능한 규칙으로 존재하며, 체육관과 마을이 분리되지 않는다.             |
| **진행**       | 관장 수가 줄어도 각 지방의 시작·중간·완료가 명확하고 다음 해금으로 자연스럽게 연결된다.             |
| **전투**       | 일반 트레이너, 체육관 트레이너, 관장, 챔피언의 난이도 차이가 팀 구성과 AI 행동으로 체감된다.        |
| **경제**       | 사탕, 디스크, 병뚜껑, 네더라이트 등 주요 아이템이 여러 활동에서 획득되며 한 활동만 강제하지 않는다. |
| **멀티플레이** | 챔피언 도전과 일일 보상이 명확한 규칙으로 운영되고, 보상 돌려먹기·로그아웃 악용을 억제한다.         |
| **운영**       | 업데이트와 장애 후에도 진행 데이터, 도시 위치, NPC, 챔피언 상태를 확인하고 복구할 수 있다.          |

### 1.4 프로젝트 한눈에 보기
| **작업 영역**  | **핵심 변화**                                 | **우선순위** |
|----------------|-----------------------------------------------|--------------|
| **월드/도시**  | 체육관+마을 일체형 랜드마크, 결정론적 배치    | 필수         |
| **트레이너**   | 자연 스폰 최소, 도시 영구 배치, 난이도별 AI   | 필수         |

| **보상**       | 트레이너 등급별 사탕·디스크·화폐 보상         | 필수         |
| **멀티플레이** | 서버 단일 챔피언, 정식 도전, 일일 보상        | 필수         |

| **확장**       | 시즌, 랭킹, 오프라인 챔피언 대리전            | 후속         |

## 2 범위와 설계 원칙
첫 버전은 “한 지방을 완주할 수 있는 수직 구간”을 우선하며, 콘텐츠 양보다 시스템 완성도를 검증한다.

### 2.1 포함 범위
- 체육관과 마을이 항상 붙어 있는 체육관 도시의 배치 규칙
- 마을별 영구 트레이너와 관장, 자연 트레이너 스폰 최소화
- 트레이너 AI 난이도 계층과 팀 구성 기준
- 지방당 관장 수 축소와 지역 완료 판정
- 지역 완료에 따른 포켓몬 출현군 해금
- 일반 상점과 배틀타워 상점의 역할 재정의
- 병뚜껑, 사탕, 기술 디스크 등 핵심 육성 아이템의 획득 경로
- 트레이너 최초 승리/재대결 보상 구조
- 플레이어 챔피언 도전, 소유권 이전, 일일 보상
- 관리자 복구, 데이터 이관, 호환성 경고에 필요한 운영 기능

### 2.2 초기 제외 범위
- 신규 포켓몬 종, 신규 배틀 시스템, 완전한 경쟁전 규칙 엔진의 자체 개발
- 대규모 MMORPG형 경매장, 직업, 토지 보호, 길드 전쟁 시스템
- 플레이어마다 서로 다른 자연 포켓몬을 보이게 하는 개인 전용 월드 스폰
- 여러 서버 사이의 챔피언·진행 상태 동기화
- 오프라인 챔피언의 팀을 AI가 완전히 대신하는 비동기 방어전
- 모든 기존 월드를 자동으로 무손실 변환하는 범용 마이그레이션

> **범위 관리:** 제외 기능은 필요성이 확인되면 후속 버전 후보로 이동한다. 첫 버전의 목표는 기능 수가 아니라 한 지방의 탐험-관장-해금-챔피언 흐름을 안정적으로 완성하는 것이다.

### 2.3 핵심 설계 원칙

|-------------------|--------------------------------------------------------------------------------------------|

## 3 목표 플레이 경험
핵심 루프는 탐험, 도시 공략, 지역 완료, 해금, 서버 경쟁의 다섯 단계로 구성한다.

### 3.1 핵심 플레이 루프
| **체육관 도시 탐색** | **→** | **마을 트레이너 공략** | **→** | **관장 도전** | **→** | **지방 완료·해금** | **→** | **챔피언 경쟁** |
|----------------------|-------|------------------------|-------|---------------|-------|--------------------|-------|-----------------|

### 3.2 플레이어 여정 예시
| **단계**           | **경험**                                                                                   |
|--------------------|--------------------------------------------------------------------------------------------|
| **1. 발견**        | 탐험 지도, 안내 NPC, 좌표 힌트 또는 구조물 찾기 기능으로 첫 체육관 도시를 발견한다.        |
| **2. 준비**        | 마을 상점과 일반 트레이너를 통해 회복 아이템, 사탕, 기본 디스크를 확보한다.                |
| **3. 검증**        | 체육관 내부 트레이너를 상대하며 해당 관장의 타입·전술을 간접적으로 학습한다.               |
| **4. 관장전**      | 지역 진행 조건을 충족하면 관장에게 도전하고 배지, 최초 보상, 다음 도시 접근 정보를 얻는다. |
| **5. 지역 완료**   | 정해진 수의 관장 또는 지역 최종전을 완료하면 다음 포켓몬 출현군과 상점 단계가 열린다.      |
| **6. 반복 성장**   | 재대결, 배틀타워, 희귀 보상을 통해 팀을 다듬고 병뚜껑 등 후반 육성 자원을 모은다.          |
| **7. 챔피언 도전** | 자격을 얻은 플레이어가 현재 챔피언과 정식 PvP를 진행하고 승리 시 지위를 넘겨받는다.        |

### 3.3 난이도 곡선
- 일반 마을 트레이너: 시스템 학습과 기본 보급을 담당하며 패배 비용이 낮다.
- 체육관 트레이너: 관장전의 테마를 예고하고, 교체·상태이상·소지품 사용을 제한적으로 보여준다.
- 관장: 완성된 팀 역할과 명확한 승리 조건을 갖고, 숨겨진 능력치 보정 대신 합리적인 AI와 팀 구성으로 강해진다.
- 지역 최종전 또는 NPC 챔피언: 다음 지역 해금의 관문으로, 해당 지방의 핵심 전략을 종합한다.
- 플레이어 챔피언전: 서버가 정한 공정한 규칙 아래 실제 플레이어 대 플레이어 실력을 겨룬다.

## 4 기능 요구사항
각 기능은 구현 기술이 아니라 사용자 경험과 운영 기준을 중심으로 정의한다.

### 4.1 체육관과 마을의 일체형 월드 생성
> **목적**
> 체육관을 독립 건물로 흩어 놓지 않고, 마을·상점·트레이너를 포함한 하나의 지역 랜드마크로 만든다.
>
> **플레이어 경험**
> 플레이어가 체육관을 찾으면 준비, 전투, 보급, 안내 기능을 한 장소에서 이용할 수 있다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 체육관과 마을은 하나의 “체육관 도시” 단위로 생성되며 서로 분리되어 생성되지 않는다.
- 각 지방의 필수 체육관 도시 수와 최소 간격을 설정할 수 있어야 한다.
- 도시 위치는 월드 시드와 설정에 따라 재현 가능하며, 특정 지역에 과도하게 몰리지 않아야 한다.
- 지형·바이옴 조건을 만족하지 못할 때 대체 후보지를 탐색하거나 명확한 실패 상태를 기록한다.
- 도시마다 고유 ID를 부여해 중복 생성, NPC 중복, 진행 상태 충돌을 방지한다.
- 관리자가 도시 위치를 조회하고, 누락된 도시 또는 NPC를 복구할 수 있어야 한다.

#### 결정이 필요한 항목
- 배치 방식: 스폰 주변 동심원/구역 방식, 사전 정의 좌표 방식, 지도형 월드 방식 중 선택.
- 기존 바닐라·코블버스 마을과 공존할지, 체육관 도시만 주요 진행 거점으로 사용할지 결정.
- 기존 월드에 자동 배치할지, 관리자 수동 배치만 지원할지 결정.
- 첫 버전에서 사용할 지방 수와 도시별 건축 규모를 결정.

#### 완료 기준
- 검증용 월드 시드 집합에서 필요한 체육관 도시가 누락 없이 배치된다.
- 모든 체육관은 자신의 마을 경계 안에 연결되어 있으며 단독 구조물로 떨어지지 않는다.
- 동일 월드에서 재접속·재시작 후에도 도시 ID와 위치가 변하지 않는다.
- 도시 또는 NPC가 손상되었을 때 관리 절차로 복구할 수 있다.

> **권고:** “황혼의 숲처럼”이라는 목표는 정확한 좌표 고정보다, 필수 랜드마크가 일정 규칙으로 반드시 존재하고 서로 연결된다는 경험으로 정의한다.

### 4.2 일반 상점 아이템 완화
> **목적**
> 네더라이트 등 생존·건축·후반 진행의 병목 아이템을 상점에서도 확보할 수 있게 하여 불필요한 반복 채굴을 줄인다.
>
> **플레이어 경험**
> 플레이어는 탐험과 전투로 벌어들인 화폐를 사용해 필요한 자원을 보완하되, 상점만으로 모든 진행을 건너뛰지는 못한다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 상점 재고는 기본, 중급, 후반 단계로 구분하고 지역 진행 또는 자격 조건과 연결할 수 있어야 한다.
- 네더라이트 관련 아이템은 구매 가능하되 가격, 구매 단위, 해금 시점으로 희소성을 유지한다.
- 생존 편의 아이템과 포켓몬 육성 아이템의 가격 체계를 분리해 한쪽 경제가 다른 쪽을 붕괴시키지 않게 한다.
- 재고 변경은 데이터 또는 설정으로 조정 가능해야 하며 전체 코드를 수정하지 않아야 한다.

#### 결정이 필요한 항목
- 네더라이트를 조각·주괴·장비 중 어느 형태로 판매할지 결정.
- 지역 해금형 상점과 모든 마을 공통 상점 중 어느 구조를 사용할지 결정.
- 무제한 구매, 일일 수량 제한, 회전 재고 중 운영 방식을 결정.
- 주요 화폐를 기존 화폐 하나로 통합할지, 일반 화폐와 전투 포인트를 분리할지 결정.

#### 완료 기준
- 후반 자원을 상점에서 얻을 수 있으나 초반 탐험과 채굴의 의미가 사라지지 않는다.
- 주요 품목에 가격·해금 근거가 문서화되어 밸런스 변경 이력을 추적할 수 있다.
- 상점 데이터 갱신 후 기존 월드와 플레이어 저장 데이터가 손상되지 않는다.

### 4.3 배틀타워 판매 아이템 재정리
> **목적**
> 배틀타워를 단순 반복 전투가 아니라 고급 육성 아이템과 병뚜껑을 얻는 대표적인 후반 콘텐츠로 만든다.
>
> **플레이어 경험**
> 플레이어는 경쟁적인 전투를 통해 일반 상점에서 얻기 어려운 아이템을 선택적으로 구매한다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 판매 품목을 육성, 개체값, 전투, 희귀 기술, 장식/명예 범주로 구분한다.
- 일반 상점과 겹치는 품목은 가격 또는 역할 차이를 두고, 배틀타워의 고유 보상을 확보한다.
- 병뚜껑은 꾸준히 모으면 확정 구매할 수 있게 하고, 금병뚜껑은 더 강한 제한을 둔다.
- 지역 완료나 랭크에 따라 품목을 단계적으로 개방할 수 있어야 한다.
- 가격표는 예상 획득 속도와 목표 플레이 시간을 기준으로 별도 밸런스 표에서 관리한다.

#### 결정이 필요한 항목
- 배틀 포인트의 평균 획득 속도와 목표 구매 시간.
- 지역별 품목 차등 여부와 시즌 재고 적용 여부.
- 기술 디스크의 상시 판매/회전 판매/일회성 해금 방식.

#### 완료 기준
- 배틀타워가 병뚜껑을 포함한 후반 육성의 신뢰 가능한 획득처가 된다.
- 특정 한 품목 때문에 나머지 판매 목록이 의미 없어지지 않는다.
- 초기·중기·후기 플레이어에게 각각 최소 한 가지 유효한 구매 목표가 존재한다.

### 4.4 트레이너 AI 개선
> **목적**
> 난이도를 단순 능력치 상승이 아니라 팀 역할, 기술 선택, 교체, 아이템 사용의 질로 표현한다.
>
> **플레이어 경험**
> 플레이어는 트레이너 등급이 올라갈수록 더 계획적인 상대를 만나되, 불공정한 치팅으로 느끼지 않는다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 일반, 체육관, 관장, 지역 최종전의 최소 네 단계 AI 프로필을 정의한다.
- AI는 기술 선택, 교체 성향, 상태이상 활용, 아이템 사용, 위험 회피 기준을 단계별로 다르게 적용한다.
- 관장 팀은 대표 테마와 약점 대응 수단을 갖되, 플레이어의 모든 선택을 완벽히 읽는 방식은 피한다.
- 월드상의 NPC 이동 AI와 포켓몬 배틀 AI를 별도 문제로 관리한다.
- AI 수치와 팀 데이터는 재밸런싱이 가능하도록 외부 데이터 중심으로 구성한다.

#### 결정이 필요한 항목
- 각 난이도에서 허용할 소지품, 회복 횟수, 기믹 사용 범위.
- 레벨 스케일링을 사용할지, 고정 레벨·레벨 캡을 사용할지 결정.
- 재대결 시 강화 팀 또는 다른 AI 프로필을 사용할지 결정.

#### 완료 기준
- 동일 팀을 반복 테스트했을 때 낮은 등급과 높은 등급의 행동 차이가 일관되게 관찰된다.
- 관장 승률이 목표 범위를 벗어나면 팀과 AI를 독립적으로 조정할 수 있다.
- AI가 불가능한 정보에 의존하거나 규칙 밖의 능력치 보정을 사용하지 않는다.

### 4.5 자연 트레이너 최소화와 마을 영구 스폰
> **목적**
> 필드에 무작위 트레이너가 과도하게 나타나는 문제를 줄이고, 트레이너를 도시의 고정 콘텐츠로 전환한다.
>
> **플레이어 경험**
> 플레이어는 어디서 트레이너를 만날지 예측할 수 있고, 마을마다 고유한 주민과 전투 구성을 기억할 수 있다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 자연 트레이너 스폰율은 완전 비활성 또는 체감상 매우 낮은 수준으로 설정할 수 있어야 한다.
- 각 체육관 도시에는 일반 트레이너, 체육관 트레이너, 관장 등 지정된 NPC가 영구적으로 존재한다.
- 영구 NPC는 기준 위치와 도시 ID를 가지며, 삭제·사망·청크 오류 후 자동 또는 관리 명령으로 복구된다.
- NPC가 건물 밖으로 영구 이탈하거나 중복 생성되지 않도록 이동 범위와 생성 상태를 관리한다.
- 도시당 NPC 수와 활성 범위를 제한해 서버 성능을 보호한다.

#### 결정이 필요한 항목
- 자연 트레이너를 0으로 할지, 희귀한 여행자 형태로 일부 남길지 결정.
- 일반 마을에도 영구 트레이너를 둘지, 체육관 도시에만 둘지 결정.
- 밤/날씨에 따른 NPC 이동과 생활 연출을 첫 버전에 포함할지 결정.

#### 완료 기준
- 서버 재시작과 청크 재로딩 후에도 필요한 NPC가 한 명씩만 유지된다.
- 자연 필드에서 트레이너가 진행을 방해할 정도로 누적되지 않는다.
- NPC 삭제·사망 상황을 재현했을 때 복구 절차가 동작한다.

### 4.6 지방 클리어에 따른 포켓몬 해금
> **목적**
> 지역 완료를 단순 배지 수집에서 끝내지 않고, 다음 포켓몬 출현군을 여는 핵심 진행 보상으로 만든다.
>
> **플레이어 경험**
> 플레이어는 새로운 지방을 완료할 때 월드의 생태가 확장되는 변화를 체감한다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 포켓몬을 지방 또는 해금 그룹 단위의 데이터 목록으로 관리한다.
- 지방 완료 이벤트가 발생하면 다음 그룹을 즉시 활성화하고, 서버 재시작 없이 반영되는 것을 목표로 한다.
- 항상 출현하는 공통 포켓몬과 지역 완료 후 출현하는 포켓몬을 구분한다.
- 해금 상태는 저장·백업·복구 가능해야 하며 관리자에 의한 수동 조정 수단을 제공한다.
- 진화 계열, 교배, 거래, 기존 보유 포켓몬이 해금 규칙과 충돌하지 않도록 정책을 명시한다.

#### 결정이 필요한 항목
- 해금 범위: 서버 월드 공용, 플레이어 개인, 하이브리드 중 선택.
- “지방 클리어”를 마지막 관장, 지역 NPC 챔피언, 별도 퀘스트 중 무엇으로 판정할지 결정.
- 해금 전 포켓몬의 거래·교배·선물 수령을 허용할지 결정.
- 여러 지방을 순차 진행할지, 일부 선택형 진행을 허용할지 결정.

#### 완료 기준
- 해금 전후 스폰 목록 차이가 명확하고, 의도하지 않은 지역 포켓몬 누출이 없다.
- 완료 이벤트를 한 번만 처리하며 중복 보상이나 중복 해금이 발생하지 않는다.
- 백업 복원과 버전 이관 후에도 해금 단계가 유지된다.

> **핵심 결정:** 공용 월드의 자연 스폰은 본질적으로 모든 플레이어에게 보이므로, 플레이어별 포켓몬 해금은 구현과 운영이 복잡하다. 초기 권고안은 “포켓몬 자연 스폰은 월드 공용, 배지·상점·보상은 개인 진행”인 하이브리드 방식이다.

### 4.7 지방당 관장 수 축소
> **목적**
> 장기간 반복되는 관장 수를 줄이고, 각 전투의 테마와 보상을 강화해 지역 완주 속도를 개선한다.
>
> **플레이어 경험**
> 플레이어는 한 지방을 지루하게 소모하지 않고, 몇 번의 의미 있는 관문을 통해 다음 지역으로 이동한다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 지방당 관장 수는 기존보다 축소하며, 초기 기준안은 4명으로 둔다.
- 각 관장은 타입뿐 아니라 전술, 환경, 보상, 도시 분위기 중 최소 하나의 고유성을 가진다.
- 관장 순서는 선형, 부분 선택형, 자유형 중 명확한 규칙을 가진다.
- 지역 완료에는 관장 수 외에 최종전 또는 리그 판정을 포함할 수 있다.
- 재대결은 최초 진행을 막지 않으면서 후반 보상 루프와 연결한다.

#### 결정이 필요한 항목
- 모든 지방에 동일하게 4명을 둘지, 지방별 3~5명으로 차등할지 결정.
- 관장 선택 자유도와 레벨 스케일링 방식.
- 사천왕/지역 NPC 챔피언을 유지할지, 플레이어 챔피언으로 바로 연결할지 결정.

#### 완료 기준
- 한 지방의 평균 완주 시간이 목표 범위에 들어오고 반복 피로도가 감소한다.
- 관장 수가 줄어도 난이도 상승과 지역 서사가 급격하게 끊기지 않는다.
- 각 관장에게 고유한 팀·보상·도시 정체성이 문서화되어 있다.

### 4.8 병뚜껑 획득 방법 추가
> **목적**
> 개체값 보정 자원을 단일 희귀 드롭에 의존하지 않고, 꾸준한 전투와 지역 진행으로 얻을 수 있게 한다.
>
> **플레이어 경험**
> 플레이어는 장기적으로 원하는 포켓몬을 육성할 수 있다는 확신을 갖고 여러 콘텐츠를 선택한다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 일반 병뚜껑은 배틀타워 확정 구매를 기본 획득처로 둔다.
- 관장 또는 지역 최초 완료 보상, 고난도 트레이너, 챔피언 보상에 보조 획득처를 둔다.
- 금병뚜껑은 일반 병뚜껑보다 훨씬 제한된 획득 경로와 비용을 가진다.
- 반복 파밍 가능한 획득처에는 쿨다운, 낮은 확률, 주간 제한 중 하나 이상을 적용한다.
- 병뚜껑 공급량은 포켓몬 한 마리를 완성하는 목표 시간과 연동해 조정한다.

#### 결정이 필요한 항목
- 일반/금 병뚜껑의 정확한 아이템 ID와 효과는 착수 시 기반 모드 구성에서 확인.
- 거래 가능 여부와 서버 경제에서의 현금성 가치.
- 챔피언 일일 보상에 확정 지급할지 확률 지급할지 결정.

#### 완료 기준
- 전투 콘텐츠를 꾸준히 플레이하면 병뚜껑을 예측 가능한 속도로 획득할 수 있다.
- 병뚜껑 공급이 너무 적어 사실상 사용 불가하거나, 너무 많아 육성 가치가 사라지지 않는다.
- 부계정·반복 재대결로 제한을 우회하는 명백한 경로가 없다.

### 4.9 트레이너 보상 개편
> **목적**
> 트레이너 전투를 진행과 육성에 직접 도움이 되는 보상 루프로 만들고, 승리 목적을 명확히 한다.
>
> **플레이어 경험**
> 플레이어는 일반 트레이너, 체육관 트레이너, 관장, 챔피언마다 다른 보상을 기대할 수 있다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 보상을 최초 승리, 반복 승리, 연승/주기 보상으로 분리한다.
- 일반 트레이너는 화폐·저급 사탕·기본 소모품, 체육관 트레이너는 중급 사탕·디스크, 관장은 배지·대표 디스크·희귀 육성 자원을 중심으로 한다.
- 반복 승리 보상은 최초 보상보다 낮고, 쿨다운 또는 감소 규칙을 적용할 수 있어야 한다.
- 보상 테이블은 트레이너 개별 및 등급 그룹 단위로 관리할 수 있어야 한다.
- 인벤토리 부족, 접속 종료, 전투 중단 상황에서 보상 유실·중복이 발생하지 않게 한다.

#### 결정이 필요한 항목
- “디스크”의 범위를 기술머신, 레코드, 커스텀 기술 아이템 중 무엇으로 정의할지 확인.
- 현금 보상과 아이템 보상 비율, 반복 전투 쿨다운.
- 패배 시 비용 또는 재도전 제한을 둘지 결정.

#### 완료 기준
- 각 트레이너 등급의 보상 목적이 겹치지 않고 설명 가능하다.
- 동일 트레이너 반복 파밍이 최적의 단일 수익원이 되지 않는다.
- 보상 지급 로그로 중복 지급과 누락을 추적할 수 있다.

### 4.10 플레이어 챔피언과 일일 보상
> **목적**
> 서버에 한 명의 현역 챔피언을 두어 지역 진행 이후의 지속적인 PvP 목표와 명예 보상을 제공한다.
>
> **플레이어 경험**
> 자격을 갖춘 플레이어가 정식 도전을 신청하고, 승리하면 챔피언 지위와 보상을 이어받는다.
>
> **설계 상태:** 기능 방향 확정 / 수치·버전·구현 세부는 착수 시 확정

#### 필수 요구사항
- 서버 또는 월드마다 한 명의 현재 챔피언과 획득 시각, 마지막 보상일, 방어 기록을 저장한다.
- 도전자와 챔피언 모두 자격·팀·온라인 상태를 확인한 뒤 정식 전투를 시작한다.
- 전투 결과는 서버가 판정하고, 도전자가 승리했을 때만 챔피언 소유권을 이전한다.
- 챔피언 일일 보상은 설정된 시간대와 리셋 시각을 기준으로 하루 한 번만 지급한다.
- 최소 유지 시간, 최소 방어 조건, 획득 당일 제외 등 보상 돌려먹기 방지 규칙을 둔다.
- 장기 미접속 챔피언의 공석 처리와 관리자 강제 초기화 절차를 제공한다.
- 전투 중 로그아웃, 팀 변경, 외부 개입, 무승부를 처리하는 명시적 규칙이 있어야 한다.

#### 결정이 필요한 항목
- 챔피언 자격: 한 지방 완료, 모든 지방 완료, 별도 리그 토너먼트 중 선택.
- 온라인 실시간 도전만 지원할지, 예약·비동기 도전을 후속으로 둘지 결정.
- 일일 보상 조건: 유지 시간, 방어 승리, 활동 점수 중 무엇을 요구할지 결정.
- 챔피언이 여러 지방에 각각 존재할지, 서버 통합 한 명만 둘지 결정.
- 시즌제와 과거 챔피언 명예 기록을 첫 버전에 포함할지 결정.

#### 완료 기준
- 동시에 두 명이 챔피언으로 기록되는 경쟁 상태가 발생하지 않는다.
- 정상 승리, 패배, 로그아웃, 서버 재시작의 모든 경우에 소유권이 일관되게 유지된다.
- 같은 날짜에 보상을 두 번 받을 수 없고 시간대 변경으로 제한을 우회할 수 없다.
- 챔피언 공석과 장기 미접속 상태를 운영자가 명확히 처리할 수 있다.

> **초기 권고:** 첫 버전은 “온라인 실시간 도전 + 서버 통합 챔피언 1명 + 최소 유지 시간 충족 시 일일 보상”으로 제한한다. 시즌, 랭킹, 오프라인 AI 방어는 후속 기능으로 둔다.

## 5 진행 상태와 경제 구조
개인 진행, 월드 공용 진행, 서버 경쟁 상태를 분리해야 멀티플레이에서 예측 가능한 규칙을 만들 수 있다.

### 5.1 권고 상태 모델
| **상태 범주**     | **포함 데이터**                                                           | **소유 범위**       |
|-------------------|---------------------------------------------------------------------------|---------------------|
| **플레이어 개인** | 관장 격파, 배지, 최초 보상, 재대결 쿨다운, 상점 자격, 챔피언 도전 자격    | 플레이어별 저장     |
| **월드 공용**     | 체육관 도시 위치, 지역 포켓몬 출현군 해금, 콘텐츠 단계, 마이그레이션 버전 | 월드별 저장         |
| **서버 경쟁**     | 현재 챔피언, 획득 시각, 마지막 보상일, 방어 기록, 시즌                    | 서버/월드 단일 저장 |
| **콘텐츠 데이터** | 지역 정의, 관장 수, 트레이너 팀, 보상표, 상점 재고, 포켓몬 해금 목록      | 버전 관리 파일      |

### 5.2 포켓몬 해금 범위 선택지
| **방식**          | **설명**                                              | **장점**                                     | **주의점**                                             | **평가** |
|-------------------|-------------------------------------------------------|----------------------------------------------|--------------------------------------------------------|----------|
| **월드 공용**     | 누군가 지역을 완료하면 서버 전체의 자연 스폰이 확장됨 | 구현·운영이 가장 단순하고 월드 생태가 일관됨 | 후발 플레이어가 일부 진행을 건너뛸 수 있음             | 권고     |
| **플레이어 개인** | 개인 완료 여부에 따라 서로 다른 포켓몬을 보게 함      | 개인 진행이 엄격히 보존됨                    | 공용 월드 자연 스폰과 충돌하며 구현 복잡도가 매우 높음 | 비권고   |
| **하이브리드**    | 자연 스폰은 공용, 상점·보상·도전 자격은 개인          | 월드 일관성과 개인 성취를 동시에 유지        | 후발 플레이어용 안내·보정이 필요                       | 초기안   |

### 5.3 지역 진행 기준안
| **단계**           | **조건**                           | **결과**                                        |
|--------------------|------------------------------------|-------------------------------------------------|
| **지역 진입**      | 기본 지역 또는 선행 지역 완료      | 해당 지역 일반 포켓몬·상점 이용                 |
| **관장 1~N**       | 개인별 필수 관장 승리              | 배지, 대표 디스크, 다음 도시 정보               |
| **지역 최종전**    | 필수 관장 완료                     | 지역 완료 플래그, 최초 완료 보상                |
| **다음 지역 해금** | 지역 완료 이벤트                   | 다음 포켓몬 출현군, 상점 단계, 체육관 도시 안내 |
| **챔피언 자격**    | 설정된 지역 수 또는 전체 지역 완료 | 현재 챔피언에게 정식 도전 가능                  |

### 5.4 경제 역할 분담
| **콘텐츠**              | **경제 역할**                                | **주요 비용/조건**    |
|-------------------------|----------------------------------------------|-----------------------|
| **일반 상점**           | 생존 편의, 회복, 기본 육성, 제한된 후반 자원 | 일반 화폐             |
| **체육관 도시 상점**    | 지역별 특화 아이템, 해금형 재고              | 일반 화폐 + 진행 조건 |
| **트레이너 보상**       | 사탕, 디스크, 소모품, 화폐의 기본 공급       | 전투 승리             |
| **관장/지역 최초 보상** | 배지, 대표 기술, 병뚜껑, 대량 화폐           | 개인 1회              |
| **배틀타워**            | 병뚜껑, 고급 육성, 경쟁 아이템               | 배틀 포인트           |
| **챔피언 일일 보상**    | 명예성 보상, 제한된 고급 자원                | 유지 조건 충족        |

### 5.5 보상 밸런스 원칙
- 최초 완료 보상은 강하게, 반복 보상은 안정적이되 낮게 설정한다.
- 고급 육성 아이템에는 최소 두 개의 획득 경로를 두어 특정 콘텐츠 강제를 줄인다.
- 일반 화폐와 배틀 포인트의 역할을 분리해 채굴/거래만으로 경쟁 보상을 대체하지 못하게 한다.
- 상점 가격은 “아이템 희귀도”가 아니라 플레이어가 목표 활동을 몇 회 수행해야 하는지를 기준으로 정한다.
- 보상표에는 지급 이유, 획득 제한, 대체 획득처를 함께 기록한다.

## 6 시스템 구성과 책임 경계
향후 구현은 하나의 거대한 모드보다, 코어 로직과 데이터·설정·리소스를 분리하는 구성을 권고한다.

### 6.1 권고 구성
| **구성요소**               | **책임**                                                    | **분리 이유**                    |
|----------------------------|-------------------------------------------------------------|----------------------------------|
| **확장 코어 모드**         | 체육관 도시 배치, 영구 상태, 지역 해금, 챔피언, 관리자 복구 | 코드가 필요한 서버 권위 기능     |
| **데이터팩/콘텐츠 데이터** | 트레이너 팀, 진행 조건, 보상표, 포켓몬 해금 그룹            | 빈번한 콘텐츠 수정과 버전 비교   |
| **설정 오버레이**          | 트레이너 스폰율, 일반 상점, 배틀타워 판매 목록              | 기존 모드 설정을 의도적으로 변경 |
| **리소스팩**               | 도시 안내, NPC 외형, UI, 번역, 아이콘, 사운드               | 표현 계층                        |
| **호환성 프로필**          | 기반 팩/배포 채널/모드 버전, 설정 차이, 마이그레이션 규칙   | 업데이트 안전성                  |

### 6.2 코어 모드가 필요한 기능
- 필수 체육관 도시의 결정론적 위치 계산과 월드 저장
- 도시 마커를 기반으로 한 영구 NPC 생성·중복 방지·복구
- 지역 완료 이벤트와 월드 공용 포켓몬 출현 단계 관리
- 플레이어 챔피언 소유권의 원자적 이전과 일일 보상 검증
- 관리자 점검·복구·마이그레이션 도구

### 6.3 데이터로 유지할 기능
- 지방 목록, 관장 수, 진행 순서, 도시 콘텐츠 ID
- 트레이너 팀, 기술, 소지품, AI 프로필 참조
- 보상 테이블, 상점 품목, 가격, 해금 조건
- 포켓몬 지역 그룹과 항상 허용되는 예외 목록
- 챔피언 보상 아이템과 운영 정책의 조정 가능한 값

> **주의:** 2027년 실제 기반 팩에서 어떤 기능을 기존 모드 API로 처리할 수 있는지는 다시 검증한다. 이 장은 책임 경계를 정의할 뿐, 특정 라이브러리나 파일 형식을 확정하지 않는다.

### 6.4 개념적 데이터 구조
| **데이터**              | **핵심 필드**                                            |
|-------------------------|----------------------------------------------------------|
| **RegionDefinition**    | 지역 ID, 선행 지역, 관장 목록, 완료 조건, 다음 해금 그룹 |
| **GymTownDefinition**   | 도시 ID, 지역, 구조물, 위치 규칙, NPC 마커, 상점 프로필  |
| **TrainerDefinition**   | 트레이너 ID, 등급, 팀, AI 프로필, 최초/반복 보상         |
| **WorldProgressState**  | 생성된 도시 위치, 공용 해금 단계, 데이터 버전            |
| **PlayerProgressState** | 배지, 관장 승리, 최초 보상, 쿨다운, 챔피언 자격          |
| **ChampionState**       | 현재 챔피언, 획득 시각, 마지막 보상일, 방어 기록, 시즌   |

## 7 서버 운영과 관리 기능
월드 생성과 장기 진행 시스템은 “문제가 생기지 않는 것”보다 “문제가 생겨도 복구 가능한 것”이 중요하다.

### 7.1 필수 관리 기능
| **기능**        | **목적**                                              |
|-----------------|-------------------------------------------------------|
| **도시 조회**   | 지역/도시 ID별 좌표, 생성 상태, 구조물 버전 확인      |
| **도시 배치**   | 테스트 또는 기존 월드에 지정 도시 수동 배치           |
| **도시 복구**   | 누락 블록/마커 또는 핵심 NPC를 재검증하고 복원        |
| **NPC 재생성**  | 삭제·사망한 영구 트레이너를 도시 기준으로 다시 생성   |
| **진행 조회**   | 월드 해금 단계와 플레이어별 배지·최초 보상 상태 확인  |
| **진행 수정**   | 버그 복구를 위한 지역 완료, 배지, 쿨다운 수동 조정    |
| **챔피언 관리** | 현재 챔피언 조회, 강제 지정, 공석 처리, 보상일 초기화 |
| **데이터 감사** | 중복 도시/NPC, 중복 보상, 불가능한 진행 상태 보고     |

### 7.2 백업 및 이관 원칙
- 업데이트 전 월드, 플레이어 진행, 챔피언 상태를 함께 백업한다.
- 저장 데이터에는 스키마 버전을 두고, 새 버전이 이전 데이터를 읽을 때 명시적 마이그레이션을 수행한다.
- 도시 구조물 업데이트는 기존 플레이어 건축물을 자동 덮어쓰지 않는 것을 기본으로 한다.
- 복구 명령은 실행 전 대상과 변경 범위를 출력하고, 가능하면 미리보기 또는 확인 단계를 제공한다.
- 보상과 챔피언 이전은 운영 로그를 남겨 분쟁과 중복 지급을 추적할 수 있게 한다.

### 7.3 서버 성능 기준
- 체육관 도시의 강제 청크 로딩을 기본값으로 사용하지 않는다.
- 영구 NPC는 플레이어 주변에서만 활성화하고, 도시당 수량 상한을 둔다.
- 지역 해금 판정과 챔피언 보상 검사는 매 틱이 아니라 이벤트 또는 낮은 빈도로 처리한다.
- 월드 생성 탐색이 장시간 블로킹되지 않도록 후보지 계산과 배치를 분리한다.
- 성능 문제를 재현할 수 있도록 도시 수, NPC 수, 활성 플레이어 수를 포함한 테스트 시나리오를 기록한다.

## 8 2027년 개발 로드맵
아래 일정은 착수 순서를 위한 기준안이며, 실제 시작일과 기반 팩 상황에 따라 조정한다.

### 8.1 단계별 계획
| **단계**             | **예정**          | **주요 범위**                                                          | **종료 조건**                          |
|----------------------|-------------------|------------------------------------------------------------------------|----------------------------------------|
| **준비 단계**        | 2026년 하반기     | 기획 확정, 지방/관장/경제 콘텐츠 목록, 배포·라이선스 검토              | 핵심 결정 D-01~D-06 승인               |
| **0단계: 기술 조사** | 2027년 1분기      | 기반 팩 버전 고정, API·설정 감사, 월드 생성·전투 이벤트·상점 연동 실험 | 핵심 기술 위험 해소 또는 대체안 확정   |
| **1단계: 수직 구간** | 2027년 2분기      | 체육관 도시 1개, 영구 트레이너, 관장 1명, 보상, 기본 복구              | 한 도시의 탐색-전투-보상 흐름 완주     |
| **2단계: 첫 지방**   | 2027년 2~3분기    | 관장 수 축소형 첫 지방, 지역 완료, 다음 포켓몬 그룹 해금               | 첫 지방을 새 월드와 서버에서 반복 완주 |
| **3단계: 경제·AI**   | 2027년 3분기      | 상점, 배틀타워, 병뚜껑, 트레이너 보상, AI 프로필                       | 경제 시뮬레이션과 난이도 목표 통과     |
| **4단계: 챔피언**    | 2027년 3~4분기    | 정식 PvP 도전, 소유권 이전, 일일 보상, 공석 처리                       | 악용·재시작·동시 도전 시나리오 통과    |
| **5단계: 확장·베타** | 2027년 4분기 이후 | 추가 지방, 도시 콘텐츠, 번역·UI, 장기 서버 테스트                      | 릴리스 품질 게이트 통과                |

### 8.2 수직 구간의 최소 범위
- 한 지방, 체육관 도시 1개 이상, 관장 1명과 일반 트레이너 그룹
- 도시의 결정론적 배치, 재접속 후 유지, 누락 NPC 복구
- 관장 최초 승리와 반복 승리 보상 분리
- 간단한 상점과 병뚜껑 또는 사탕 한 가지 획득 경로
- 지역 완료 이벤트의 시험용 다음 포켓몬 그룹 해금
- 관리자 조회·복구 기능과 저장 데이터 버전

> **개발 순서:** 챔피언과 여러 지방을 먼저 만들지 않는다. 한 도시와 한 지방에서 월드 생성, NPC, 전투, 보상, 저장, 복구가 모두 닫힌 뒤 콘텐츠를 확장한다.

### 8.3 우선순위
| **구분**         | **범위**                                                                                              |
|------------------|-------------------------------------------------------------------------------------------------------|
| **Must**         | 체육관 도시, 영구 트레이너, 관장 축소, 지역 완료, 포켓몬 해금, 기본 보상, 챔피언 핵심 흐름, 복구 기능 |
| **Should**       | 일반 상점 단계화, 배틀타워 정리, 병뚜껑 다중 획득처, AI 프로필 세분화, 기존 월드 수동 배치            |
| **Could**        | 시즌제, 과거 챔피언 기록, 회전 상점, 지도 연출, NPC 생활 패턴, 랭킹 UI                                |
| **Won't for v1** | 오프라인 AI 챔피언, 서버 간 동기화, 플레이어별 자연 스폰 분리, 범용 자동 월드 변환                    |

## 9 검증 및 출시 기준
기능이 보이는 것뿐 아니라 재시작, 업데이트, 동시 접속, 악용 시나리오에서 상태가 일관되는지 검증한다.

### 9.1 테스트 영역
| **영역**        | **핵심 시나리오**                                                  |
|-----------------|--------------------------------------------------------------------|
| **월드 생성**   | 여러 시드·바이옴·지형에서 도시 누락, 겹침, 분리, 접근 불가 여부    |
| **NPC 영속성**  | 청크 언로드, 서버 재시작, 사망, 삭제, 중복 생성, 이동 이탈         |
| **진행**        | 관장 순서, 중복 완료, 후발 플레이어, 관리자 수정, 백업 복원        |
| **포켓몬 해금** | 해금 전 누출, 해금 즉시성, 진화/거래/교배 예외, 버전 이관          |
| **전투 AI**     | 난이도별 행동 차이, 교체·아이템·기믹 사용, 불공정 행동 여부        |
| **경제**        | 시간당 화폐·BP·사탕·병뚜껑 공급량, 최적 파밍 편중, 상점 인플레이션 |
| **챔피언**      | 동시 도전, 로그아웃, 무승부, 서버 종료, 보상 리셋, 부계정 악용     |
| **성능**        | 도시 수, NPC 수, 접속자 수 증가에 따른 틱 지연과 메모리 사용       |

|---------------|------------------------------------------------------------------------------|

| **기술 검증** | 필수 이벤트·저장·월드 생성·상점 연동의 실현 가능성이 확인됨                  |
| **수직 구간** | 한 도시와 한 관장의 전체 흐름이 새 월드와 전용 서버에서 반복 동작함          |

- 지역·관장·포켓몬 해금·상점·보상 데이터 변경 기록
- 서버 백업과 업데이트 롤백 절차
- 알려진 충돌, 비지원 기능, 데이터 손상 가능성이 있는 작업 목록

## 10 리스크 관리

| **리스크**            | **영향** | **설명**                                              | **완화 방향**                                              |

| **기반 팩 업데이트**  | 상       | 모드/API/설정 구조가 변경되어 설계가 무효화될 수 있음 | 착수 시 버전 고정, 호환성 프로필, 업데이트 브랜치 분리     |

| **D-09** | 챔피언 자격과 도전 방식은?                     | 지정 지역 완료 + 온라인 정식 도전          | 챔피언 설계 전          | 미정     |
| **D-10** | 챔피언 일일 보상 조건은?                       | 최소 유지 시간 + 하루 1회 + 획득 당일 제외 | 경제표 작성 전          | 미정     |
| **D-11** | 장기 미접속 챔피언은?                          | 설정 기간 후 공석 처리                     | 운영 정책 확정          | 미정     |
| **D-12** | 원본 팩과 에셋의 배포 방식은?                  | 공식 팩 위에 설치하는 확장형 배포          | 공개 개발 전            | 미정     |

### 11.1 우선 결정 순서
1.  D-02 첫 버전의 지방 수와 D-03 관장 수를 먼저 정한다.
2.  D-06 포켓몬 해금 범위를 확정해 개인/월드 저장 구조를 결정한다.
3.  D-04 도시 배치 방식과 D-05 기존 월드 지원 범위를 함께 결정한다.
4.  D-09~D-11 챔피언 정책을 정한 뒤 보상 경제를 설계한다.
5.  D-01과 D-12는 실제 착수 시점의 기반 팩과 배포 조건을 조사해 최종 확정한다.

### 12.2 기획 체크리스트
- [ ] 첫 버전에 포함할 지방과 관장 수를 정했다.
- [ ] 체육관 도시의 위치 규칙과 기존 월드 지원 수준을 정했다.
- [ ] 포켓몬 해금의 공용/개인 범위를 정했다.
- [ ] 각 관장의 전술 테마와 대표 보상을 한 줄로 설명할 수 있다.
- [ ] 네더라이트, 병뚜껑, 사탕, 디스크의 획득처와 소비처를 표로 만들었다.
- [ ] 배틀타워가 일반 상점과 다른 역할을 가진다.
- [ ] 챔피언 도전과 일일 보상의 악용 방지 규칙을 정했다.
- [ ] 새 월드 우선 여부와 기존 월드 복구 정책을 정했다.
- [ ] 공개 배포 시 원본 팩과 에셋을 재배포하지 않는 구조를 검토했다.
- [ ] 첫 수직 구간의 종료 조건을 팀이 합의했다.

### 12.3 최초 상세 설계 문서의 권장 분리
- 월드 생성 설계서: 도시 배치 규칙, 구조물 경계, 마커, 복구 절차
- 진행 설계서: 지역/관장/배지/해금 상태와 이벤트 흐름
- 전투 콘텐츠 설계서: 트레이너 팀, AI 계층, 재대결
- 경제 설계서: 상점, 배틀타워, 보상, 병뚜껑 공급/소비 시뮬레이션
- 챔피언 시스템 설계서: 자격, 도전 상태기계, 일일 보상, 운영 정책
- 호환성 및 배포 설계서: 기반 팩 버전, 설치, 업데이트, 마이그레이션, 라이선스

> **현재의 최종 목표:** 다음 단계는 코드를 작성하는 것이 아니라, D-02·D-03·D-06·D-09·D-10을 결정하고 “첫 지방 하나”의 지역 정의표, 관장표, 상점표, 보상표를 만드는 것이다.

## 부록 B 용어 정리
기획 과정에서 같은 개념을 일관되게 사용하기 위한 용어 기준이다.

| **용어**             | **정의**                                                                                           |
|----------------------|----------------------------------------------------------------------------------------------------|
| **체육관 도시**      | 체육관, 마을 건물, 상점, 영구 NPC가 하나의 고유 ID와 경계로 묶인 진행 거점.                        |
| **지방**             | 관장 목록, 완료 조건, 포켓몬 해금 그룹, 상점 단계를 공유하는 진행 단위.                            |
| **지역 완료**        | 해당 지방의 필수 관장과 최종 조건을 충족해 완료 이벤트가 발생한 상태.                              |
| **포켓몬 해금 그룹** | 특정 지역 완료 전후로 자연 출현 허용 여부가 함께 바뀌는 포켓몬 목록.                               |
| **영구 트레이너**    | 도시 ID와 기준 위치에 귀속되어 삭제·사망 후에도 복구 가능한 NPC.                                   |
| **최초 보상**        | 플레이어가 특정 트레이너 또는 지역을 처음 완료했을 때 한 번만 받는 보상.                           |
| **반복 보상**        | 재대결 또는 반복 콘텐츠에서 제한 규칙 아래 여러 번 받을 수 있는 보상.                              |
| **플레이어 챔피언**  | 서버가 인정한 공식 PvP에서 승리해 현재 챔피언 상태를 보유한 플레이어.                              |
| **호환성 프로필**    | 기반 팩, 배포 채널, 버전, 핵심 의존 모드, 설정 차이와 마이그레이션 규칙을 묶은 정보.               |
| **수직 구간**        | 한 지역의 탐색부터 관장 승리, 보상, 해금, 저장, 복구까지 전체 흐름을 최소 규모로 완성한 구현 단위. |
