# 던전 및 지하 차원

> 관련 요구사항: F-01, F-06, F-07
>
> 관련 결정: 세대별 일반 월드와 리그 전환 차원을 유지하면서 이름 있는 던전은 지하 차원으로 분리
>
> 아키텍처 적용: 3안 보호형 하이브리드. 이름 있는 특수 던전이 자연 동굴 탐험과 제한 채광을 대체한다.
>
> 설계 상태: 기술 조사 진행 / 첫 수직 구간 던전 미선정

## 1 목적

달맞이산처럼 본가에 등장하는 이름 있는 동굴과 던전을 일반 월드의 우연한 자연 동굴에 의존하지 않고 재현한다. 입구를 통과하면 네더 또는 Don't Starve의 동굴처럼 넓고 지속적인 지하 세계가 펼쳐지고, 그 안에 필수 경로와 고정 랜드마크를 배치한다.

## 2 던전의 역할

리그 전환 차원과 던전 차원은 역할을 분리한다.

| 구분 | 목적 | 완료 결과 |
|------|------|-----------|
| 세대 월드 | 마을, 도로, 체육관과 일반 탐험 | 배지와 지역 진행 |
| 던전·지하 차원 | 탐험, 희귀 포켓몬, 퍼즐, 재생 광물과 지름길 | 지역 해금, 재료와 선택 보상 |
| 리그 전환 차원 | 챔피언로드, 사천왕과 챔피언 | 다음 세대 월드 해금 |

던전은 대부분 반복 방문할 수 있게 하고, 챔피언 격파처럼 세대 전체를 완료시키는 기능은 리그에 남겨둔다.

## 3 권고 차원 구조

던전마다 차원을 하나씩 만들면 관리 대상이 지나치게 늘어난다. 같은 하늘, 조명, 시간과 지형 규칙을 사용하는 던전은 하나의 공유 `dungeons` 차원 안에 좌표 구역으로 나눈다.

```text
dungeons
├─ generation_1 / mt_moon
├─ generation_1 / rock_tunnel
├─ generation_1 / cerulean_cave
├─ generation_2 / union_cave
└─ generation_N / dungeon_id
```

각 구역 사이에는 충분한 비어 있는 거리, 기반암 경계 또는 생성 금지 영역을 둔다. 플레이어가 채굴만으로 다른 던전이나 세대 구역에 도달하지 못하게 보호한다.

다음 조건이 필요한 던전만 별도 차원으로 승격한다.

- 완전히 다른 시간, 조명, 하늘과 안개
- 특수 중력, 산소, 온도 또는 지속 피해 규칙
- 공유 차원과 호환되지 않는 독자적 지형 생성기
- 월드 전체를 초기화하거나 인스턴스로 운영해야 하는 콘텐츠

## 4 지하 세계 구성

던전 구역은 자연 생성 지형과 수작업 구조물을 혼합한다.

```text
지하형 노이즈 지형
  → 큰 공동·좁은 통로·지하 호수 생성
  → 고정 입구와 출구 배치
  → 직소 구조물로 퍼즐방·야영지·유적 배치
  → 필수 랜드마크와 보스방을 고정 앵커에 배치
  → 지정 자원 방의 고정 앵커에 재생 광물 노드 배치
  → 포켓몬 스폰과 보상 프로필 적용
```

네더와 비슷한 천장형 지형을 시작점으로 삼을 수 있지만 블록, 용암, 표면 규칙과 바이옴은 프로젝트용으로 교체한다. 단순히 네더 설정을 그대로 복사하면 네더 지형과 자원이 따라오므로 정식 구현에는 별도의 노이즈 설정과 표면 규칙이 필요하다.

필수 진행 경로는 노이즈 생성 결과에 맡기지 않는다. 입구, 주요 갈림길, 필수 구조물과 출구를 고정 앵커로 연결하고 주변 자연 지형만 무작위로 변주한다.

## 5 달맞이산형 첫 던전 예시

```text
1세대 월드 서쪽 입구
  → dungeons: mt_moon_west
  → 넓은 자연 공동과 갈림길
  → 운석 연구 구역
  → 삐·삐삐 계열 희귀 구역
  → 화석 선택 이벤트
  → mt_moon_east
  → 1세대 월드 동쪽 출구
```

입구와 출구를 서로 다른 지상 좌표에 연결하면 던전이 실제 도로를 가로지르는 통과형 지역으로 기능한다. 내부에 선택형 샛길과 반복 탐험 구역을 추가해 일회성 통로가 되지 않게 한다.

달맞이산 구역의 예시 구성은 다음과 같다.

| 요소 | 구현 방식 |
|------|-----------|
| 서쪽·동쪽 출입구 | 고정 구조물과 목적지 앵커 |
| 주요 통로 | 항상 연결되는 고정 직소 풀 |
| 갈림길·막다른 방 | 가중치 기반 선택 직소 풀 |
| 운석·화석 구역 | 고정 랜드마크 구조물 |
| 희귀 포켓몬 구역 | 구조물·좌표·주변 블록 스폰 조건 |
| 로켓단·트레이너 | 영구 NPC 마커와 플레이어별 승리 상태 |
| 회복·귀환 지점 | 체크포인트와 탈출 오브젝트 |
| 광물 자원 방 | 고정 노드를 채굴할 때 같은 자리의 다음 광물을 가중치로 재추첨 |

### 5.1 자연 동굴 대체와 채굴 범위

세대 월드의 일반 자연 동굴은 주요 채굴 콘텐츠로 사용하지 않는다. 달맞이산, 암석터널과 같은 이름 있는 특수 던전이 자연 동굴의 탐험·포켓몬 포획·광물 채굴 역할을 대신한다.

- 던전의 일반 돌, 벽과 필수 구조물은 보호한다.
- `resource_node`로 등록된 광물 블록만 채굴할 수 있다.
- 광물 노드의 좌표는 설계된 자원 방과 벽면 앵커에 고정한다.
- 채굴하면 현재 보상을 지급한 뒤 같은 자리의 다음 광물 종류를 가중치로 재추첨한다.
- 짧은 고갈 상태, 플레이어별 보상 쿨다운과 시간당 상한으로 무한 자원 경제를 방지한다.
- 세부 권한·드롭·재생 정책은 [보호형 서바이벌 필드와 재생 자원](PROTECTED_SURVIVAL_RESOURCES.md)을 따른다.

## 6 입구와 출구 연결

던전 출입구는 단순한 임의 워프가 아니라 명시적인 연결 쌍으로 관리한다.

| 필드 | 설명 |
|------|------|
| `entrance_id` | 중복되지 않는 입구 ID |
| `source_dimension` | 세대 월드 차원 ID |
| `source_anchor` | 지상 입구 좌표 |
| `dungeon_id` | 연결된 던전 구역 |
| `destination_anchor` | 지하 도착 좌표 |
| `return_anchor` | 지상 귀환 좌표 |
| `required_progress` | 입장에 필요한 개인 진행 상태 |
| `fallback_anchor` | 막힘·오류 시 사용할 안전 좌표 |

서쪽 입구로 들어온 플레이어는 서쪽 지하 앵커에, 동쪽 입구로 들어온 플레이어는 동쪽 지하 앵커에 도착한다. 탈출 로프나 귀환 아이템은 마지막으로 사용한 입구 또는 체크포인트를 기준으로 처리한다.

## 7 포켓몬 스폰

던전 스폰은 [포켓몬 스폰 프로필](POKEMON_SPAWNS.md)의 세대 중심 혼합 정책을 따른다.

```text
소속 세대의 기본 혼합 프로필
  + dungeon_id
  + 지형·구조물·좌표 구역
  + 광량·높이·주변 블록
  + 던전 고유 희귀도 배율
  = 실제 던전 스폰 풀
```

공유 `dungeons` 차원만 조건으로 사용하면 모든 동굴의 포켓몬이 섞인다. 반드시 좌표 경계, 구조물 또는 던전 전용 바이옴 조건을 함께 사용한다.

## 8 멀티플레이와 영속성

- 구조물과 자연 지형은 서버 전체가 공유한다.
- 퍼즐, 아이템 선택, 트레이너 승리와 체크포인트는 플레이어별로 저장한다.
- 한 플레이어가 연 문이나 제거한 장애물이 다른 플레이어의 필수 진행을 우회시키지 않게 한다.
- 일반 지형과 필수 구조물은 보호하고 등록된 재생 광물 노드만 채굴을 허용한다.
- 상자와 희귀 보상이 월드 공용인지 플레이어별인지 명시한다.
- 서버 재시작 후에도 입구 연결, 체크포인트와 완료 상태를 복구한다.

## 9 첫 프로토타입

1. `dungeons` 시험 차원을 등록한다.
2. 지하 천장과 석재 기반의 작은 자연 생성 구역을 만든다.
3. 세대 월드에 서쪽·동쪽 입구 두 개를 배치한다.
4. 두 입구를 던전의 서로 다른 앵커와 연결한다.
5. 항상 연결되는 통로와 고정 랜드마크 하나를 배치한다.
6. 일반 동굴 포켓몬 3종과 희귀 구역 포켓몬 1종을 설정한다.
7. 체크포인트, 사망, 탈출과 재접속을 검증한다.
8. 다른 던전 구역으로 채굴 우회가 불가능한지 검증한다.
9. 고정 앵커 세 곳에 광물 노드를 배치하고 채굴 후 가중치 재추첨·고갈 지연·동시 접근을 검증한다.

## 10 외부 모드 후보 조사

조사 기준은 Minecraft 1.21.1, Fabric 지원 여부, 지하 차원 생성 기능, 설정 가능성, 소스와 라이선스다.

| 후보 | 용도 | 1.21.1 Fabric | 라이선스 | 평가 |
|------|------|---------------|----------|------|
| YUNG's Better Caves | 대형 공동, 지하 호수·강, 용암 공동 등 동굴 형태 생성 | 지원 | LGPL-3.0 | 차원별 설정을 지원해 정식 생성 기반의 1순위 후보 |
| Deep Underground | 256블록 높이의 완성형 지하 차원과 3개 동굴 바이옴 | 지원 | MIT | 빠른 체험·프로토타입과 구현 참고에 적합 |
| Mining Dimensions | Caving 차원, 포털 블록과 좌표 지정 텔레포트 패드 | 지원 | MIT | 이동과 완성형 차원 참고용, 자원 채집 중심 콘텐츠는 프로젝트와 분리 필요 |

| CustomDimensions | 명령 기반 일반·네더·엔드·동굴 차원 생성 | 지원 | CC-BY-NC-4.0 | 관리자 실험에는 편리하지만 초기 프로젝트와 비상업 라이선스 제약을 추가 검토해야 함 |

### 10.1 권고 조합

정식 구현의 우선 검증 조합은 다음과 같다.

```text
프로젝트 데이터팩
  └─ 정적 dungeons 차원과 차원 타입 정의

YUNG's Better Caves
  └─ dungeons 차원의 대형 공동·강·호수·통로 형태 생성

프로젝트 월드 생성 데이터
  ├─ 지하 바이옴·표면 블록·광물 규칙
  ├─ 달맞이산 등 고정 구조물
  └─ 구조물 보호 경계

프로젝트 코어 모드
  ├─ 지상 입구와 지하 앵커 연결
  ├─ 개인 진행·체크포인트·귀환
  └─ Cobblemon 스폰 프로필 적용
```

YUNG's Better Caves는 차원 자체를 프로젝트 대신 설계하는 것이 아니라 동굴의 형태를 풍부하게 만드는 생성 계층으로 사용한다. 던전의 정체성, 진행선, 포켓몬과 보상은 프로젝트가 소유한다.

### 10.2 빠른 비교 프로토타입

두 개의 시험 월드를 만들어 같은 달맞이산 구조물을 비교한다.

1. 프로젝트 정적 차원 + YUNG's Better Caves
2. Deep Underground 차원 + 외부 데이터팩 구조물·Cobblemon 스폰

다음 항목을 동일한 조건에서 비교한다.

- 입구에서 보이는 첫 인상과 지하 세계의 규모감
- 길 찾기 가능성과 필수 구조물 연결 안정성
- 광물·기존 몹·포털·장비 등 원하지 않는 콘텐츠 제거 난도
- 구조물, 바이옴과 포켓몬 스폰 설정 가능 범위
- 청크 생성 시간, 메모리와 서버 틱 영향
- 모드 업데이트와 라이선스·재배포 부담

Deep Underground는 외부 데이터팩으로 구조물을 추가할 수 있고 MIT 소스가 공개되어 있어 비교 대상으로 적합하다. 그러나 프로젝트에 필요하지 않은 광물, 장비, 포털과 생성 규칙까지 포함하므로 결과에 따라 의존성 사용, 포크 또는 구현 참고 중 하나를 선택한다.

DimLib은 런타임에 차원을 생성·삭제해야 할 때 유용하지만 현재 설계는 고정된 공유 던전 차원을 사용하므로 초기 의존성에 넣지 않는다.

## 11 미결정 사항

- 첫 수직 구간 던전을 달맞이산형으로 확정할 것인가?
- 공유 던전 차원의 구역 간격과 보호 경계를 얼마로 할 것인가?
- 던전별 고정 노드 수, 광물 풀 가중치, 도구 조건과 재추첨 지연은 얼마인가?
- 지상과 지하 좌표를 비율로 대응시킬지 고정 앵커만 사용할 것인가?

- 후보 모드 조합이 선택한 Cobblemon 호환 프로필의 월드 생성·성능 모드와 충돌하지 않는가?
