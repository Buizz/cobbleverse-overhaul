# 키우미집 NPC 위탁 교배와 개인 농장 자가 교배

> 관련 시스템: Cobbreeding 2.2.2 (NeoForge), CobbleDollars, NPC 이벤트 런타임, 개인 농장
>
> 설계 상태: 기준 설계
>
> 핵심 방향: 초중반에는 NPC에게 유료로 위탁하고, 후반에는 개인 농장에서
> 브리더 도구를 제작해 직접 교배할 수 있다.

## 1. 목표

키우미집을 단순 장식 건물이 아니라 포켓몬 교배의 첫 진입점으로 사용한다.
플레이어는 키우미 NPC에게 부모 포켓몬 두 마리를 맡기고 비용을 지불한 뒤, 시간이
지나면 같은 NPC에게 돌아와 알과 부모 포켓몬을 찾아간다.

이후 개인 농장이 충분히 성장하면 브리더 도구를 제작해 직접 교배할 수 있다. 직접
교배는 서비스 비용이 없지만 제작 비용, 농장 공간과 현장 관리가 필요하다. 따라서
자가 교배를 해금한 뒤에도 NPC 키우미집은 편의 서비스로 남는다.

```text
초중반
키우미 NPC → 부모 2마리 선택 → 3,000원 지불 → 오프라인 진행 → NPC에게 알 수령

후반
개인 농장 → 브리더 도구 제작·설치 → 부모 직접 배치 → 현장 진행 → 도구에서 알 수령
```

## 2. 확정 원칙

### 2.0 런타임 버전을 고정한다

개발팩은 Minecraft `1.21.1`, NeoForge `21.1.248`, Cobblemon `1.7.3` 조합에 맞는
Cobbreeding `2.2.2` NeoForge 배포 파일을 사용한다. Modrinth 프로젝트 ID는
`ItmVb4zY`, 파일 버전 ID는 `9bPk2DC3`으로 고정한다. 같은 `2.2.2` 표기의 Fabric
파일을 대신 넣지 않는다.

Cobbreeding이 요구하는 Kotlin for Forge 5+, Architectury API 13+와 Cloth Config
15+는 기존 개발팩 고정 의존성을 그대로 공유한다. 클라이언트와 서버 양쪽에 같은
Cobbreeding 파일을 설치한다.

### 2.1 같은 교배 규칙을 사용한다

NPC 서비스와 농장 도구가 서로 다른 알 생성 규칙을 가지면 개체값, 성격, 특성,
유전기와 이로치 판정에서 플레이 방식에 따른 유불리가 생긴다. 두 경로 모두
Cobbreeding의 다음 규칙과 알 아이템 형식을 사용한다.

- 교배 가능 조합과 알 그룹 판정
- 태어날 종과 폼 판정
- 개체값, 성격, 특성, 유전기, 볼과 허용된 종족 특징의 유전
- 빨간실, 변함없는돌과 파워 계열 지닌 도구 효과
- 부모의 오리지널 트레이너에 따른 국제 교배 판정
- Cobbreeding 알 아이템과 암호화된 알 데이터
- 프로젝트에서 확정한 Cobbreeding 전역 설정

NPC 위탁 전용으로 더 좋은 확률을 주거나 유전 결과를 다시 굴리지 않는다. 서비스
비용은 편의와 오프라인 처리의 가격이지 더 좋은 알을 구매하는 비용이 아니다.

### 2.2 NPC는 실제 목장 블록을 숨겨서 사용하지 않는다

숨겨진 차원에 플레이어별 목장 블록을 만들고 청크를 계속 틱시키는 방식은 소유권,
청크 로딩, 백업과 장애 복구를 어렵게 한다. NPC 위탁은 별도의 영속 작업으로
관리하되, 알 생성 순간에는 Cobbreeding 호환 어댑터를 통해 동일한 교배 엔진을
호출한다.

```text
DaycareService
  ├─ 부모 보관·예약
  ├─ 가격·시간·슬롯 정책
  ├─ 영속 작업과 수령 트랜잭션
  └─ BreedingEngine 포트
       └─ CobbreedingAdapter
            ├─ 호환 조합 조회
            └─ Cobbreeding 알 생성·직렬화
```

Cobbreeding 내부 클래스가 버전 변경으로 달라질 수 있으므로 NPC, UI와 저장 코드는
모드 클래스에 직접 의존하지 않는다. `CobbreedingAdapter` 하나만 직접 연동하고,
지원 버전이 아니면 키우미 서비스를 비활성화하면서 원인을 로그에 남긴다. 이미 맡긴
포켓몬의 반환 기능은 어댑터 로드 실패와 관계없이 항상 동작해야 한다.

### 2.3 NPC 작업은 한 번에 알 하나만 만든다

Cobbreeding 목장은 인벤토리가 찰 때까지 여러 알을 만들 수 있지만, NPC에게 한 번
맡긴 뒤 장기간 접속하지 않아 알을 쌓는 방식은 경제 비용과 슬롯 제한을 무력화한다.
NPC 위탁 한 건은 알 하나가 완성되면 즉시 멈춘다. 다음 알을 원하면 알과 부모를
찾은 뒤 새 위탁을 접수한다.

### 2.4 돈은 접수 시 전액 받는다

기준 가격은 위탁 한 건당 `3,000원`이다. 현재 경제에서 몬스터볼 15개 정도의 가격에
해당해 초반에는 선택이 필요하지만 교배를 막을 정도로 비싸지는 않은 시작값이다.

- 호환 가능 여부와 보관 공간을 먼저 검사한다.
- 최종 확인 시 포켓몬 이동과 CobbleDollars 차감을 하나의 서버 트랜잭션으로 처리한다.
- 잔액 부족, 포켓몬 상태 변경 또는 저장 실패 시 돈과 포켓몬 모두 원래 상태를 유지한다.
- 정상 접수 후 플레이어가 취소하면 부모는 돌려주지만 위탁료는 환불하지 않는다.
- 서버 오류나 호환성 오류로 알을 만들 수 없으면 전액 환불하고 부모를 돌려준다.
- 알을 찾을 때 추가 요금이나 날짜별 보관료를 받지 않는다.

수령 시 돈이 부족해 부모나 알을 되찾지 못하는 상황을 만들지 않기 위해 후불제와
일일 보관료는 사용하지 않는다.

가격은 콘텐츠 설정값 `daycare.service_fee`로 두며 초기 밸런스 테스트 범위는
`2,000~5,000원`으로 잡는다. 포켓몬 종, 레벨, 개체값이나 이로치 여부로 가격을
차등하지 않는다.

## 3. NPC 이용 흐름

### 3.1 첫 대화

키우미 NPC의 메뉴는 다음 네 항목을 상태에 맞춰 표시한다.

1. `포켓몬 맡기기`
2. `맡긴 포켓몬 확인`
3. `알과 포켓몬 찾기` 또는 `포켓몬 되찾기`
4. `교배 설명 듣기`

진행 중인 위탁이 없으면 맡기기를 강조하고, 알이 준비되면 첫 선택지를
`알이 준비됐어요!`로 바꾼다. NPC 머리 위나 지도 시설 정보에도 준비 표시를 보여줄
수 있지만 월드에 떨어진 알 엔티티는 만들지 않는다.

### 3.2 접수 화면

```text
[부모 A 선택] + [부모 B 선택]
          ↓
호환 가능 여부와 예상 결과 종 표시
          ↓
위탁료 3,000원 / 예상 시간 7~12분
          ↓
[3,000원을 내고 맡긴다]
```

- 파티와 PC에서 포켓몬을 고를 수 있다.
- 기절, 체력과 레벨은 접수 가능 여부에 영향을 주지 않는다.
- 교배 불가, 동일 개체 중복 선택, 다른 시스템 사용 중, 거래 잠금 상태는 거부한다.
- 지닌 도구와 오리지널 트레이너 정보가 유전에 사용됨을 화면에 표시한다.
- 예상 결과에는 가능한 종만 보여주며 개체값, 성격, 특성, 이로치 여부는 미리
  공개하지 않는다.
- 알 데이터 암호화가 켜져 있으면 준비 후에도 수령 전 결과를 노출하지 않는다.

### 3.3 진행 시간

Cobbreeding 2.2.2의 기본 교배 간격인 `8,000~14,000틱`, 즉 정상 20 TPS 기준
약 6분 40초~11분 40초를 기준값으로 사용한다. 접수 시 이 범위에서 완료 시각을 한
번 정하고 저장한다.

NPC 서비스 시간은 서버의 단조로운 경과 시간 정책으로 계산하므로 플레이어가
로그아웃하거나 키우미집 청크가 언로드되어도 흐른다. 서버가 꺼져 있던 실제 시간까지
인정할지는 전체 오프라인 성장 정책과 같은 설정을 사용하되, 기본안은 최대 24시간의
경과만 인정한다.

완료 시각에 도달했다고 접속하지 않은 모든 작업을 즉시 순회하지 않는다. 플레이어
로그인, 키우미 NPC 상호작용 또는 제한된 주기 작업에서 상태를 지연 갱신한다.

### 3.4 알 생성 과정

키우미집 전용 알이나 완성된 포켓몬을 새로 구현하지 않는다. Cobbreeding 2.2.2가
실제 목장에서 사용하는 공개 정적 생성 경로를 호환 어댑터 안에서 호출한다.

```text
보관 중인 부모 Pokemon 2마리
  → BreedingUtilities.getPossibleEggs(parents)
  → 교배 가능 조합 재검사
  → BreedingUtilities.chooseEgg(parents)
  → 유전 결과가 확정된 PokemonProperties
  → EggUtilities.getEggFromPokemonProperties(properties, null)
  → Cobbreeding PokemonEgg ItemStack
  → daycare 작업의 egg_stack에 전체 직렬화 저장
```

`chooseEgg` 단계에서 태어날 종과 폼, 개체값, 성격, 특성, 유전기, 볼, 이로치와
허용된 특징이 한 번만 확정된다. `getEggFromPokemonProperties`의 두 번째 인수에는
`null`을 전달해 종의 `eggCycles × 600 × eggHatchMultiplier`로 계산되는 Cobbreeding
기본 부화 시간을 사용한다. 생성된 알 아이템은 다음 데이터 컴포넌트를 사용한다.

- `POKEMON_PROPERTIES`: 암호화를 끈 경우에만 기록하는 평문 포켓몬 정보
- `TIMER`: 종에 따른 남은 부화 시간
- `SECOND`: 초 단위 표시와 틱 처리용 보조 값
- `EGG_INFO`: 암호화된 실제 알 정보
- `VERSION`: 알 데이터 호환 버전
- `NAME`: 알 표시 이름

위탁 완료 시간과 알 부화 시간은 서로 다른 값이다. `ready_at`까지는 키우미집이 알을
만드는 시간이고, 수령한 뒤에는 Cobbreeding의 `PokemonEgg`가 플레이어 인벤토리에서
자체 부화 타이머를 처리한다. 불꽃몸처럼 Cobbreeding이 지원하는 부화 촉진 효과도
이 단계에서 기존 모드 규칙 그대로 적용된다.

알은 접수 순간 미리 만들지 않고 `ready_at`이 지난 작업을 처음 갱신할 때 만든다.
단, 생성 직후 플레이어에게 바로 주지 않고 완성된 `ItemStack` 전체를
`egg_stack`에 먼저 저장하고 `generation_committed = true`를 확정한다. 따라서
플레이어가 재접속하거나 수령 버튼을 반복해서 눌러도 유전 결과가 다시 추첨되지
않는다.

```text
READY 진입
  1. job_id와 generation_committed 검사
  2. 부모 데이터로 알 결과를 한 번 생성
  3. egg_stack 영속 저장
  4. generation_committed 확정
  5. 이후 수령 요청은 저장된 같은 egg_stack만 전달
```

생성 도중 서버가 종료되더라도 `generation_committed`와 `egg_stack`을 함께 저장하는
원자적 커밋으로 빈 알이나 두 개의 알이 생기지 않게 한다. Cobbreeding 호출이
예외를 내거나 지원하지 않는 데이터가 발견되면 작업을 `FAILED`로 바꾸고 부모와
위탁료를 복구한다. 운영자 명령이나 `/give`로 알을 대신 만들어 정상 처리된 것처럼
넘기지는 않는다.

### 3.5 건물 밖 목장 연출

위탁이 진행 중이거나 알이 준비된 동안, 키우미집 밖 울타리 목장에 플레이어가 맡긴
부모 포켓몬 두 마리가 돌아다니는 모습을 보여준다. 이 개체는 작업 저장소에 보관된
포켓몬 원본이 아니라 외형 데이터에서 만든 `DaycarePokemonProjection` 연출 개체다.

- 종, 폼, 성별, 이로치, 별명과 크기는 실제 맡긴 부모를 반영한다.
- 체력, 기술, 개체값, 성격과 지닌 도구처럼 외관에 필요 없는 정보는 노출하지 않는다.
- 포획, 배틀, 탑승, 교환, 회수, 아이템 사용과 일반 상호작용을 모두 차단한다.
- 피해, 넉백, 상태이상, 포탈 이동, 드롭과 경험치 획득 대상이 되지 않는다.
- 서버 저장의 포켓몬 원본으로 취급하지 않으며 연출 개체가 사라져도 위탁에는 영향이 없다.
- 부모가 반환되거나 작업이 취소·실패하면 대응하는 연출 개체를 즉시 제거한다.
- 알이 준비된 뒤에도 부모는 수령할 때까지 목장에 남고, 짧은 하트 또는 음표
  파티클로 준비 상태를 표현한다.

연출 개체는 다음 범위 안에서만 제한적으로 움직인다.

```text
daycare_paddock
  ├─ ground_zone: 일반 육상 포켓몬
  ├─ pond_zone: 수중 이동이 필요한 포켓몬
  ├─ perch_zone: 비행 포켓몬의 착지·낮은 호버 지점
  └─ rest_zone: 대형 포켓몬과 이동이 어려운 포켓몬
```

구조물 메타데이터에 `daycare_paddock` 경계와 유형별 앵커를 선언한다. 연출 개체는
선택된 영역을 벗어나는 경로를 만들지 않고, 경계에 접근하면 안쪽 앵커로 방향을
바꾼다. 길 찾기가 실패하거나 경계를 벗어나면 눈에 띄지 않는 순간에 휴식 앵커로
되돌린다. 수중 포켓몬을 잔디 위에서 헤엄치게 하거나 대형 포켓몬을 작은 우리에
끼워 넣지 않도록 종의 이동·크기 분류에 맞는 영역만 사용한다.

기준안은 목장을 방문한 플레이어가 자기 포켓몬을 반드시 볼 수 있고, 주변
플레이어도 그 포켓몬을 볼 수 있는 공개 목장이다. 연출 개체 이름표에는
`<별명> · <플레이어>의 포켓몬`을 표시하되, 플레이어가 가까이 보거나 조준할 때만
보이게 한다.

서버 부하와 혼잡을 막기 위해 다음 가시성 예산을 적용한다.

- 키우미집 반경 64블록 안에 소유자가 있을 때만 그 플레이어의 연출 개체를 생성한다.
- 소유자가 반경을 벗어나면 짧은 유예 후 제거하고, 다시 접근하면 작업 데이터로 재생성한다.
- 한 시설에서 동시에 표시할 수 있는 부모 포켓몬은 기본 12마리다.
- 예산을 넘으면 가까운 소유자의 포켓몬을 우선하고, 나머지는 교대로 표시한다.
- 연출 개체는 청크 강제 로드의 이유가 될 수 없으며, 비활성 시설에는 존재하지 않는다.
- 서버 재시작 후 월드에 남은 고아 연출 개체는 제거하고 활성 작업에서 다시 만든다.

공개 목장 때문에 다른 플레이어가 결과 종이나 이로치 부모 보유 사실을 보는 것이
싫을 수 있으므로 NPC 메뉴에 `내 포켓몬 목장 공개` 설정을 제공한다. 기본값은
`공개`이며, 끄면 소유자 클라이언트에만 패킷 기반 연출을 보내는 개인 표시 모드로
전환한다. 개인 표시 구현이 준비되지 않은 첫 버전에서는 비공개 설정 시 연출 자체를
숨기고 위탁 기능은 정상 유지한다.

### 3.6 수령

수령 시 다음을 하나의 멱등 트랜잭션으로 처리한다.

1. 부모 스냅샷과 현재 작업 토큰을 검사한다.
2. 아직 알이 생성되지 않았다면 Cobbreeding 어댑터로 정확히 한 번 생성한다.
3. 생성한 알 `ItemStack`을 작업 데이터에 먼저 영속 저장한다.
4. 플레이어 인벤토리에 알 한 칸, Cobblemon PC에 부모 두 마리를 넣을 공간이 있는지
   확인한다.
5. 알과 부모를 전달한 뒤 작업을 `COLLECTED`로 확정한다.

일반 인벤토리에 빈칸이 없으면 알과 부모를 작업에 그대로 보관하고 빈칸을 만든 뒤
다시 오도록 안내한다. 부모는 파티가 아니라 PC로 반환하는 것을 기본으로 하여 파티
구성이 바뀌어도 안전하게 수령할 수 있게 한다.

`수령` 패킷이 중복 도착하거나 서버가 전달 도중 재시작되어도 작업 토큰과 단계별
완료 기록으로 같은 알 또는 부모가 두 번 지급되지 않아야 한다.

## 4. 작업 상태와 저장 데이터

플레이어당 NPC 위탁 슬롯은 기본 `1개`다. 슬롯 확장은 초기 구현에서 제외한다.

```text
EMPTY
  → 접수 성공 → BREEDING
  → 완료 시각 경과 → READY
  → 수령 성공 → COLLECTED → EMPTY

BREEDING
  → 사용자 취소 → CANCELLED → 부모 반환 → EMPTY
  → 시스템 실패 → FAILED → 환불·부모 반환 → EMPTY
```

필수 저장 필드는 다음과 같다.

| 필드 | 용도 |
|------|------|
| `job_id` | 중복 요청을 막는 UUID |
| `owner_uuid` | 위탁 소유자 |
| `daycare_id` | 접수·수령 가능한 시설 ID |
| `status` | 현재 상태 |
| `parent_a`, `parent_b` | Cobblemon 포켓몬 전체 직렬화 데이터 |
| `parent_a_uuid`, `parent_b_uuid` | 중복 보관과 복제 검사 |
| `accepted_at`, `ready_at` | 접수와 완료 기준 시각 |
| `fee_paid` | 실제 납부액과 환불 근거 |
| `egg_stack` | 생성 후 암호화된 Cobbreeding 알 아이템 |
| `generation_committed` | 알 생성 재실행 방지 |
| `delivery_step` | 수령 중 재시작 복구 지점 |
| `paddock_visibility` | 공개·개인·숨김 목장 표시 설정 |
| `schema_version` | 데이터 마이그레이션 |

포켓몬은 맡기는 순간 원래 파티 또는 PC 저장소에서 제거하고 작업 저장소가 소유한다.
복사본을 남긴 채 사용 금지 플래그만 거는 방식은 거래, 진화, 삭제와 다른 모드의
포켓몬 조작을 완전히 막기 어렵기 때문에 사용하지 않는다.

## 5. 개인 농장 자가 교배

### 5.1 해금

기준안은 배지 4개와 개인 농장 튜토리얼 완료 후 키우미 NPC가 `브리더 자격` 퀘스트를
주는 것이다. 퀘스트를 끝내면 다음을 해금한다.

- 브리더 도구 제작법
- 개인 농장 안의 브리더 도구 설치 권한
- 농장 PC의 `교배 관리` 도움말

정확한 배지 수는 진행 밸런스 설정으로 옮길 수 있지만, NPC 위탁을 먼저 경험한 뒤
자가 운영으로 넘어가는 순서는 유지한다.

### 5.2 제작과 설치

브리더 도구의 실제 블록은 Cobblemon 목장 블록과 Cobbreeding 확장 기능을 사용한다.
제작법은 기존 목장 블록에 농장에서 얻는 목재·건초·규토리 또는 열매 계열 재료를
요구하는 `브리더 도구 키트` 형태로 제공한다. 정확한 재료 ID와 수량은 농장 작물
목록이 확정된 뒤 데이터 레시피로 정한다.

- 개인 농장 안의 소유자 플롯에만 설치할 수 있다.
- 플레이어당 활성 브리더 도구는 기본 1개다.
- 다른 차원에 설치하거나 피스톤 등으로 경계를 넘기면 비활성화한다.
- 파괴 시 부모와 생성된 알을 먼저 안전하게 회수해야 하며, 회수 공간이 없으면
  파괴를 취소한다.
- 호퍼 알 추출은 기본 비활성화해 무인 자동화를 막는다.

도구와 첫 제작 재료의 합산 가치는 약 `30,000원`, 즉 NPC 위탁 10회 정도를 기준으로
잡는다. 실제 현금 구매가 아니라 농장 생산물을 주재료로 사용해 농장 성장의 보상으로
느껴지게 한다.

### 5.3 직접 교배의 차이

| 항목 | NPC 키우미집 | 개인 농장 브리더 도구 |
|------|--------------|------------------------|
| 회당 비용 | 3,000원 | 없음 |
| 초기 투자 | 없음 | 제작 재료와 해금 퀘스트 |
| 진행 위치 | 어디서 활동해도 진행 | 소유자가 농장에 있을 때 진행 |
| 오프라인 진행 | 지원 | 미지원 |
| 알 생산 | 접수당 1개 | Cobbreeding 목장 방식으로 반복 |
| 수령 | 같은 키우미 NPC | 설치된 도구 |
| 자동화 | 불가 | 호퍼 비활성, 수동 회수 |
| 추천 대상 | 가끔 교배하거나 편의를 원하는 플레이어 | 반복 교배에 투자한 플레이어 |

자가 교배가 NPC 서비스의 완전한 상위 호환이 되지 않도록, 브리더 도구의 교배 틱은
소유자가 자기 농장에 있을 때만 진행한다. 청크 상시 로드나 오프라인 성장 보정으로
무료 알이 자동 축적되지 않게 한다.

### 5.4 공통 제한

- Ditto+Ditto 무작위 알은 비활성화한다.
- 전설, 환상, 패러독스, 울트라비스트와 미발견 알 그룹의 예외 교배를 허용하지 않는다.
- 프로젝트 포켓몬 해금 정책상 아직 획득 불가능한 종이 알로 새어 나오지 않게
  결과 종을 접수 시 검사한다.
- 부모가 합법적으로 보유한 유전 정보는 NPC와 농장 양쪽에서 동일하게 인정한다.
- 마스다 방식과 이로치 배율은 전역 설정 하나만 사용한다.

## 6. NPC 이벤트와 전용 UI의 경계

일반 대사, 첫 설명, 메뉴 선택과 퀘스트 해금은 CVES NPC 이벤트가 담당한다. 부모
선택, 호환성 미리보기, 결제 확인, 작업 상태와 수령은 서버 권위 전용 키우미 화면이
담당한다.

CVES에는 장기적으로 다음 비동기 명령 하나만 추가한다.

```cves
await daycare "cobbleventure:daycare/pallet_town" -> result
```

명령 결과는 `accepted`, `ready`, `collected`, `cancelled`, `insufficient_funds`,
`incompatible`, `inventory_full`, `failed` 중 하나다. 이벤트는 결과에 맞는 짧은 후속
대사만 표시한다. 돈 차감과 포켓몬 이동을 `take_money`, 별도 명령 조합으로 작성하지
않아 중간 실패 시 일부만 적용되는 문제를 막는다.

## 7. 운영 설정 초안

```json
{
  "daycare": {
    "enabled": true,
    "service_fee": 3000,
    "jobs_per_player": 1,
    "min_breeding_ticks": 8000,
    "max_breeding_ticks": 14000,
    "offline_progress": true,
    "offline_progress_cap_hours": 24,
    "return_parents_to": "pc",
    "self_breeding_badges_required": 4,
    "self_breeder_limit": 1,
    "self_breeding_requires_owner_present": true,
    "allow_hopper_extraction": false
  }
}
```

교배 시간과 유전 관련 값은 가능하면 Cobbreeding 설정을 단일 원본으로 사용한다.
위 설정의 시간 필드는 명시적 덮어쓰기가 필요할 때만 사용하고, 평상시에는
Cobbreeding 값을 읽어 화면의 예상 시간과 실제 시간이 어긋나지 않게 한다.

## 8. 구현 단계

### 1단계: 호환성 실험

- Cobbreeding 2.2.2 NeoForge 파일 `9bPk2DC3`에서 교배 가능 조합 조회와 알 생성 호출 검증
- 지닌 도구, 폼, 유전기, 개체값, 성격, 특성, 볼, 마스다 방식 결과 비교
- 알 `ItemStack` 저장·재로드·부화 왕복 검증
- Cobbreeding 업데이트 시 깨짐을 감지하는 어댑터 계약 테스트 작성

### 2단계: NPC 최소 기능

- 부모 선택과 서버 검증 화면
- 작업 영속 저장소와 포켓몬 격리 보관
- CobbleDollars 원자적 결제
- 온라인·오프라인 완료 시간 처리
- 알 하나와 부모 두 마리의 멱등 수령
- 취소, 오류 환불과 관리자 복구 명령

### 3단계: 시설·이벤트 통합

- 키우미집 NPC 배치와 CVES `await daycare` 연결
- 준비 상태 표식과 지도 시설 정보
- 작업 데이터 기반 목장 연출 개체 생성·제거와 경계 이동
- 육상·수중·비행·대형 포켓몬용 목장 영역과 앵커 배치
- 시설별 표시 예산, 거리 비활성화와 공개 범위 설정
- 지역별 키우미집이 같은 플레이어 작업을 공유할지 시설별로 나눌지 확정
- 콘텐츠 관리 도구에서 가격, 시간과 해금 조건 편집 지원

기준안은 모든 정식 키우미집 NPC가 같은 위탁 작업을 조회하되, 알과 부모의 수령은
접수한 시설에서만 가능하게 하는 것이다. 지도에는 접수 시설을 표시한다.

### 4단계: 농장 자가 교배

- 브리더 자격 퀘스트와 제작법 해금
- 개인 농장 설치·소유권·개수 제한
- 소유자 농장 체류 중에만 교배 진행
- 파괴·농장 초기화·서버 복구 시 부모와 알 보호
- NPC와 농장 결과가 같은지 회귀 테스트

## 9. 합격 기준

- NPC에게 맡긴 포켓몬은 파티, PC, 거래와 다른 목장에서 동시에 사용할 수 없다.
- 호환되지 않는 조합에는 돈이 청구되지 않는다.
- 접수 성공 시 3,000원과 부모 두 마리 이동이 함께 성공하거나 함께 실패한다.
- 로그아웃과 키우미집 청크 언로드 중에도 NPC 위탁 시간이 정확히 흐른다.
- 한 위탁에서 알이 하나만 생성되고 재접속·중복 패킷으로 복제되지 않는다.
- 알 결과는 Cobbreeding 목장에서 같은 조건으로 만든 결과와 동일한 규칙을 따른다.
- 인벤토리가 가득 찬 경우 부모와 알이 사라지거나 월드에 떨어지지 않는다.
- 모드 호환성 실패 시 이미 맡긴 부모와 납부액을 복구할 수 있다.
- 목장 연출 개체의 종, 폼, 이로치와 크기가 맡긴 부모의 외형과 일치한다.
- 목장 연출 개체를 포획·전투·공격·탑승하거나 울타리 밖으로 유도할 수 없다.
- 연출 개체 제거·청크 언로드·서버 재시작이 보관된 부모 데이터에 영향을 주지 않는다.
- 동시 방문자가 표시 예산을 넘어도 TPS가 안정적이고 모든 소유자의 포켓몬이 교대로 보인다.
- 배지 4개와 퀘스트 완료 전에는 브리더 도구를 제작·활성화할 수 없다.
- 개인 농장 밖에서는 브리더 도구가 동작하지 않는다.
- 자가 교배는 무료지만 소유자가 농장에 없을 때 진행되지 않는다.

## 10. 밸런스 검증 지표

첫 플레이 테스트에서는 다음을 기록한다.

- 첫 NPC 위탁 시점의 평균 보유금과 `3,000원`의 비율
- 배지 구간별 NPC 위탁 횟수
- 접수 후 취소율과 미수령 작업 수
- 브리더 도구 해금까지의 플레이 시간
- 제작 후 NPC 서비스와 자가 교배의 이용 비율
- 플레이어당 하루 알 생성량과 이로치·고개체 알 공급량

NPC 위탁을 거의 아무도 사용하지 않으면 가격 또는 해금 시점을 낮춘다. 반대로
