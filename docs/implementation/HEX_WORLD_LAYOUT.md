# 육각 계획 그래프와 연속 바이옴 지형

> 결정: 기존 마을별 사각형 `bounds`, 바이옴 경쟁 배치와 직선 관문 방식을
> 폐기한다. 육각 셀은 마을·통로·바이옴 점유량을 계산하는 보이지 않는 계획
> 그래프로만 사용하고, 플레이어가 보는 지형은 연속 영향 마스크로 만든다.

> 구현 상태: World Bootstrap 지도 버전 6에서 육각 셀 예약, A* 통로, 주변
> 바이옴 성장, 연속 지형 마스크, 바이옴별 외곽 경계와 5개 마을 배치를 구현했다. 현재는
> 최초 입장 시 블록과 `fillbiome`으로 그리는 프로토타입이며 정식 커스텀
> `BiomeSource`/`ChunkGenerator` 이관은 후속 단계다.

## 핵심 모델

하나의 육각 셀은 하나의 계획상 바이옴을 가진다. 실제 Minecraft 바이옴 경계는
셀 중심의 영향 반경과 저주파 노이즈를 합성해 곡선으로 그린다. 따라서 육각형은
데이터 편집과 길찾기에는 남지만 게임 화면에 정육각형 윤곽으로 드러나지 않는다.

```text
       [숲] [숲]          [꽃] [꽃]
    [강] [시작 마을] [길] [초록길 마을] [숲]
       [강] [평원]          [강] [숲]
```

- `town_radius_cells`: 마을 건물과 도로가 들어가는 셀 반경
- `town_biome`: 마을 셀에만 적용되는 바이옴
- `surroundings[].tile_count`: 해당 주변 바이옴이 반드시 차지할 셀 수
- `surroundings[].influence_radius_blocks`: 각 셀 중심에서 뻗는 실제 지형 반경
- `surroundings[].edge_noise`: 실제 바이옴 외곽의 굴곡 강도
- `surroundings[].boundary_profile`: 이 바이옴이 월드 외곽에 닿았을 때의 경계
- `terrain_profile`: 기준 높이, 높낮이 변화량, 저주파 높이 노이즈 크기
- `access_requirement`: 지역 진입에 필요한 `rock_climb`, `surf` 필드 기술
- `connections`: 두 마을 앵커 사이에서 길찾기로 예약하는 통로 셀
- `corridor_width_blocks`: A* 중심선을 감싸는 실제 통로 폭
- `surface_style`: 돌길, 자연 지표 또는 물길 렌더링
- `boundary_profile`: 마을 또는 통로가 미할당 외부에 닿을 때 그릴 경계

이제 마을 내부와 외곽에서 바이옴들이 가중치로 경쟁하지 않는다. 마을 셀은 먼저
확정되고 주변 바이옴에는 요청한 셀 수가 보장되므로, 첫 바이옴이 전체 지역을
잠식하는 문제가 구조적으로 사라진다.

## 데이터 책임

| 데이터 | 책임 |
|------|------|
| `content/worlds/generation_1.json` | 육각 격자, 마을 앵커 셀, 바이옴 셀 수와 연결 경로 |
| `content/catalogs/boundary-profiles.json` | 벽·토루·수목 경계의 외형과 충돌 방식 |
| `content/settlements/**/*.json` | 건물, NPC, 체육관, 콘텐츠와 셀 중심 기준 상대 앵커 |
| 런타임 계획 결과 | 실제 점유 셀, 경로, 노출 변, 월드 좌표와 생성 버전 |

마을 JSON의 기존 `bounds`, `biome_layout`, `connections`는 육각 생성기로 이관하는
동안만 읽는 레거시 필드다. 최종 계약에서는 월드 지리 정보가 모두 세대 월드
지도에 있고, 마을 데이터는 셀 중심에 배치할 콘텐츠만 가진다.

## 좌표계

육각형은 꼭짓점이 위를 향하는 `pointy_top` 방향과 axial `(q, r)` 좌표를 쓴다.
세 번째 cube 좌표는 `s = -q-r`로 계산한다.

```text
world_x = origin_x + radius * sqrt(3) * (q + r / 2)
world_z = origin_z + radius * 3/2 * r
```

셀 거리는 다음 식으로 계산한다.

```text
distance = (abs(dq) + abs(dr) + abs(ds)) / 2
```

샘플은 계획 셀 반지름 64블록을 사용한다. 바이옴 셀 배정은 axial 좌표로 하지만,
실제 블록 판정은 모든 관련 셀의 `거리 / 영향 반경`을 비교한다. 영향 반경에는
시드 기반 저주파 보간 노이즈를 적용해 자연스러운 곡선 외곽을 만든다.

## 1세대 샘플 동선

현재 샘플은 직선 진행에 하나의 선택 분기를 둔다.

```text
시작 마을(1) ─ 초록길 마을(2) ─ 붉은바위 마을(3) ─ 물결섬 마을(4)
                                      │
                                      └─ 하늘마루 마을(5)
```

- `3→4`: `surf`가 필요한 해상 통로
- `3→5`: `rock_climb`가 필요한 산악 자연 통로
- 관리 웹의 **마을 설정 → 마을 동선**에서 노드 Q/R 좌표, 연결 방향, 통로 형태와
  필요 기술을 수정한다.
- 저장 시 전체 그래프의 중복 앵커, 존재하지 않는 마을, 자기 연결과 연결성을 먼저
  검사하고 성공한 경우에만 `content/worlds/generation_1.json`을 교체한다.

## 계획 알고리즘

계획기는 같은 월드 시드와 `seed_salt`에 대해 항상 같은 결과를 만든다.

1. 마을 앵커와 `town_radius_cells` 범위의 셀을 먼저 예약한다.
2. 마을 사이 연결을 A*로 계산해 통로 셀을 예약한다.
3. 주변 바이옴을 `tile_count`만큼 빈 셀에 성장시킨다.
4. 마을, A* 중심선 통로, 주변 바이옴 순으로 연속 영향 마스크를 계산한다.
5. 연속 마스크와 미할당 외부가 맞닿는 지점에 현재 바이옴의 경계 프로필을 적용한다.
6. 셀 중심을 기준으로 마을 구조물과 NPC 상대 앵커를 월드 좌표로 변환한다.
7. 모든 마을이 연결됐는지, 셀 중복과 고립 셀이 없는지 검증한 뒤 생성한다.

### 높이 지형과 필드 기술

마을 건축물이 기울지 않도록 마을 중심은 평탄하게 유지한다. 주변 필드는
`base_height_offset`, `height_variation`, `noise_scale_blocks`를 조합해 완만한
높낮이를 만든다. 일반 필드는 1~3블록 범위이며 `starter_highlands`는 가장 낮은
지점도 기본 지표보다 6블록 이상 높다.

`access_requirement`가 있는 지역은 서버가 플레이어의 해금 상태를 검사한다.
해금하지 않은 플레이어가 진입하면 마지막 안전 위치로 되돌린다. 고지대는
`cobbleventure:field_move/rock_climb`, 해상 통로와 물결섬 마을은
`cobbleventure:field_move/surf`를 요구한다.

### 주변 바이옴 성장

`preferred_direction`은 첫 성장 방향일 뿐 절대 좌표를 하드코딩하지 않는다.

- `compact`: 둘레가 짧은 덩어리를 우선한다.
- `organic`: 낮은 빈도의 결정적 노이즈를 더해 굴곡진 덩어리를 만든다.
- `linear`: 강, 협곡처럼 이어지는 셀을 우선한다.

경로 셀과 마을 셀은 주변 바이옴보다 우선한다. 필요한 `tile_count`를 확보하지
못하면 조용히 수를 줄이지 않고 빌드 오류로 처리한다.

### 통로 생성

통로의 중심선은 육각 셀 A* 경로다. 실제 지형은 중심선의 선분 거리를 계산하고
`corridor_width_blocks`와 `edge_noise`를 적용한 연속 띠로 만든다.

- 이미 예약된 다른 마을 셀: 통과 금지
- 강·산악 같은 고비용 바이옴 후보: 추가 비용
- 기존 통로 셀: 낮은 비용으로 합류 허용
- `organic`: 최단 거리에서 `detour_cells` 이내의 결정적 굴곡 허용

`width_cells`가 2 이상이면 중심 경로 양옆 셀도 통로로 예약한다. 진행 조건은 경로
끝의 관문이나 논리 경계에 적용하며, 연결 자체는 셀 그래프에서 항상 존재해야 한다.

## 경계 프로필

경계는 바이옴 사이마다 생기지 않는다. 연속 플레이 영역과 미할당 외부 사이에만
생성한다. 서로 이웃한 숲·강·마을·통로 사이는 열린 상태이며, 외곽에 닿은 바이옴의
`boundary_profile`이 벽·토루·수목선 중 무엇을 그릴지 결정한다.

### `wall`

- 석재 외장과 기반암 코어를 가진 인공 벽
- 도시권, 리그와 격리 구역에 사용
- 높이·두께·기초 깊이를 프로필로 조절

### `earthwork`

- 흙, 거친 흙과 잔디를 계단형으로 쌓은 토루 또는 절벽
- 지면 아래 보호 코어와 지역 보호 규칙을 함께 사용
- 숲과 평원 사이의 자연스러운 외곽에 적합

### `tree_line`

- 통나무와 잎을 간격·높이 범위에 맞춰 밀집 배치
- 나무만으로는 벌목·틈·비행 우회를 막을 수 없으므로 `protected` 충돌과
  나무 안쪽의 보이지 않는 차단 코어를 함께 사용
- 경계의 외관은 숲이지만 실제 통과는 허용된 통로에서만 가능

`collision`은 `hard`, `protected`, `soft`로 분리한다. 외관 타입과 통과 정책을
결합하지 않아 스토리 진행 후 같은 외형의 경계를 열 수 있게 한다.

## 마을 배치 이관

현재 마을 데이터의 `center`, `bounds`, 절대 `anchors`는 프로토타입 좌표다.
육각 계획기로 전환할 때 다음처럼 바꾼다.

1. 마을의 실제 중심은 월드 지도의 `anchor(q,r)`에서 계산한다.
2. `town_square`, `player_spawn`, `gym_entrance`는 중심 기준 상대 좌표로 저장한다.
3. 구조물은 모든 마을·주변·통로 셀이 확정된 다음 셀 중심에 배치한다.
4. 건물이 `town_radius_cells` 밖으로 나가면 데이터 검증에서 실패한다.

이 순서 때문에 “마을을 먼저 좌표에 놓고 주변을 자르는 방식”이 아니라, 사용자가
말한 대로 “육각 통로와 지역 그래프를 계획한 뒤 알맞은 셀에 마을을 놓는 방식”이
된다.

## 완료 기준

- 마을 셀에서는 `town_biome` 외 바이옴이 선택되지 않는다.
- 모든 주변 바이옴이 지정한 `tile_count`를 차지한다.
- 육각 계획 셀의 직선 변이 실제 바이옴 외곽에 드러나지 않는다.
- 두 마을 사이에 셀 단위 경로가 하나 이상 존재한다.
- 경계는 노출 변에만 생기고 통로 입구를 막지 않는다.
- 벽·토루·수목 프로필을 JSON만 바꿔 교체할 수 있다.
- 같은 시드와 콘텐츠 버전에서 동일한 셀 지도가 생성된다.
- 기존 사각형 경계와 블록 단위 직선 통로 코드가 제거된다.
