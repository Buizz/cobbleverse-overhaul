# PC 기반 1청크 개인 농장

> 적용 아키텍처: 3안 하이브리드의 기준 개인 공간
>
> 관련 결정: D-14 하이브리드 별도 공간 역할, D-15 집 PC 연출
>
> 설계 상태: 1청크 공유 차원 프로토타입 구현 / 작물 목록·성장 속도 미정

## 1 목적

넓은 서바이벌 월드 대신 플레이어마다 1청크 크기의 개인 농장을 배정한다. 플레이어는 시작 마을의 자기 집 PC에서 농장에 접속해 규토리와 포켓몬 열매를 재배한다.

```text
세대 보호형 서바이벌 월드
  → 시작 마을의 자기 집 PC
  → 1청크 개인 농장
  → 규토리·열매 재배와 수확
  → PC로 귀환
```

첫 프로토타입은 자기 1청크 안에서 일반 서바이벌 블록 편집을 허용한다. 자연 광맥과
넓은 탐험 지형은 제공하지 않으며, 포켓몬 관련 농사와 소규모 꾸미기를 위한 보조
공간으로 사용한다.

## 2 권고 물리 구조

플레이어마다 실제 차원을 하나씩 만들지 않고, 하나의 공유 `farm_plots` 차원에 개인 청크를 격리 배치한다.

```text
farm_plots 차원

[플롯 A 1청크] [완충 구역] [플롯 B 1청크]

[완충 구역]    [관리 구역] [완충 구역]

[플롯 C 1청크] [완충 구역] [플롯 D 1청크]
```

| 항목 | 기준안 |
|------|--------|
| 플롯 크기 | 16×16 블록, 청크 1개 |
| 소유 단위 | 플레이어 개인 |
| 배치 | 플레이어 UUID로 결정되는 플롯 인덱스 |
| 격리 | 플롯 사이 1개 이상의 비활성·보호 청크 또는 충분한 거리 |
| 입장점 | 플롯 중앙의 PC·온실 입구 |
| 귀환점 | 세대 월드 시작 집의 PC 앞 |
| 청크 로딩 | 활성 플롯은 1청크 상시 로드를 기본 후보로 삼고, 장기 미접속 플롯은 보관 상태로 전환 |

공유 차원 방식은 플레이어별 동적 차원보다 생성·백업·복구가 단순하다. 화면에는 가상 온실 또는 개인 시뮬레이션처럼 연출해 다른 플롯이 보이지 않게 한다.

## 3 허용 콘텐츠

### 3.1 기본 허용

- 규토리 나무 또는 규토리 작물 심기와 수확
- 포켓몬 열매 재배와 수확
- 밭 갈기, 물 공급과 작물 관리
- 상자·농장 PC 등 제한된 보관 블록
- 울타리, 길, 표지판과 소형 장식
- 프로젝트가 허용한 농업용 도구 사용

### 3.2 기본 금지

- 자연 광맥과 채광
- 대규모 자동화 기계와 청크 로더
- 몬스터 사냥과 일반 자원 파밍
- 다른 플레이어 플롯 침입·파괴
- 포탈·워프·비행을 이용한 플롯 경계 이탈
- 서버 부하가 큰 엔티티 농장과 무한 증식 장치

### 3.3 건축 범위

농사만 허용하면 모든 플롯이 같아져 개인 공간의 애착이 약해질 수 있다. 반대로 자유 건축을 허용하면 농장보다 건축 월드가 된다. 초기안은 다음만 허용한다.

- 높이와 개수가 제한된 온실·창고
- 농로, 울타리와 장식 블록
- 포켓몬 한두 마리를 보여주는 휴식 공간
- 운영자가 지정한 블록 태그만 설치·파괴

## 4 게임 모드와 보호

두 구현 방식이 가능하다.

| 방식 | 설명 | 평가 |
|------|------|------|
| 서바이벌+영역 보호 | 플레이어는 서바이벌이며 자기 플롯 안의 블록만 변경 | 구현·조작이 자연스러워 기준안 |
| 어드벤처+전용 상호작용 | 서버가 작물 심기·수확 이벤트만 별도로 허용 | 보호는 강하지만 모드 작물 호환 검증 필요 |

서바이벌+영역 보호를 사용해도 허기, 자연 회복과 사망 페널티는 농장 설계에서 제외할 수 있다. 플롯 밖으로 이동하면 즉시 자신의 입장점으로 돌려보낸다. 크리에이티브
모드에서는 플롯 편집과 이동 경계 검사를 적용하지 않는다.

### 4.1 현재 프로토타입 명령어

- `/cobbleventure_farm`: 자기 플롯을 생성하거나 기존 플롯으로 이동한다.
- `/cobbleventure_return`: 농장 입장 직전의 차원과 좌표로 돌아간다.

귀환 차원과 좌표는 플레이어 영속 데이터에, UUID별 플롯 번호와 초기화 상태는 월드
저장 데이터에 기록한다. 플롯은 공유 `cobbleventure:farm_plots` 차원에서 32청크
간격으로 배치해 일반 렌더 거리에서 다른 플롯이 보이지 않게 한다.

## 5 작물 역할

### 5.1 규토리

규토리는 몬스터 사냥이나 광물 채굴 없이 포켓볼 관련 재료를 보충하는 장기 공급원으로 사용한다.

- 기본 색상은 초반부터 재배 가능
- 특수 규토리는 배지, 지역 또는 세대 진행으로 종자 해금
- 상점 구매를 완전히 대체하지 않고 직접 재배 선택지를 제공
- 자동 수확과 폭발적 증식은 제한

### 5.2 포켓몬 열매

열매는 회복, 상태이상 대응, 배틀 준비와 수집을 담당한다.

- 흔한 회복 열매는 기본 제공
- 전투용·희귀 열매는 지역 진행이나 발견으로 종자를 해금
- 최초 종자는 상점, NPC, 탐험 보상 또는 야생 채집으로 획득
- 수확한 열매는 세대 월드로 반입 가능
- 필수 관장전이 농장 대기시간에 막히지 않도록 상점·트레이너 보상 대체 경로 유지

### 5.3 농사를 강제하지 않는 원칙

개인 농장은 보조 공급처다. 규토리와 열매를 얻는 유일한 방법으로 만들지 않는다.

- 상점과 전투 보상으로 기본 수량을 확보할 수 있어야 한다.
- 농장은 장기적으로 비용을 절감하고 원하는 품종을 안정적으로 재배하는 이점을 준다.
- 농장을 이용하지 않아도 세대 월드와 리그를 완료할 수 있어야 한다.
- 성장 시간 때문에 메인 진행이 멈추지 않게 한다.

## 6 청크 상시 로드와 오프라인 성장

활성 플레이어당 농장 1청크를 상시 로드하는 방식은 소규모 스트리머 서버에서 충분히 검토할 수 있다. Minecraft Java 1.20.5부터 기본 스폰 청크 반경은 `2`로 축소되었으며, Mojang은 이를 약 `48×48` 블록 영역으로 설명한다. 농장 수가 적다면 기존의 작은 상시 로드 영역과 비슷한 규모에서 시작할 수 있다.

다만 개인 농장은 플레이어 수에 따라 상시 로드 청크가 선형으로 늘어난다. 10명은 10청크, 30명은 30청크, 100명은 100청크다. 등록된 모든 계정의 농장을 무기한 유지하지 않고, 최근 활동 플레이어의 플롯만 활성 상태로 둔다. 일정 기간 미접속한 플롯은 데이터는 보존하되 강제 로드를 해제한다.

목표 버전인 Minecraft 1.21.1에서는 **청크가 로드되어 있다는 사실만으로 플레이어가 없는 곳의 작물 랜덤 틱까지 보장된다고 가정하면 안 된다.** 다른 원인으로 로드된 청크도 랜덤 틱을 받을 수 있도록 범위가 확장된 것은 1.21.5 변경 사항이다. 따라서 상시 로드는 플롯 접근성과 상태 유지 정책으로 사용하고, 오프라인 작물 성장은 프로젝트가 별도로 보장한다.

권장 운영 모드는 다음과 같다.

1. 활성 플롯: 1청크 상시 로드 + 프로젝트가 제어하는 제한된 작물 성장 처리
2. 비활성 플롯: 강제 로드 해제 + 마지막 처리 시각 저장
3. 재활성화: 경과 시간을 계산해 허용된 최대치까지만 성장 단계를 한 번 보정

상시 로드 농장에서는 비용이 큰 자동화를 허용하지 않는다. 호퍼 연쇄, 레드스톤 시계, 대량 블록 엔티티, 주민·가축·몬스터 농장, 플레이어가 설치하는 추가 청크 로더는 금지하거나 엄격히 제한한다. 규토리와 나무열매 같은 지정 작물, 물, 장식 블록, 소수의 저장공간만 허용하는 것이 안전하다.

- 서버 실제 시각이 아니라 조작하기 어려운 서버 기준 시간을 사용한다.
- 오프라인 성장에는 최대 누적 시간을 둔다.
- 뼛가루와 다른 모드 성장 가속 아이템의 허용 범위를 제한한다.
- 서버 재시작과 백업 복원 후 성장 시간이 중복 계산되지 않게 한다.

## 7 PC 접속 흐름

```text
자기 집 PC 사용
  → 플레이어 소유 플롯 조회
  → 플롯이 없으면 1청크 템플릿 생성
  → 경과 시간 기반 작물 성장 반영
  → 플롯 청크 준비
  → 농장용 게임 규칙 적용
  → 개인 입장점으로 이동
```

첫 접속 시 온실, 작은 밭, 물 공급원, 보관함과 귀환 PC가 포함된 기본 템플릿을 생성한다. FTB Genesis식 AE2 공간 로딩은 선택적인 시각 연출로 사용할 수 있지만 플롯 저장과 소유권은 프로젝트 시스템이 관리한다.

## 8 멀티플레이 규칙

- 기본적으로 소유자만 블록과 작물을 변경할 수 있다.
- 방문 허용 목록으로 친구에게 보기·수확·편집 권한을 개별 부여할 수 있다.
- 소유자가 오프라인일 때 방문을 허용할지 설정한다.
- 팀 농장은 개인 플롯과 별도 후보로 두며 초기 구현에는 포함하지 않는다.
- 부계정 플롯을 이용한 종자·열매 대량 생산을 막기 위해 희귀 종자 해금은 플레이어 진행과 연결한다.
- 장기간 미접속 플롯은 자동 삭제하지 않고 아카이브 후 관리자 복구가 가능하게 한다.

## 9 프로토타입 합격 기준

- 집 PC 첫 사용 시 플레이어 전용 1청크 농장이 중복 없이 생성된다.
- 자기 플롯에서는 일반 서바이벌처럼 블록을 설치하고 파괴할 수 있다.
- 플롯 밖과 다른 플레이어 플롯은 수정할 수 없다.
- 채광, 몬스터 농장과 금지된 자동화가 차단된다.
- 퇴장·재접속·서버 재시작 후 작물과 보관함 상태가 유지된다.
- 활성 플롯 1청크를 상시 로드했을 때 목표 동시접속 인원에서 MSPT가 안정적이다.
- 플레이어가 없는 1.21.1 환경에서도 프로젝트 성장 처리가 정확히 동작한다.
- 비활성 플롯의 강제 로드를 해제하고 재접속하면 성장 보정이 한 번만 적용된다.
- 귀환 PC가 시작 마을의 올바른 집으로 플레이어를 돌려보낸다.
- 농장을 사용하지 않는 플레이어도 메인 진행을 완료할 수 있다.

## 10 미결정 사항

- 플롯 사이 완충 거리는 몇 청크인가?
- 건축 가능한 최대 높이와 블록 목록은 무엇인가?
- 기본 제공 작물과 진행 해금 작물은 무엇인가?
- 규토리·열매 성장 시간과 오프라인 성장 상한은 얼마인가?
- 자동 수확, 물뿌리개와 뼛가루를 어디까지 허용할 것인가?
- 친구 방문과 공동 편집을 기본 허용할 것인가?
- 플레이어 탈퇴·UUID 변경·팀 이동 시 플롯 소유권을 어떻게 처리할 것인가?
