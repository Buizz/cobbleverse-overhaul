# 플레이어 메뉴

> 관련 기능: F-17 플레이어 메뉴, F-14 본가식 가방 인벤토리
>
> 관련 문서: [본가식 가방 인벤토리](BAG_INVENTORY.md), [진행 및 콘텐츠 해금](PROGRESSION.md), [서바이벌 월드와 플레이어 집 PC](SURVIVAL_WORLD.md)
>
> 설계 상태: 본가식 세로 리스트 구현 / 장비·Cobblemon 포켓몬·PC·도감·지도 연결 완료, 세부 기능 미정

## 1 목적

기본 인벤토리 키를 누르면 플레이어가 자주 사용하는 핵심 기능을 한곳에서 선택할 수 있는 본가식 세로 메뉴를 연다. 가방 하나로 모든 기능을 합치지 않고 가방, 포켓몬, 도감, 지도와 진행 정보를 독립된 화면으로 제공한다.

```text
인벤토리 키 입력
  → 화면 오른쪽에 세로 메뉴 표시
  → 기능 선택
  → 현재 위치·진행·전투 상태 검사
  → 허용된 화면 열기 또는 비활성화 사유 표시
```

플레이어 메뉴는 각 기능의 데이터와 규칙을 직접 소유하지 않는다. 메뉴 항목을 일정한 순서에 표시하고 각 기능 화면으로 연결하는 공통 진입점이다.

## 2 기본 메뉴 구성

1차 메뉴는 한 번에 인식하고 선택하기 쉬운 8항목을 기준으로 한다.

| 메뉴 | 핵심 역할 | 기본 접근성 |
|------|-----------|-------------|
| 가방 | 포켓별 아이템 관리, 사용, 버리기와 퀵슬롯 등록 | 필드에서 사용 가능, 전투·지역 규칙 적용 |
| 포켓몬 | 현재 파티 확인, 순서 변경, 기술·지닌물건·탑승 담당 관리 | 필드에서 사용 가능, 전투 중 일부 제한 |
| 도감 | 발견·포획 기록, 서식지, 진화와 폼 정보 | 필드에서 열람 가능 |
| 지도 | 지방·지역·도시·관문·목적지와 발견 정보 | 필드에서 열람 가능, 미발견 정보 제한 |
| 퀘스트 | 메인·서브 목표, 추적, 완료 기록과 보상 | 필드에서 열람 가능 |
| 트레이너 카드 | 프로필, 배지, 지역 진행도, 전적과 챔피언 기록 | 필드에서 열람 가능 |
| PC | 포켓몬 박스, 우편·보상함, 개인 공간과 관리 기능 | PC 단말기·해금 상태에 따라 제한 |
| 장비 | 방어구, 보조 손, 액세서리, 핫바와 바닐라 호환 슬롯 | 필드에서 사용 가능, 지역 규칙 적용 |

메뉴 이름은 1차 작업명이다. 실제 번역과 UI 프로토타입에서 `퀘스트`를 `모험 기록`으로 바꾸거나 `장비`의 범위를 조정할 수 있다.

## 3 메뉴별 기능 경계

### 3.1 가방

- 아이템 종류별 포켓 이동
- 이름·설명 검색과 정렬
- 아이템 사용, 수량 선택과 버리기
- 포켓몬에게 사용하거나 지니게 하기
- 자주 쓰는 아이템의 퀵슬롯 등록
- 중요한 물건의 사용 조건과 현재 상태 표시

가방의 저장·분류·아이템 이동 규칙은 [본가식 가방 인벤토리](BAG_INVENTORY.md)가 담당한다. 방어구와 외부 모드 장비 슬롯은 가방이 아니라 장비 화면에서 관리한다.

### 3.2 포켓몬

- 현재 파티와 순서 변경
- 능력치, 상태, 특성, 기술과 상세 정보
- 지닌물건 장착·회수
- 회복 아이템과 기술 관련 아이템 사용
- 탑승·비전머신 담당 지정
- 허용된 위치에서 PC 박스로 보내기

포켓몬 화면은 현재 소지한 개체를 관리한다. 종 전체의 발견·포획·서식 정보는 도감이 담당한다.

### 3.3 도감

- 발견·포획 여부와 달성도
- 지방·지역·바이옴별 서식지
- 시간, 날씨와 특수 출현 조건
- 진화 조건과 폼 정보
- 잠긴 포켓몬의 공개 가능한 힌트
- 즐겨찾기와 추적 대상 등록
- 해당 서식지를 지도에서 확인

도감은 실제로 발견했거나 진행 규칙이 공개를 허용한 정보만 표시한다. 서버의 전체 스폰 테이블을 클라이언트에 그대로 보내지 않는다.

### 3.4 지도

- 현재 지방·지역과 플레이어 위치
- 도시, 포켓몬센터, 상점, 체육관과 관문
- 발견한 던전·농장·집과 특수 시설
- 추적 중인 퀘스트 목적지
- 도감에서 추적한 서식지
- 공중날기와 귀환이 가능한 목적지
- 잠긴 지역과 해금 조건의 허용된 안내

지도는 지역·진행 모듈이 제공한 정보를 표현한다. 월드 생성 좌표나 진행 원본 데이터를 별도로 복제해 소유하지 않는다.

### 3.5 퀘스트

- 메인 스토리와 지역 진행 목표
- NPC 서브 퀘스트
- 일일·주간 목표가 도입될 경우의 반복 목표
- 현재 추적 중인 목표와 HUD 표시 선택
- 완료 기록과 미수령 보상
- 지도에서 목적지 확인

첫 버전의 퀘스트 수가 적다면 튜토리얼과 시스템 안내를 합친 `모험 기록` 화면으로 시작할 수 있다.

### 3.6 트레이너 카드

- 플레이어 프로필과 외형
- 시작 지방, 플레이 시간과 주요 기록
- 획득한 배지와 지역별 진행도
- 트레이너전·리그전·공식 PvP 전적
- 도감 달성도와 대표 포켓몬
- 리그 도전 자격
- 현재·역대 챔피언 기록
- 다른 플레이어에게 공개할 정보 설정

배지 케이스, 업적과 리그 기록은 별도 1차 메뉴로 늘리지 않고 트레이너 카드의 탭으로 통합한다.

### 3.7 PC

- 포켓몬 박스와 파티 교체
- 우편·운영 보상·복구함
- 개인 농장과 집 관련 관리
- 허용될 경우 세대 월드 또는 개인 공간 이동
- 프로필·외형 관련 PC 전용 기능

PC 항목의 위치는 항상 유지하되 실제 기능은 상황에 따라 제한한다.

| 상황 | 권고 동작 |
|------|-----------|
| PC 단말기 사용 중 | 모든 해금된 PC 기능 사용 |
| 일반 필드 | 박스·우편의 읽기 전용 정보 또는 비활성화 사유 표시 |
| 원격 PC 기능 해금 후 | 규칙이 허용한 박스 기능만 원격 사용 |
| 전투·인스턴스·이동 잠금 중 | 기능 열기 거부와 사유 표시 |

원격 박스의 허용 범위와 해금 수단은 후속 결정으로 남긴다. 사용할 수 없는 상황에도 메뉴 항목 자체를 숨기지 않는다.

### 3.8 장비

- 방어구와 보조 손
- 액세서리 모드 호환 슬롯
- 현재 핫바와 임시 사용 슬롯
- 탑승·탐험 장비가 별도 아이템일 경우의 장착 상태
- 바닐라 인벤토리 호환 영역
- 필요할 경우 2×2 개인 제작

가방이 바닐라 인벤토리를 대체하더라도 다른 모드가 사용하는 장비와 실제 손 슬롯에 접근할 경로를 유지한다. 초기 프로토타입에서는 바닐라 인벤토리 화면으로 이동하는 호환성 버튼을 제공한다.

## 4 배치와 조작 원칙

기본 배치는 화면 중앙과 월드 시야를 비우는 오른쪽 세로 구조다.

```text
[ 포켓몬      ]
[ 가방        ]
[ 장비        ]
[ PC          ]
[ 트레이너 카드 ]
[ 퀘스트      ]
[ 지도        ]
[ 도감        ]
```

- 항목 위치는 사용 가능 여부나 차원에 따라 바꾸지 않는다.
- 사용할 수 없는 항목은 제거하지 않고 어둡게 표시하며 사유를 제공한다.
- 연결된 항목은 녹색 상태 점, 준비 중인 항목은 회색 상태 점으로 구분한다.
- 마우스, 키보드와 게임패드에서 모두 선택할 수 있어야 한다.
- 선택 중인 행은 코블몬 파티 화면과 유사한 밝은 회색 슬롯으로 강조하고 왼쪽 정보 패널에 설명을 표시한다.
- 코블몬 요약·파티 화면의 중성 회색 팔레트, 1픽셀 명암 테두리와 패널 그림자를 따른다.
- 월드 화면에는 블러나 전체 화면 오버레이를 적용하지 않고 작은 불투명 패널만으로 UI 대비를 확보한다.
- 메뉴 너비는 상한을 두고 오른쪽 가장자리에 고정해 고해상도에서도 월드 시야를 과도하게 가리지 않는다.
- 화면 비율과 GUI 배율이 달라도 항목이 겹치지 않아야 한다.
- `Esc`는 메뉴를 닫고 원래 게임 화면으로 돌아간다.
- 빠른 선택 방식은 클릭 확정을 기본으로 하고, 누른 키를 놓아 확정하는 방식은 선택 설정으로 검토한다.
- 메뉴가 열려 있는 동안 이동·시점 회전·시간 흐름을 어떻게 처리할지는 싱글·멀티플레이를 구분해 결정한다.

## 5 상태와 권한 판정

플레이어 메뉴 화면은 클라이언트에서 표시할 수 있지만 실제 기능 열기와 데이터 변경은 서버가 승인한다.

```text
클라이언트가 feature_id 선택
  → 서버에 열기 요청
  → 서버가 플레이어·차원·전투·진행 상태 검사
  → 허용: 해당 메뉴 또는 화면 열기
  → 거부: 사유 코드와 표시 문구 반환
```

기본 거부 사유 후보:

- 아직 해금되지 않음
- 전투 중 사용할 수 없음
- PC 단말기가 필요함
- 현재 차원 또는 인스턴스에서 사용할 수 없음
- 플레이어가 사망·관전·이동 처리 중임
- 서버가 해당 기능 공급자를 지원하지 않음

클라이언트가 보낸 `feature_id`, 포켓 탭이나 대상 ID를 신뢰하지 않고 서버에서 다시 검증한다.

## 6 모드와 기능 경계

플레이어 메뉴는 월드 생성 모드와 분리한 별도 NeoForge 모드로 구현하는 것을 권고한다.

```text
projects/cobbleventure-player-menu
├─ menu: 입력, 세로 리스트 화면과 기능 항목 등록
├─ bag: 가방 저장, 분류, 컨테이너와 화면
├─ equipment: 장비·바닐라 슬롯 연결
├─ map: 지역 지도 화면 어댑터
├─ pokedex: Cobblemon 도감 어댑터
├─ quest: 진행·퀘스트 화면 어댑터
├─ trainer-card: 프로필·배지·전적 화면
└─ pc: 박스·우편·개인 공간 기능 연결
```

가방, 지도와 도감을 처음부터 각각 별도 JAR로 만들지는 않는다. 독립 설치가 필요하거나 외부 의존성이 달라질 때만 호환 모듈을 분리한다. 플레이어 메뉴는 등록형 기능 계약을 제공해 기능 추가가 화면의 하드코딩 변경으로 이어지지 않게 한다.

## 7 후속 메뉴 후보

아래 기능은 필요할 수 있지만 기본 8항목을 늘리기보다 기존 화면의 하위 탭이나 상황별 보조 메뉴로 우선 배치한다.

| 후보 | 우선 배치 위치 |
|------|----------------|
| 배지·업적·리그 기록 | 트레이너 카드 |
| 공중날기·빠른 이동 | 지도 |
| 탑승 포켓몬 지정 | 포켓몬 |
| 우편·보상함 | PC |
| 튜토리얼·시스템 안내 | 퀘스트 또는 모험 기록 |
| 거래·PvP·친구 | 통신 기능이 커질 경우 후속 메뉴 검토 |
| UI·접근성 설정 | 기존 설정 화면 |
| 바닐라 인벤토리 | 장비 화면의 호환성 탭 또는 개발용 항목 |

통신 기능이 핵심 플레이 루프로 커지면 장비를 가방 화면의 하위 탭으로 합치고 여덟 번째 자리에 `통신`을 넣는 대안을 비교한다.

## 8 1차 프로토타입 범위

- [x] 인벤토리 키로 오른쪽 세로 메뉴를 연다.
- [x] 마우스, 방향키·Enter와 숫자키 1~8 선택을 지원한다.
- [x] 모든 항목의 위치와 이름을 고정한다.
- [x] 장비 항목을 바닐라 인벤토리 화면에 연결한다.
- [x] 포켓몬 항목을 Cobblemon 파티 정보 화면에 연결한다.
- [x] PC 항목에서 권한이 적용되는 Cobblemon 원격 PC를 요청한다.
- [x] 소지한 Cobblemon 도감 아이템으로 기존 도감 화면을 연다.
- [x] 아직 화면이 없는 항목은 선택 시 준비 중 상태를 표시한다.
- [x] 각 항목에 아이콘·밝은 선택 슬롯·연결 상태 표시를 적용한다.
- [x] 코블몬 계열 회색 패널과 블러 없는 제한된 화면 점유를 적용한다.
- [ ] 가방 화면을 구현해 연결한다.
- [ ] PC 항목이 단말기 근처와 일반 필드에서 서로 다른 상태를 표시하게 한다.
- [ ] 서버가 데이터 변경과 기능 열기 요청을 다시 검증한다.
- [ ] 게임패드 선택과 접근성 설정을 검증한다.

현재 구현은 [Cobbleventure Player Menu](../../projects/cobbleventure-player-menu/README.md)에 있다. 포켓몬은 현재 선택한 파티 포켓몬의 Cobblemon 정보 화면을 열고, PC는 서버의 `/pc` 명령을 통해 원격 저장소 동기화와 편집 권한 검사를 거쳐 연다. 원격 PC 사용에는 서버의 `cobblemon.command.pc` 권한이 필요하다. 장비는 바닐라 인벤토리, 지도는 초기 월드맵 화면으로 연결한다. 도감은 플레이어 인벤토리에 있는 빨강·노랑·초록·파랑·분홍·검정·흰색 Cobblemon 도감 중 첫 아이템의 색상으로 기존 화면을 연다. 가방, 트레이너 카드와 퀘스트는 항목만 표시하며 후속 기능 화면이 준비되면 연결한다.

### 8.1 합격 기준

- 인벤토리 키를 한 번 눌러 플레이어 메뉴를 열고 다시 닫을 수 있다.
- GUI 배율과 해상도가 달라도 8개 항목과 이름이 겹치지 않는다.
- 항목의 위치가 차원·진행 상태에 따라 바뀌지 않는다.
- 비활성화된 항목을 선택하면 정확한 사유가 표시된다.
- 가방과 장비 또는 바닐라 인벤토리 사이를 이동해도 아이템이 유실되지 않는다.
- 조작 패킷을 재전송하거나 잘못된 기능 ID를 보내도 서버 상태가 변경되지 않는다.
- 모드에 연결되지 않은 기능이 있어도 플레이어 메뉴 전체가 열리지 않는 장애로 이어지지 않는다.

## 9 미결정 사항

- 8항목의 최종 이름, 아이콘과 시계 방향 순서는 무엇인가?
- `퀘스트`와 `모험 기록` 중 어떤 이름과 범위를 사용할 것인가?
- 장비 화면에 2×2 제작과 일반 27칸 인벤토리를 노출할 것인가?
- 필드에서 PC를 열었을 때 어디까지 읽기 또는 조작을 허용할 것인가?
- 원격 박스는 기본 기능인가, 진행 보상인가, 중요한 물건의 효과인가?
- 플레이어 메뉴가 열린 동안 플레이어 이동과 시점 회전을 막을 것인가?
- 통신 기능을 기본 8항목에 포함할 정도로 첫 버전에서 확장할 것인가?
- 지도와 도감은 자체 화면으로 구현할 것인가, 외부 모드 화면을 연결할 것인가?
