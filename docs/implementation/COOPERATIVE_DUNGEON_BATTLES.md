# 특수 던전 2인 협동 멀티배틀

> 관련 기능: F-06, F-07, F-15
>
> 관련 결정: 특수 던전에 한해 2인 협동 입장과 `GEN_9_MULTI` PvE를 제공한다.
>
> NPC 표현 계층: EasyNPC
>
> 설계 상태: 기준 결정 / 협력 거리 경고·강제 복귀 구현 / 전투 어댑터 검증 예정
>
> 입장 매칭: [던전 입구 대기열·자동 매칭 시스템](DUNGEON_ENTRY_MATCHMAKING.md)

## 1 목적과 범위

일반 필드와 트레이너전에는 파티 시스템을 추가하지 않고, 지정된 특수 던전에서만 두 플레이어가 같은 인스턴스에 입장해 협동 PvE를 진행할 수 있게 한다. 협동 관계의 수명은 던전 입장 준비부터 귀환까지이며 던전 밖에서는 유지하지 않는다.

- 일반 RCT NPC 엔티티는 사용하지 않는다.
- 던전 안의 안내자·적 트레이너·보스 외형과 상호작용은 EasyNPC가 담당한다.
- RCT의 NPC 클릭 전투 흐름에 의존하지 않는다.
- 2인 보스전은 플레이어 두 명과 상대 트레이너 두 명을 독립된 전투 참가자로 구성하는 `GEN_9_MULTI` 형식을 사용한다.
- 전역 길드·파티·친구 시스템은 이 기능의 범위에 포함하지 않는다.

## 2 사용자 흐름

```text
던전 입구 상호작용
  → 던전 안내 확인 후 입장 선택
  → 입구 대기열 등록
  → 다른 플레이어의 입장 요청 대기
  → 두 요청 자동 매칭
  → 두 플레이어의 UUID를 DungeonRun에 고정
  → 인스턴스 슬롯 준비와 귀환점 저장
  → 두 플레이어를 같은 던전으로 이동
  → 탐험·퍼즐·일반 조우 진행
  → 보스방 진입 시 참가자 검증
  → 플레이어 2명 대 트레이너 2명 멀티배틀 시작
  → 승패·보상·진행도 기록
  → 귀환 후 DungeonRun 종료
```

플레이어는 이름이나 배틀 명령을 직접 입력하지 않는다. 먼저 입장한 플레이어에게 `다른 도전자를 기다리는 중입니다`를 표시하고, 다른 플레이어가 같은 입구에서 입장을 누르면 서버가 FIFO 순서로 두 UUID를 자동 매칭한다.

## 3 던전 입장 세션

대기 중인 요청은 `DungeonEntryRequest`, 매칭된 명단은 `DungeonMatch`가 권위 상태를 가진다. 두 요청을 잠그고 `DungeonRun`으로 복사한 뒤에는 `DungeonRun`이 활성 협동 참가자의 권위 상태가 된다. Cobblemon의 PvP용 멀티배틀 팀이나 표시된 플레이어 이름을 참가자 저장소로 사용하지 않는다.

```text
DungeonRun
  run_id
  match_id
  dungeon_id
  member_uuids[2]
  instance_slot_id
  lifecycle_state
  return_anchors
  boss_encounter_id
  battle_id
  created_at
  reconnect_deadline
```

수명 상태는 최소한 다음을 구분한다.

```text
PREPARING
  → ACTIVE
  → BOSS_BATTLE
  → CLEARED | FAILED | ABORTED
  → RETURNING
  → CLOSED
```

- 던전 정의에 따라 1인 입장을 허용할 수 있지만 `GEN_9_MULTI` 보스전은 정확히 두 플레이어가 있어야 시작한다.
- 매칭 완료 후에는 참가자 교체를 허용하지 않는다.
- 표시 이름은 UI에만 사용하고 소유권, 보상과 복구는 UUID를 기준으로 처리한다.
- 대기 중 이탈은 해당 요청만 취소한다. 매칭 후 준비 중 한 명이 이탈하면 두 참가자의 입장을 취소하고 아무도 이동시키지 않는다.

## 4 보스 전투 구성

보스 EasyNPC를 플레이어가 직접 클릭해 각자 별도의 전투를 시작하게 하지 않는다. 보스방 또는 조우 컨트롤러가 세션과 NPC 상태를 확인하고 단 하나의 전투를 시작한다.

```text
player side = [player_a, player_b]
npc side    = [trainer_a, trainer_b]
format      = GEN_9_MULTI
```

각 참가자는 독립된 전투 액터와 포켓몬 팀을 가진다. 각자 최대 6마리를 사용하면 양쪽 합계는 최대 12마리 대 12마리가 되며, 필드에는 각 트레이너가 한 마리씩 내보내 2마리 대 2마리로 진행한다.

전투 시작 컨트롤러는 다음 순서로 검증한다.

1. `DungeonRun`이 `ACTIVE`이고 현재 조우가 아직 시작되지 않았는지 확인한다.
2. 세션의 플레이어 두 명이 접속 중이며 같은 인스턴스와 보스방 경계 안에 있는지 확인한다.
3. 두 플레이어 모두 사용 가능한 포켓몬을 한 마리 이상 보유했는지 확인한다.
4. EasyNPC 두 엔티티와 연결된 트레이너 정의·팀·AI가 준비되었는지 확인한다.
5. 조우 잠금을 원자적으로 획득하고 중복 시작을 막는다.
6. 전투 어댑터에 양쪽 참가자 목록과 전투 규칙을 전달한다.
7. 반환된 `battle_id`를 `DungeonRun`에 저장하고 상태를 `BOSS_BATTLE`로 바꾼다.

정식 구현은 던전 컨트롤러가 RCT API 또는 프로젝트 전투 어댑터를 직접 호출하는 방식을 우선한다. TBCS 0.14.1-beta도 필수 의존성으로 설치해 EasyNPC 액션, 초기 호환성 프로토타입과 관리자 진단에 사용한다. 다만 TBCS 명령을 런타임의 권위 있는 참가자 저장소로 사용하지 않는다.

## 5 EasyNPC 역할과 경계

EasyNPC는 다음을 담당한다.

- 던전 입구 안내와 자동 매칭 진입점
- 적 트레이너와 보스의 외형, 위치, 대사와 연출
- 보스전 전후 컷신과 상태별 상호작용
- 던전 세션·조우 컨트롤러를 호출하는 안정적인 NPC ID

EasyNPC 자체가 소유하지 않는 상태는 다음과 같다.

- 협동 멤버 UUID와 인스턴스 소유권
- 보스전 참가자 목록과 중복 시작 잠금
- 승패, 개인 진행도와 보상 수령 여부
- 로그아웃·서버 재시작 후 복구 상태

두 보스 NPC 중 어느 쪽과 상호작용하더라도 같은 `boss_encounter_id`를 사용한다. 전투가 시작된 뒤에는 양쪽 NPC의 추가 상호작용을 잠그고, 한 NPC가 없거나 로딩되지 않았으면 전투를 시작하지 않는다.

## 6 이탈·재접속·실패 정책

- 매칭 후 준비 단계에서 한 명이 나가면 인스턴스를 만들지 않고 두 참가자 모두 입구 안내 상태로 돌아간다.
- 던전 진행 중 연결이 끊기면 짧은 재접속 유예 시간을 두고 슬롯과 세션을 유지한다.
- 유예 시간 안에 돌아오면 기존 인스턴스의 안전 앵커로 복귀시킨다.
- 보스전 시작 전 한 명이 없으면 전투를 시작하지 않는다.
- 보스전 중 이탈 처리는 Cobblemon 전투 복구 가능성을 프로토타입에서 검증한 뒤 `재접속 대기` 또는 `던전 실패` 중 하나로 확정한다.
- 한 플레이어의 모든 포켓몬이 쓰러져도 동료에게 사용 가능한 포켓몬이 남아 있고 전투 엔진이 계속 진행할 수 있으면 즉시 실패로 처리하지 않는다.
- 세션을 포기하거나 복구할 수 없는 오류가 발생하면 두 플레이어를 저장된 귀환점으로 먼저 이동시킨 뒤 인스턴스를 정리한다.

## 7 보상과 진행도

- 던전 승리는 `run_id + player_uuid + encounter_id` 조합으로 개별 기록한다.
- 두 참가자 모두에게 개인 보상을 지급하며 인벤토리가 가득 찬 경우의 우편·드롭·보관 정책을 별도로 정의한다.
- 재접속이나 종료 이벤트 중복 수신으로 같은 보상을 두 번 지급하지 않는다.
- 던전 클리어 플래그와 관련 퀘스트 진행은 참가자별로 갱신한다.
- 한 명만 입장 자격이나 선행 진행을 충족해도 되는지, 두 명 모두 충족해야 하는지는 던전 정의에서 명시한다.
- 클리어 후 슬롯 정리는 보상과 진행도 저장이 성공한 뒤 수행한다.

## 8 프로토타입과 합격 기준

첫 프로토타입은 EasyNPC 보스 두 명과 고정 팀 두 개를 배치한 작은 인스턴스 전투방으로 제한한다.

1. 같은 입구에서 두 플레이어가 차례로 입장을 눌러 같은 `DungeonRun`에 자동 매칭된다.
2. 두 플레이어의 출발 위치를 저장하고 같은 슬롯으로 이동시킨다.
3. 보스방 트리거가 `GEN_9_MULTI`의 네 참가자를 구성한다.
4. 각 플레이어와 각 NPC가 자신의 액터와 팀만 조작하는지 확인한다.
5. 한 액터 전멸, 동시 기절, 교체와 항복 시 전투가 멈추지 않는지 확인한다.
6. 정상 승리·패배·이탈·재접속·서버 재시작 후 귀환과 정리를 검증한다.
7. 두 플레이어에게 진행도와 보상이 정확히 한 번씩 기록되는지 확인한다.
8. 다른 인스턴스에서 동시에 시작한 전투와 NPC·보스바·보상이 섞이지 않는지 확인한다.

다음 조건을 모두 만족해야 정식 던전에 적용한다.

- 플레이어가 이름이나 관리자 명령을 입력하지 않고 입장부터 배틀까지 완료한다.
- 세션에 등록되지 않은 플레이어가 인스턴스나 전투에 합류할 수 없다.
- 같은 보스 조우가 중복으로 시작되지 않는다.
- 네 액터의 팀, 명령과 보상이 서로 잘못 귀속되지 않는다.
- 실패 경로에서도 플레이어가 인스턴스에 갇히지 않고 슬롯이 누수되지 않는다.

## 9 후속 결정

- EasyNPC와 트레이너 정의를 연결할 정식 전투 어댑터를 RCT API 기반으로 둘 것인가, 프로젝트 전용으로 둘 것인가?
- 던전별로 1인 입장을 허용할 경우 2인 전용 보스의 대체 경로를 제공할 것인가?
- 보스전 중 한 명이 접속 종료했을 때 전투를 일시 정지할 수 있는가?
- 입구 대기 제한 시간과 재접속 유예 시간을 얼마로 둘 것인가?
- 같은 던전의 서로 다른 입구 대기열까지 합칠 필요가 있는가?
