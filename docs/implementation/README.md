## 작성 원칙

- 요구사항의 기준은 [프로젝트 기획서](../PROJECT_PLAN.md)로 유지한다.
- 각 구현 문서는 관련 기능 ID와 결정 ID를 명시한다.
- 확정된 결정, 현재 권고안, 검증이 필요한 가정을 구분한다.
- 게임, 모드 로더와 의존 모드 버전을 문서 상단에 기록한다.
- 외부 구조물과 데이터팩을 참고할 때 출처와 라이선스를 함께 기록한다.
- 구현 전에 실험 방법과 합격 기준을 정의하고 결과를 남긴다.

## 권장 작업 순서

1. 아키텍처 비교 문서의 세 프로토타입 범위와 평가 기준을 확정한다.
2. 1안의 어드벤처 지역, 2안의 격자 도시, 3안의 PC 생존 공간을 최소 규모로 비교한다.
3. 최종 아키텍처를 선택하고 해당 월드·진행 문서를 기준안으로 승격한다.
4. 선택한 안에 트레이너, 경제와 보상 데이터를 수직 구간으로 추가한다.
5. 운영 및 복구 절차가 닫힌 뒤 챔피언 시스템과 추가 세대를 확장한다.
