## 작성 원칙

- 요구사항의 기준은 [프로젝트 기획서](../PROJECT_PLAN.md)로 유지한다.
- 각 구현 문서는 관련 기능 ID와 결정 ID를 명시한다.
- 확정된 결정, 현재 권고안, 검증이 필요한 가정을 구분한다.
- 게임 어댑터 문서에는 게임, 모드 로더와 의존 모드 버전을 기록한다. 플랫폼 독립 코어 문서에는 게임 API가 필요하지 않음을 명시한다.
- 외부 구조물과 데이터팩을 참고할 때 출처와 라이선스를 함께 기록한다.
- 구현 전에 실험 방법과 합격 기준을 정의하고 결과를 남긴다.

## 권장 작업 순서

1. 게임 비의존 지역 JSON, 연결 그래프, 진행 조건과 차원 연결 계약을 구현한다.
2. 첫 지역·던전·집 PC·개인 농장의 콘텐츠 데이터를 작성하고 전체 교차 참조를 검증한다.
3. Cobblemon 안정 버전 출시 후 Minecraft·Cobblemon·트레이너 어댑터를 최소 규모로 연결한다.
4. 지역 경계, 관장 진행, 비전머신과 차원 왕복의 우회·복구 시나리오를 검증한다.
5. 운영 및 복구 절차가 닫힌 뒤 리그, 챔피언 시스템과 추가 세대를 확장한다.
