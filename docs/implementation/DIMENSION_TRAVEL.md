# 차원 및 지역 이동

> 관련 요구사항: F-01, F-06, F-07
>
> 관련 결정: D-04 도시 배치 방식, D-05 기존 월드 지원 범위
>
> 설계 상태: 기술 조사 진행 / 구현 버전과 API 미확정

> 적용 아키텍처: 3안 보호형 하이브리드. 모든 플레이 공간은 서바이벌 모드를 유지하고 영역별 서버 권한을 적용하며, 집 PC 목적지는 개인 1청크 농장으로 운영한다.

## 1 목적

오버월드의 자동 지형에 모든 필드와 동굴을 억지로 맞추지 않고, 전용 차원과 이동 오브젝트를 이용해 본가식 진행 동선과 수작업 지역을 안정적으로 제공한다.

## 2 난도 구분

차원 등록 자체와 차원의 콘텐츠 제작은 별개의 작업이다.

| 범위 | 난도 | 설명 |
|------|------|------|
| 기존 지형 설정을 재사용하는 시험용 차원 | 낮음~중간 | 데이터팩 JSON으로 차원과 차원 타입을 정의 |
| 오브젝트 상호작용과 고정 좌표 이동 | 중간 | 서버 측 조건 검사, 안전한 도착점과 귀환 처리 필요 |
| 고정 맵 또는 직소 구조물 기반 동굴 차원 | 중간 | 원하는 동선과 방 구성을 통제하기 쉬움 |
| 독자적인 자동 지형·동굴 생성기 | 높음 | 노이즈 설정, 밀도 함수, 바이옴 분포와 호환성 필요 |
| 플레이어별 동적 인스턴스 차원 | 매우 높음 | 생성·초기화·동시 접속·삭제·복구 수명주기 필요 |

Minecraft 1.16 이후의 차원은 데이터팩으로 정의할 수 있다. 단순 차원은 코드 없이 만들 수 있지만, 세밀한 생성과 이동 동작은 코어 모드 코드가 필요하다.

## 3 권고 차원 구성

마을이나 리그마다 차원을 하나씩 만들지 않는다. 차원이 많아질수록 서버 월드, 저장 파일, 백업, 엔티티와 청크 관리 대상이 늘어난다.

첫 구현은 다음 세 계층을 권고한다.

```text
[3안 전용] 개인 농장 차원
  └─ 집 PC로 접근하는 플레이어별 1청크 플롯

세대 차원들
  ├─ generation_1: 1세대 필드·마을·체육관
  ├─ generation_2: 2세대 필드·마을·체육관
  └─ generation_N: N세대 필드

전환 차원
  ├─ 1세대 챔피언로드·리그
  ├─ 2세대 챔피언로드·리그
  └─ N세대 챔피언로드·리그
```

각 세대의 일반 필드와 탐험 동굴은 해당 세대 차원 안에 생성한다. 챔피언로드와 리그만 공유 전환 차원에 서로 충분히 떨어진 구역으로 배치한다. 특별한 규칙이 필요한 최종 던전만 독립 차원으로 분리한다.

세대·전환·리그 차원은 서바이벌 모드를 유지하지만 일반 자연환경과 구조물은 서버 권한으로 보호한다. 지정 작물과 특수 던전 광물만 채집할 수 있다. 시작 마을의 자기 집 PC는 별도 `farm_plots` 차원으로 연결하며, 이곳에서는 자기 1청크 플롯의 농사와 제한된 꾸미기만 허용한다.

달맞이산처럼 넓은 지하 생태계를 가진 이름 있는 던전은 일반 자연 동굴과 구분해 전용 지하 차원 또는 공유 던전 차원의 독립 구역으로 구성한다. 상세 설계는 [던전 및 지하 차원](DUNGEON_DIMENSIONS.md)에서 다룬다.

### 3.1 공용 인스턴스 차원

짧은 관장전·레이드·리그전·컷신을 위해 매번 동적 차원을 생성하지 않는다. Cobblemon Raid Dens처럼 고정 공허 차원 하나에 멀리 떨어진 좌표 슬롯을 할당하고, NBT 구조물을 배치한 뒤 종료 시 초기화하는 방식을 검토한다.

같은 패턴을 플레이어별 스토리 건물 내부에도 사용할 수 있다. 집이나 연구소의 외관은 세대 월드에 유지하고, 입장 시 플레이어의 진행 플래그에 맞는 내부 템플릿을 인스턴스 슬롯에 준비한다. 임시 전투장과 달리 건물의 컨테이너·NPC·개인 상태는 구조물과 분리해 저장한다.

상세 수명주기, 안전 귀환과 상태별 템플릿 전환은 [공용 인스턴스 차원과 상태 변화 건물](INSTANCED_SPACES.md)에서 관리한다.

## 4 이동 오브젝트 흐름

네더 포털 같은 프레임을 반드시 구현할 필요는 없다. 리그 관문, 동굴 입구, 비행 택시, 배, 기차표, 워프석 같은 오브젝트의 상호작용으로 서버가 플레이어를 이동시키는 편이 단순하다.

```text
플레이어가 이동 오브젝트 사용
  → 서버에서 목적지와 진행 조건 확인
  → 탑승 상태와 전투 상태 확인
  → 출발 차원·좌표를 귀환점으로 저장
  → 목적지 청크 준비
  → 안전한 도착 좌표로 순간이동
  → 도착 이벤트와 안내 표시
```

챔피언로드 입장 시에는 관장 승리와 배지를 검사하고, 다음 세대 출구에서는 리그 완료 상태를 검사한다. 잠겨 있으면 이동시키지 않고 필요한 조건을 안내한다.

## 5 필수 안전장치

- 도착 지점이 막혔거나 제거됐을 때 사용할 예비 좌표를 둔다.
- 서버 재시작 후에도 출발지, 목적지와 귀환점을 복구한다.
- 사망 시 해당 지역 시작점, 마지막 체크포인트 또는 오버월드 중 하나로 일관되게 보낸다.
- 탈것, 승객과 Cobblemon 동행 상태를 이동 전후에 검증한다.
- 전투 중, 추락 중, 재사용 대기시간 중 이동 악용을 차단한다.
- 목적지 청크가 준비되기 전에 플레이어를 배치하지 않는다.
- 같은 오브젝트를 연속 사용해 차원 왕복 루프가 발생하지 않게 한다.
- 목적지 종류에 따라 영역 보호, 허용 행동과 자원 프로필을 적용하고 재접속 시 재검증한다.

## 6 포켓몬 스폰 연동

Cobblemon 스폰 조건의 `dimensions`에 커스텀 차원 ID를 지정할 수 있다. 따라서 같은 바이옴을 사용해도 각 세대 차원과 전환 차원의 포켓몬 풀을 완전히 분리할 수 있다.

전환 차원 안에서 세대별 챔피언로드 스폰을 다시 나누려면 좌표 범위, 구조물, Y좌표, 광량, 하늘 노출과 주변 블록 조건을 조합한다.

## 7 세대별 월드와 리그 전환 차원

### 7.1 기본 진행 구조

세대 하나를 일반 오버월드와 유사한 독립 차원으로 구성하고, 각 세대의 마지막에는 전환 차원에 있는 챔피언로드와 리그를 둔다.

```text
1세대 월드
  → 1세대 챔피언로드
  → 1세대 리그
  → 사천왕·챔피언 격파
  → 2세대 월드 해금
  → 2세대 챔피언로드와 리그
  → 사천왕·챔피언 격파
  → 3세대 월드 해금
```

각 세대 월드는 평원, 숲, 산과 바다를 가진 일반 월드 지형을 기반으로 한다. 플레이어는 서바이벌 모드지만 서버 권한이 일반 지형 훼손을 막고 허용 작물·광물만 채집하게 한다. 포켓몬 스폰 프로필, 도시 구조물, 주요 랜드마크와 일부 바이옴 가중치로 세대의 개성을 만든다.

### 7.2 물리 차원 수

모든 세대와 리그를 각각 별도 차원으로 만들면 지원 세대가 N개일 때 세대 차원 N개와 리그 차원 N개가 필요하다. 논리 구조는 단순하지만 서버 월드, 저장, 백업, 청크와 장애 복구 대상이 크게 늘어난다.

권고안은 세대 월드는 각각 독립 차원으로 유지하고 모든 챔피언로드와 리그는 하나의 `transition` 차원 안에 서로 멀리 떨어진 구역으로 구성하는 것이다.

```text
generation_1 ... generation_N  # 세대별 독립 차원
transition                     # 세대별 챔피언로드와 리그 구역
```

플레이어에게는 각 챔피언로드와 리그가 독립된 지역처럼 보이며, 구현상으로는 좌표 셀과 보호 경계로 분리한다. 특정 리그에 완전히 다른 시간·중력·월드 규칙이 필요할 때만 별도 차원으로 승격한다.

### 7.3 지형 시드 주의

모든 세대 차원이 동일한 월드 시드, `minecraft:overworld` 노이즈 설정과 같은 바이옴 소스를 사용하면 지형이 서로 동일하거나 매우 비슷하게 재현될 수 있다.

이를 방지하려면 다음 중 하나가 필요하다.

- 코어 모드가 세대 ID를 반영한 차원별 시드 솔트를 적용한다.
- 세대별로 서로 다른 노이즈·바이옴 분포 리소스를 사용한다.
- 세대 월드를 서로 다른 고정 시드로 미리 생성해 배포한다.

첫 프로토타입에서는 동일 지형이어도 차원 이동과 스폰 분리가 작동하는지만 확인하고, 정식 월드 생성 전에 차원별 시드 분리를 구현한다.

### 7.4 세대별 포켓몬 스폰

각 스폰 파일의 `dimensions` 조건에 세대 차원 ID를 지정한다.

```text
cobbleventure:generation_1
cobbleventure:generation_2
...
cobbleventure:generation_N
cobbleventure:transition
```

기본 Cobblemon 스폰 파일에 차원 제한이 없으면 동일한 바이옴을 사용하는 모든 세대 차원에 그대로 적용될 수 있다. 완전한 세대별 분리가 필요하면 기본 스폰 풀을 필터링하고 프로젝트가 생성한 스폰 파일로 대체한다. 포켓몬 수만큼 JSON을 손으로 관리하지 않고 다음 입력표에서 데이터 생성기로 스폰 파일을 생성한다.

기존 서식지 규칙을 보존하면서 세대 차원을 주입하는 변환 과정은 [포켓몬 스폰 프로필](POKEMON_SPAWNS.md)에서 별도로 다룬다.

| 필드 | 설명 |
|------|------|
| `pokemon` | 포켓몬 ID |
| `native_generation` | 원래 등장 세대 |
| `world_profiles` | 출현 가능한 세대 월드 목록 |
| `biome_tags` | 허용 바이옴 태그 |
| `habitat` | 지상, 동굴, 수중 등 |
| `rarity`, `weight` | 희귀도와 풀 내부 가중치 |
| `level_range` | 해당 월드의 레벨 범위 |

세대 월드를 해당 세대 포켓몬만 존재하는 폐쇄형으로 만들지, 이전 세대 포켓몬까지 누적하는 방식으로 만들지는 별도 게임 디자인 결정으로 남긴다.

### 7.5 챔피언로드와 리그 배치

`transition` 차원을 세대별 리그 구역으로 나눈다. 각 구역은 입구, 챔피언로드, 리그 건물과 다음 세대 출구를 하나의 고정 진행선으로 갖는다.

```text
세대 월드의 리그 관문
  → transition의 해당 세대 입구
  → 챔피언로드·동굴·야생 포켓몬
  → 회복·체크포인트 구역
  → 리그 접수처
  → 사천왕
  → 챔피언
  → 전당 등록
  → 다음 세대 월드 출구
```

챔피언로드와 리그 건물은 무작위 위치를 탐색하게 하지 않고 고정 앵커에 배치한다. 길의 장식, 샛길과 일부 방만 직소 구조물로 변주하고 필수 통로와 출구는 항상 연결되게 한다.

각 리그 구역은 서로 충분히 떨어뜨리고 다음 항목을 별도로 정의한다.

| 필드 | 설명 |
|------|------|
| `league_id` | 세대별 리그 식별자 |
| `generation_id` | 완료 대상 세대 |
| `bounds` | 챔피언로드와 리그 전체 경계 |
| `entry_anchor` | 세대 월드에서 들어오는 좌표 |
| `checkpoint_anchor` | 패배·사망 시 복귀 좌표 |
| `league_anchor` | 리그 건물 기준 좌표 |
| `next_world_anchor` | 다음 세대 시작 마을 도착 좌표 |
| `spawn_profile` | 챔피언로드 야생 포켓몬 구성 |

### 7.6 리그 완료와 다음 세대 해금

리그 건물을 발견하거나 출구에 도달한 것만으로 다음 세대를 해금하지 않는다. 서버가 사천왕과 챔피언의 승리 기록을 확인한 뒤 플레이어별 해금 상태를 기록한다.

```text
챔피언로드 입장
  → 리그 도전 자격과 배지 확인
  → 리그 체크포인트 갱신
  → 사천왕 승리 기록
  → 챔피언 승리 확인
  → 전당 등록
  → generation_N 해금 기록
  → 출구 오브젝트 활성화
  → 다음 세대 시작 거점으로 이동
```

명령어, 다른 모드의 워프 또는 관리자 이동으로 잠긴 세대에 들어오는 우회를 막으려면 차원 진입 시에도 해금 상태를 검사한다. 잠긴 플레이어는 마지막 허용 체크포인트로 돌려보낸다.

멀티플레이에서는 실제 공용 문이나 레드스톤 장치만으로 사천왕 진행을 막지 않는다. 다른 플레이어가 연 문을 따라가는 우회가 가능하기 때문이다. 각 방 입구와 출구에서 플레이어별 승리 상태를 검사하고, 조건을 충족한 플레이어만 통과·순간이동시키는 방식으로 구현한다.

사천왕과 챔피언 NPC, 문과 구조물은 모두에게 공유하되 다음 상태는 플레이어별로 관리한다.

- 리그 도전 자격과 요구 배지
- 현재 사천왕 진행 순서
- 각 트레이너 승리 여부
- 도전 중 패배·이탈 여부
- 챔피언 승리와 전당 등록
- 다음 세대 월드 해금 여부

### 7.7 확정 아키텍처 적용안

- 세대별 월드는 독립 차원으로 만든다.
- 전환·리그 차원과 세대별 월드는 서바이벌 모드를 유지하고 영역별 서버 보호를 적용한다.
- 필드 작물과 특수 던전 광물은 명시된 자원 노드만 수확·채굴할 수 있다.
- 시작 마을의 집 PC는 공유 농장 차원의 개인 1청크 플롯으로 연결한다.
- 농장에서는 규토리·나무열매 재배와 제한된 꾸미기만 허용한다.
- 임시 전투·컷신과 상태 변화 건물 내부에는 공용 인스턴스 차원 패턴을 검토한다.
- 세대별 챔피언로드와 리그는 하나의 공유 `transition` 차원에 좌표 구역으로 배치한다.
- 세대별 월드는 일반 오버월드 생성기를 기반으로 하되 정식 배포 전 시드 솔트를 분리한다.
- 포켓몬 스폰 데이터는 차원 ID를 기준으로 자동 생성한다.
- 다음 세대 해금은 월드 공용이 아니라 플레이어 개인 상태로 관리한다.
- 챔피언로드, 리그와 출구는 고정 앵커로 보장하고 필수 진행선에는 무작위 단절이 없게 한다.

## 8 프로토타입 범위

1. `generation_1`, `generation_2`, `transition` 시험 차원을 데이터팩으로 등록한다.
2. 기존 오버월드 생성기 설정을 재사용해 차원 로딩만 검증한다.
3. 관리자 명령으로 세 차원의 왕복 이동과 재접속을 검증한다.
4. 1세대와 2세대에 서로 다른 포켓몬 각 3종의 스폰 파일을 적용한다.
5. 전환 차원에 작은 챔피언로드, 임시 리그와 고정 출구 장치를 배치한다.
6. 임시 챔피언 승리 시 플레이어별 `generation_2` 해금 상태를 기록한다.
7. 잠긴 상태의 우회 진입, 귀환, 사망과 서버 재시작을 검증한다.
8. 두 세대 차원의 지형이 겹치는지 확인하고 차원별 시드 분리 방식을 결정한다.
9. 시작 집 PC에서 시험 개인 농장으로 왕복하고 게임 모드와 귀환점을 검증한다.
10. 공용 공허 차원에서 임시 전투장 슬롯 하나의 생성·입장·정리·복귀를 검증한다.

독자적인 노이즈 지형과 플레이어별 인스턴스 차원은 이 프로토타입에 포함하지 않는다.

## 9 미결정 사항

- 세대 차원을 자동 생성 월드로 할지 고정 제작 월드로 할 것인가?
- 일반 탐험 동굴과 챔피언로드를 같은 전환 차원에 둘 것인가?
- 목적지 해금은 플레이어 개인 상태인가, 서버 공용 상태인가?
- 이동 오브젝트는 블록, NPC, 아이템 또는 구조물 중 무엇인가?
- 귀환점과 사망 지점 규칙을 어떻게 정의할 것인가?
- 퍼즐용 블록 파괴·설치 예외를 어느 구역에서 허용할 것인가?
- 세대별 스폰은 해당 세대 전용인가, 이전 세대 누적인가, 생태 기반 혼합인가?
- 세대별 리그를 공유 차원의 좌표 구역으로 유지할지 별도 차원으로 분리할 것인가?
- 리그 도중 회복, 파티 교체, 이탈과 재도전 규칙을 어떻게 정할 것인가?
- 차원별 지형 시드 솔트를 데이터팩과 코어 모드 중 어디에서 관리할 것인가?
