# 체육관 제작 가이드

이 문서는 체육관 외관, 내부 모듈, 관장 NPC를 제작하고 게임에 반영하는 작업 순서를
설명한다. 평소 작업은 JSON이나 NBT 파일을 직접 편집하지 않고 **웹 관리 화면에서
시작하는 방식**을 권장한다.

## 가장 먼저 알아둘 구조

체육관도 일반 건물과 같은 내부공간 라이브러리를 사용한다.

```text
마을
  └─ 체육관 선택 + 관장 선택
       └─ 체육관
            ├─ 공용 외관 base_gym
            └─ 공용 내부공간 NBT 1개 이상
```

- 외관은 모든 체육관이 `base_gym.nbt` 하나를 공유한다.
- 체육관별 차이는 웹에서 선택한 속성 테마 색상으로 표현한다.
- 내부는 웹 `NBT 건물 설정`에서 공용 내부공간 NBT를 선택한다.
- 관장은 내부 모듈의 `leader` 위치에 생성된다.

따라서 새 체육관을 만들 때 외관이나 내부 NBT를 체육관 전용으로 복사하지 않는다.
필요한 내부공간을 공용 라이브러리에 만들고 일반 건물과 같은 방법으로 연결한다.

## 권장 작업 흐름

```text
웹에서 모듈 생성·연결
        ↓
건축 월드 빌드 및 실행
        ↓
인게임에서 건축·앵커 지정·저장
        ↓
웹에서 자동 가져오기·미리보기
        ↓
검사 후 mod-bootstrap 빌드
```

웹은 이름, 크기, 층수, 체육관 연결처럼 실수하기 쉬운 데이터를 관리한다. 인게임은
블록 배치와 실제 위치 지정만 담당한다. 이 역할을 나누면 파일명과 리소스 ID가
어긋나거나 관장 위치를 좌표로 직접 계산하는 일을 줄일 수 있다.

## 웹 최초 설정

처음 한 번만 `빌드 및 검사 → 독립 건축 월드`에서 CurseForge 건축 프로필 인스턴스
경로를 지정하고 `경로 저장`을 누른다. 이후에는 웹이 다음 위치를 자동으로 찾는다.

- 건축 월드: `<인스턴스>/saves/Cobbleventure Structure Builder`
- 게임에서 내보낸 NBT
- 저장소가 관리하는 NBT

경로가 정상이라면 화면의 건축 팩, 건축 월드, 내보낸 NBT, 저장소 NBT 상태가
표시된다. 이후 팩을 수동으로 복사하지 말고 `건축 팩 빌드`, `게임 NBT 자동 가져오기`,
`상태 새로고침` 버튼을 사용한다.

## 기존 체육관 내부 수정하기

### 1. 웹에서 대상 확인

1. 콘텐츠 관리 웹을 실행한다.
2. 왼쪽 메뉴에서 `체육관 관리`를 연다.
3. 수정할 체육관을 선택한다.
4. 체육관에 연결된 `내부 모듈` 이름을 확인한다.
5. 아래 `체육관 내부 모듈 관리`에서 해당 모듈의 `미리보기`를 눌러 현재 NBT와
   `leader` 위치를 확인한다.

미리보기를 먼저 확인하면 잘못된 체육관의 내부를 편집하는 일을 방지할 수 있다.

### 2. 건축 월드 열기

1. `건축 월드로 이동`을 누른다.
2. 건축 월드 빌드를 실행한다.
3. 화면에 설정된 건축 월드 인스턴스를 실행한다.
4. 인게임에서 다음 명령으로 편집 가능한 내부 목록을 확인한다.

```mcfunction
/cobbleventure_builder interior list
```

5. 웹에서 확인한 모듈 ID로 이동한다.

```mcfunction
/cobbleventure_builder interior tp <모듈_ID>
```

### 3. 내부 건축과 관장 위치 지정

블록과 장식은 자유롭게 수정한다. 관장이 설 위치는 좌표를 입력하지 않고 전용 도구로
지정한다.

```mcfunction
/cobbleventure_builder tool leader
```

명령 실행 후 관장이 설 바닥을 편집 막대기로 우클릭한다. 이 위치는
`npc_position` 라벨 `leader`로 메타데이터에 기록된다.

체육관 전체에는 `leader`가 정확히 하나만 있어야 한다. 여러 내부 모듈을 사용하더라도
그중 하나에만 지정한다.

### 4. 저장하고 웹으로 가져오기

```mcfunction
/cobbleventure_builder interior save <모듈_ID>
```

저장 후 웹의 빌드 화면에서 `게임 NBT 자동 가져오기`를 실행한다. 가져오기는 NBT와 앵커
메타데이터를 함께 갱신한다. 완료되면 다시 `체육관 관리`로 돌아와 `미리보기`에서
다음을 확인한다.

- 건축한 블록이 최신 상태인지
- 크기와 층수가 의도한 값인지
- `leader` 좌표가 표시되는지
- 현재 모듈이 올바른 체육관에 연결되어 있는지

## 새 내부 모듈 추가하기

내부를 늘릴 때는 파일을 직접 복사하지 말고 웹에서 빈 모듈을 만든다.

1. `체육관 관리`에서 사용할 체육관을 먼저 선택한다.
2. `체육관 내부 모듈 관리`에 모듈 ID, 너비, 깊이, 층 높이, 층수를 입력한다.
3. `빈 모듈 만들기`를 누른다.
4. 생성된 모듈 카드에서 `현재 체육관에 추가`를 누른다.
5. 체육관 설정을 저장한다.
6. 건축 월드를 다시 빌드하고 인게임에서 모듈을 편집한다.
7. 저장 후 웹의 `게임 NBT 자동 가져오기`를 실행한다.

새 모듈은 벽, 바닥, 천장과 출입구만 있는 빈 상자로 생성된다. 기존 모듈이 있는
체육관에 추가하면 웹이 기존 공간과 겹치지 않도록 뒤쪽 Z 좌표에 우선 배치한다.
필요하면 모듈 카드에서 위치와 회전을 조정한다.

### 크기와 층수 선택 기준

처음부터 큰 공간 하나를 만드는 것보다 역할별 모듈로 나누는 편이 관리하기 쉽다.

| 용도 | 권장 구성 |
| --- | --- |
| 작은 체육관 | 로비와 경기장을 한 모듈에 구성 |
| 퍼즐 체육관 | 입구, 퍼즐, 경기장을 각각 분리 |
| 여러 층 체육관 | 층별 모듈 또는 층수가 지정된 단일 모듈 사용 |
| 확장 예정 체육관 | 시작 모듈을 작게 만들고 나중에 모듈 추가 |

웹의 너비와 깊이는 NBT 작업 영역 자체의 크기다. 장식과 이동 공간을 고려해 필요한
크기보다 약간 여유 있게 만든다. 이미 건축한 모듈의 크기를 억지로 변경하기보다 새
모듈을 추가하는 방식을 권장한다.

## 새 체육관 추가하기

1. 웹 `체육관 관리`에서 체육관을 추가한다.
2. 이름과 속성 테마를 지정한다.
3. `체육관 내부 모듈 관리`에서 시작 모듈을 만들고 연결한다.
4. 내부 모듈에 `leader` 위치를 하나 지정한다.
5. 웹 `마을 프리셋`에서 마을을 연다.
6. 해당 마을의 체육관을 먼저 선택한다.
7. 그 체육관에 배치할 관장을 선택한다.
8. 콘텐츠 검사를 실행하고 저장한다.

마을 설정 순서는 항상 다음과 같다.

```text
마을 → 체육관 → 관장
```

체육관 외관과 내부는 재사용할 수 있지만, 관장은 마을에 배정되는 값이다. 같은 체육관
정의를 다른 마을에서 사용하더라도 서로 다른 관장을 선택할 수 있다.

## 외관 수정하기

모든 체육관 외관은 `base_gym.nbt` 하나를 공유한다. 외관 형태를 바꾸면 전체 체육관에
반영되므로, 웹 미리보기에서 여러 속성 테마로 확인한 뒤 저장한다.

색상 표식 블록은 다음과 같다.

| 표식 블록 | 용도 |
| --- | --- |
| `minecraft:light_gray_concrete` | 주 색상 |
| `minecraft:yellow_concrete` | 보조 색상 |
| `minecraft:orange_stained_glass_pane` | 유리 색상 |

런타임은 이 세 블록만 테마 색상으로 치환한다. 내부를 검은 블록으로 채우거나 외관을
자동으로 밀폐하지 않는다. 외부에서 내부가 보이지 않게 할 벽과 차폐는 `base_gym`에
직접 건축해야 한다. 출입문도 철문으로 자동 교체하지 않는다.

## 웹에서 마지막으로 확인할 항목

빌드하기 전에 웹을 단순 설정 화면이 아니라 검수 도구로 사용한다.

1. `체육관 관리`에서 각 체육관의 외관 테마를 미리 본다.
2. 내부 모듈 라이브러리에서 `사용` 항목으로 미연결 모듈을 찾는다.
3. 각 체육관의 모듈 목록에서 위치가 겹치지 않는지 확인한다.
4. 내부 미리보기에서 `leader` 좌표가 있는지 확인한다.
5. `마을 프리셋`에서 체육관과 관장 연결을 확인한다.
6. 빌드 화면에서 콘텐츠 검사를 실행한다.
7. 오류가 없을 때 `mod-bootstrap`을 빌드한다.

## 자주 발생하는 문제

### 관장이 생성되지 않는다

- 내부 미리보기에 `leader`가 표시되는지 확인한다.
- 관장 위치를 지정한 뒤 `interior save`와 웹 `게임 NBT 자동 가져오기`를 모두
  실행했는지 확인한다.
- 마을 프리셋에 관장이 선택되어 있는지 확인한다.
- 여러 모듈에 `leader`가 중복 지정되지 않았는지 확인한다.

`leader`가 없거나 두 개 이상이면 콘텐츠 검증 오류로 처리한다. 고정 기본 좌표로 대신
배치하지 않는다.

### 웹에서 새 건축 내용이 보이지 않는다

인게임 저장만으로 프로젝트 NBT가 갱신되지는 않는다. 웹 빌드 화면의
`게임 NBT 자동 가져오기`를 실행한 뒤 미리보기를 다시 연다.

### 모듈끼리 겹친다

체육관의 내부 모듈 카드에서 `position`을 조정한다. 회전한 모듈은 너비와 깊이 방향도
바뀌므로 미리보기와 콘텐츠 검사를 함께 사용한다.

### 통로가 자동으로 생기지 않는다

`connections`는 현재 데이터 계약과 검증에 사용한다. 문이나 복도를 자동 건축하지
않으므로 각 NBT의 통로가 실제 배치 좌표에서 맞닿도록 건축해야 한다.

## 개발자 참고

### 저장 위치

- 체육관 정의: `content/catalogs/gyms.json`
- 공용 외관: `content/structures/gyms/base_gym.nbt`
- 내부 모듈: `content/structures/interiors/gyms/*.nbt`
- 내부 메타데이터: `content/structures/interiors/gyms/*.structure.json`
- 리그: `content/structures/league/kanto_league.nbt`
- 스키마: `content/schemas/gym-catalog.schema.json`

### 내부 데이터 예시

```json
{
  "interior": {
    "modules": [
      {
        "id": "lobby",
        "structure": "cobbleventure:interiors/gyms/example_lobby",
        "position": [0, 0, 0],
        "rotation": "none"
      },
      {
        "id": "arena",
        "structure": "cobbleventure:interiors/gyms/example_arena",
        "position": [0, 0, 40],
        "rotation": "clockwise_90"
      }
    ],
    "connections": [
      { "from": "lobby:exit", "to": "arena:entrance" }
    ]
  }
}
```

런타임은 모듈의 위치와 회전을 NBT뿐 아니라 `leader` 좌표에도 적용한다. 관장은 마을의
`leader_trainer_id`에 대응하는 EasyNPC 프리셋으로 생성된다.

### 패키징과 출처

`tools/mod-builder/build_data_mod.py`는 체육관 카탈로그, 외관, 내부 NBT, 내부
메타데이터와 리그 NBT를 생성 리소스에 포함한다.

Radical Gyms & Structures는 실행 모드 의존성으로 사용하지 않는다. 원본 RGS 구조물과
라이선스 고지는 `content/archive/radical-gyms-interiors` 및
`content/structures/THIRD_PARTY.md`에서 관리한다. 게임과 건축 월드는
`cobbleventure:*` 리소스만 참조한다.
