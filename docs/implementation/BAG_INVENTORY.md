# 본가식 가방 인벤토리

> 관련 기능: F-14 본가식 가방 인벤토리
>
> 관련 결정: D-20 가방과 바닐라 인벤토리의 관계
>
> 상위 진입점: [플레이어 메뉴](PLAYER_MENU.md)
>
> 설계 상태: 3안 기준 설계 / 서버 확장 가방 4,096칸·동일 아이템 수량 집계 구현

## 1 목적

기본 Minecraft의 슬롯·핫바 중심 인벤토리 대신 포켓몬 본가처럼 아이템 종류별 포켓으로 나뉜 가방을 제공한다. 플레이어는 인벤토리 키로 [플레이어 카드 메뉴](PLAYER_MENU.md)를 열고 가방을 선택한다. 플레이어는 빈 슬롯을 정리하는 대신 아이템 이름, 분류와 수량을 기준으로 소지품을 관리한다.

```text
아이템 획득
  → 서버가 아이템 분류 확인
  → 대응하는 가방 포켓에 수량 추가
  → 가방 UI에서 검색·정렬·사용
```

가방은 단순한 화면 스킨이 아니다. 소지품의 저장, 획득, 소비, 거래, 사망과 복구를 서버가 관리하는 별도 시스템이다.

### 1.1 1차 화면 구현 범위

현재 구현은 저장 모델을 교체하기 전의 UI·조작 검증 단계다.

- 플레이어 메뉴의 가방 항목에서 B안 화면을 연다.
- 기존 Minecraft 주 인벤토리와 핫바 36칸, 서버 확장 가방 4,096칸을 한 화면에서 탐색한다.
- 전체·회복·몬스터볼·배틀·재료·중요 아이템의 임시 분류를 제공한다.
- `사용`은 서버에서 아이템을 임시 주 손으로 처리한 뒤 원래 슬롯에 결과를 돌려놓는다. 기존 핫바 구성은 바뀌지 않는다.
- `단축키 등록` 또는 숫자키 1~9로 선택 아이템을 원하는 핫바 칸과 교환한다.
- 아이템을 좌·우클릭으로 집고 다른 칸으로 드래그해 이동·교환할 수 있다.
- 아이템 툴팁 설명, 설명 검색, 아이콘·목록 보기 전환과 묶음 버리기 2회 확인을 제공한다.
- 화면 해상도에 따라 보이는 행·열 수를 늘려 더 많은 아이템을 한 번에 보여 준다.
- 페이지 버튼 없이 마우스 휠, 빈 공간 드래그와 스크롤바 드래그로 전체 항목을 연속 탐색한다.
- 비어 있지 않은 항목은 현재 언어의 아이템 이름 기준으로 자동 정렬하고 빈 슬롯은 마지막에 둔다.
- 기본 인벤토리가 가득 차면 월드에서 줍는 아이템을 확장 가방의 같은 스택 또는 빈 슬롯에 자동 수납한다.
- 상점·퀘스트·트레이너 보상은 공용 `BagApi`를 통해 기본 인벤토리와 확장 가방에 원자적으로 지급·조회·차감할 수 있다.
- 상자와 외부 모드 컨테이너 자동 연동, 태그 기반 최종 분류는 다음 단계에서 적용한다.

이 단계에서 사용하는 ID·아이템 속성 기반 분류는 화면 검증용이다. 다음 단계에서는 데이터 태그와 프로젝트 설정을 서버에서 판정하는 분류기로 교체한다.

## 2 기본 포켓 구성

| 포켓 | 주요 아이템 | 기본 규칙 |
|------|-------------|-----------|
| 몬스터볼 | 몬스터볼 계열 | 야생 포획과 전투 UI에서 바로 사용 |
| 회복 | 상처약, 상태 회복, 기력 회복 | 필드와 허용된 전투 상황에서 사용 |
| 배틀 | 능력치 강화, 도핑, 전투용 소비품 | 전투 규칙이 허용할 때만 표시 |
| 나무열매 | 재배·획득한 포켓몬 열매 | 포켓몬 사용, 지니게 하기, 농장 반출 |
| 기술 | 기술머신과 기술 관련 디스크 | 대상 포켓몬과 습득 가능 여부 검사 |
| 중요한 물건 | 배지 연동 키, 비전머신 권한, 퀘스트 물품, 던전 열쇠 | 버리기·판매·거래 금지, 보통 수량 1 |
| 재료 | 규토리, 포켓볼·농장 관련 제작 재료 | 제작 시스템을 유지할 때만 활성화 |
| 장식·건축 | 농장과 허용 공간용 블록·장식 | 2·3안 또는 특정 차원에서만 노출 |

아이템 분류는 하드코딩보다 데이터 태그와 프로젝트 설정으로 관리한다. 분류되지 않은 모드 아이템은 임시 `기타` 포켓에 들어가며 운영 로그에 남겨 누락된 정의를 찾을 수 있게 한다.

## 3 저장 모델

가방의 원본 데이터는 서버가 플레이어별 영속 NBT로 저장한다. 현재 확장 가방은 4,096개의 희소 `ItemStack` 슬롯을 가지며 일반 64개 스택 아이템 한 종류를 약 26만 개까지 보관할 수 있다. 이는 플레이 관점에서 사실상 수량 제한이 없는 용량으로 취급한다.

```text
BagInventory
  player_uuid
  revision
  pockets
    pocket_id
    item_id
    component_fingerprint
    quantity
  selected_shortcuts
  migration_version
```

- 동일 아이템 ID라도 내구도, 커스텀 데이터, 이름과 컴포넌트가 다르면 별도 항목으로 취급한다.
- 같은 아이템과 데이터 컴포넌트를 가진 내부 스택은 UI에서 하나의 항목으로 합치고 정확한 총수량을 표시한다.
- Minecraft·Cobblemon 호환을 위해 내부 `ItemStack`은 원래 최대 스택 크기를 지킨다. 핫바로 꺼낼 때도 한 번에 한 바닐라 스택만 이동한다.
- 슬롯 번호와 전체 데이터 컴포넌트를 함께 저장하므로 정렬과 커스텀 아이템 정보가 재접속·사망 후에도 유지된다.
- 일반 아이템에는 별도의 아이템별 최대 수량을 적용하지 않는다. 4,096개 내부 슬롯의 전체 물리 용량만 안전 한계로 사용한다.
- 중요한 물건은 중복 획득 시 수량을 늘리지 않고 이미 보유 중이라는 결과를 반환한다.
- 획득과 소비는 원자적 트랜잭션으로 처리해 재접속·동시 클릭·차원 이동 중 복제를 막는다.
- 저장 데이터에는 버전을 기록해 아이템 분류와 모드 구성이 바뀌어도 마이그레이션할 수 있게 한다.

## 4 UI와 조작

가방 화면은 다음 기능을 기본으로 한다.

- 포켓 탭 이동
- 이름·설명 검색
- 종류, 이름, 최근 획득과 수량 정렬
- 사용, 포켓몬에게 사용, 지니게 하기, 등록, 상세 보기
- 중요한 물건의 진행 조건과 현재 사용 가능 위치 표시
- 자주 쓰는 아이템을 퀵슬롯 또는 카드 메뉴 즐겨찾기에 등록
- 키보드·마우스뿐 아니라 게임패드로 모든 조작 가능

화면을 닫은 상태에서는 퀵슬롯으로 포켓몬 소환, 몬스터볼 선택, 등록된 중요 아이템과 귀환 도구를 사용한다. 3안에서는 Minecraft의 전체 인벤토리를 숨기고 9칸 핫바를 가방 퀵슬롯 표현으로 재사용할지를 프로토타입으로 결정한다.

### 4.1 현재 조작

| 조작 | 결과 |
|------|------|
| `사용` / Enter | 핫바를 변경하지 않고 선택 아이템을 즉시 사용 |
| `단축키 등록` | 현재 선택된 핫바 칸에 아이템 등록 |
| 숫자키 1~9 | 지정한 핫바 칸에 바로 등록 |
| 좌·우클릭 후 드래그 | 실제 인벤토리 묶음 규칙으로 슬롯 이동·교환 |
| `버리기` 2회 | 선택 묶음 전체를 월드에 버림 |
| `V` / 보기 버튼 | 아이콘 보기와 목록 보기 전환 |
| 휠 / 빈 공간 드래그 | 가방 항목을 행 단위로 연속 스크롤 |
| 우측 스크롤바 드래그 | 항목이 많을 때 원하는 위치로 빠르게 이동 |

블록 배치처럼 월드의 대상 위치가 필요한 아이템은 가방 안의 즉시 사용보다 단축키 등록 후 필드에서 사용하는 것을 기준으로 한다.

아이콘 보기에서는 좁은 칸에 아이콘과 축약 수량을 표시한다. 목록 보기에서는 한 행에 아이콘, 현지화 이름과 정확한 합산 수량을 함께 표시한다. 두 보기 모두 같은 연속 스크롤 위치를 사용한다. 좌클릭 아이템 드래그는 내부 한 묶음 이동·합치기·교환, 우클릭 아이템 드래그는 한 개 이동으로 처리한다. 포켓 필터나 검색 중에는 빈 슬롯을 숨기므로 빈 칸으로 옮길 때는 `전체` 포켓에서 조작한다.

## 5 아이템 유입과 사용 경로

모든 아이템 경로가 가방 API를 사용해야 한다.

| 경로 | 처리 |
|------|------|
| 월드 드롭 획득 | 자동으로 대응 포켓에 추가하고 남은 드롭만 월드에 유지 |
| NPC·상점 구매 | 결제와 가방 추가가 모두 성공할 때만 거래 확정 |
| 트레이너·퀘스트 보상 | 공간·수량 검사 후 지급하고 결과 기록 |
| 농장 수확 | 열매·재료 포켓으로 직접 이동 |
| 전투 사용 | 전투 서버가 가방 수량을 예약한 뒤 행동 확정 시 소비 |
| 제작 | 재료를 예약·차감한 뒤 결과 아이템 추가 |
| 상자·우편·거래 | 양쪽 저장소 간 원자적 이동 |
| 관리자 명령 | 일반 획득과 같은 검사를 거치고 감사 로그 기록 |

### 5.1 서버 지급 API

상점·퀘스트·전투 보상 구현은 바닐라 `Inventory.add`를 직접 호출하지 않고 다음 진입점을 사용한다.

```java
BagApi.InsertResult result = BagApi.insert(player, rewardStack, true);
if (!result.complete()) {
    // 전량 지급이 불가능하므로 거래나 보상 확정을 취소한다.
}

int owned = BagApi.count(player, requiredItem);
boolean consumed = BagApi.remove(player, requiredItem, requiredAmount);
```

- `insert(..., true)`는 전체 수량이 들어갈 때만 변경하는 거래·퀘스트용 원자적 지급이다.
- `insert(..., false)`는 들어갈 수 있는 만큼 지급하고 나머지를 결과로 돌려준다.
- `count`와 `remove`는 기본 36칸과 확장 4,096칸을 하나의 소지품으로 계산한다.
- 운영자 테스트 명령은 `/cobbleventurebag give <targets> <item> [count]`다.

아이템 엔티티를 바로 삭제한 뒤 나중에 저장하지 않는다. 가방 추가 성공이 확인된 후에만 월드 드롭을 제거해야 아이템 유실을 막을 수 있다.

## 6 아키텍처별 적용

### 6.1 1안 순수 어드벤처

가방이 플레이어의 주 인벤토리를 완전히 대체한다. 블록 설치·파괴와 일반 장비 사용이 없으므로 바닐라 제작창, 방어구 슬롯과 전체 인벤토리는 숨기거나 비활성화한다. 퀵슬롯에는 포켓몬 플레이에 필요한 등록 아이템만 둔다.

### 6.2 2안 서바이벌 격자

건축, 채집과 일반 모드 아이템 때문에 바닐라 슬롯 개념을 완전히 제거하기 어렵다. 다음 두 후보를 프로토타입으로 비교한다.

1. 포켓몬 아이템은 가방, 블록·도구·장비는 별도의 `서바이벌 파우치`로 분리
2. 가방 UI 안에 블록·도구 포켓과 장비 슬롯까지 통합

첫 후보가 기존 모드 컨테이너와 자동화 호환성이 높다. 두 번째 후보는 경험이 일관되지만 모든 제작대, 상자, 장비와 모드 API를 연결해야 하므로 개발 위험이 크다.

### 6.3 3안 하이브리드

세대 보호형 서바이벌 월드에서도 가방을 주 인벤토리로 사용한다. 필드 작물 수확과 던전 광물 채굴에 필요한 허용 도구는 퀵슬롯의 임시 사용 슬롯으로 꺼낸다. 개인 농장에서는 열매·규토리·허용 도구·장식 포켓만 열고 금지된 블록과 아이템은 꺼낼 수 없게 한다.

차원을 이동할 때 인벤토리를 복사하거나 교체하지 않는다. 같은 서버 가방 데이터에서 현재 차원이 허용한 포켓과 행동만 노출해 아이템 유실과 복제 가능성을 줄인다.

## 7 바닐라·모드 호환 경계

Minecraft와 다른 모드는 플레이어 인벤토리의 실제 `ItemStack`을 직접 검사하는 경우가 많다. 따라서 가방에만 존재하는 아이템을 모든 모드가 자동으로 인식할 것이라고 기대할 수 없다.

필요한 호환 계층은 다음과 같다.

- 손에 들어야 사용하는 아이템을 위한 임시 사용 슬롯
- 제작대와 레시피가 가방 재료를 조회·예약·소비하는 연동 API
- 상점, NPC, 퀘스트와 전투 모드용 가방 조회·소비 API
- 장비, 액세서리와 포켓몬 지닌물건 전용 슬롯
- 상자, 셜커 상자와 다른 저장 모드로 이동할 때의 필터와 거래 화면
- 분류되지 않거나 직렬화할 수 없는 아이템을 격리하는 복구함

초기 구현에서는 지원 대상을 프로젝트 핵심 아이템과 필수 모드로 제한한다. 임의의 모든 모드 아이템을 처음부터 완벽히 지원하려 하지 않는다.

## 8 사망·드롭·거래 규칙

- 세대·던전·리그 월드에서 가방 아이템은 사망 시 드롭하지 않는 것을 기준안으로 삼는다.
- 전투 패배 페널티가 필요하면 아이템 분실 대신 화폐 차감, 체크포인트 귀환 또는 일부 소모품 비용을 사용한다.
- 중요한 물건, 배지, 비전머신 권한과 퀘스트 물품은 어떤 경우에도 드롭·판매·거래할 수 없다.
- 일반 아이템의 플레이어 간 거래는 별도 확인 UI와 서버 트랜잭션을 사용한다.
- 바닥에 버리기는 기본 비활성화하고, 허용 아이템만 수량 선택 후 버릴 수 있게 한다.
- 관리자에게 가방 조회, 지급, 회수, 복구와 변경 이력 확인 명령을 제공한다.

## 9 마이그레이션

기존 플레이어의 바닐라 인벤토리를 처음 변환할 때 다음 순서를 사용한다.

```text
접속 잠금
  → 기존 인벤토리 백업
  → 각 ItemStack 분류·변환
  → 변환 불가 항목을 복구함으로 이동
  → 가방 저장 성공 확인
  → 기존 슬롯 정리
  → 변환 보고서 저장 후 접속 허용
```

변환은 플레이어별로 한 번만 실행하고 원본 백업과 마이그레이션 버전을 남긴다. 실패 시 기존 인벤토리를 지우지 않고 전체 과정을 되돌린다.

## 10 프로토타입 합격 기준

- 드롭, 상점, 보상과 관리자 지급이 올바른 포켓에 중복 없이 들어간다.
- 검색, 정렬, 수량 선택, 사용과 퀵슬롯 등록이 키보드·마우스와 게임패드에서 동작한다.
- 전투 아이템은 행동 확정 시 정확히 한 번만 소비된다.
- 중요한 물건을 버리거나 판매하거나 다른 플레이어에게 넘길 수 없다.
- 차원 이동과 서버 재시작 후 가방 상태가 유지된다.
- 가방이 가득 찼거나 저장이 실패했을 때 월드 드롭과 구매 아이템이 사라지지 않는다.
- 동시 클릭, 재접속과 패킷 재전송으로 아이템을 복제할 수 없다.
- 기존 인벤토리 변환 실패 시 원본 백업으로 복구할 수 있다.
- 선택한 아키텍처에서 제작대, 상자, 장비와 핵심 의존 모드의 호환 테스트가 통과한다.
