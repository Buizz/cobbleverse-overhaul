# 무지하 차원의 안전 기반층

## 목적

`starter_plains` 아래가 공허인 구조는 유지하되, 청크 경계·블록 갱신·생성 오류로 플레이어가 공허로 빠지지 않도록 최소 10층의 기반암과 낙하 복구 장치를 둔다.

- 관련 기능: `WORLD-SAFETY-01`
- 결정: `DEC-WORLD-018` — 표면 높이를 유지하고 Y=55~64를 10층 기반암으로 만든다.
- 상태: 구현 예정

## 표준 수직 단면

| Y 범위 | 블록 | 층수 |
|---|---|---:|
| 69 이상 | 공기·건축물·장식 | 가변 |
| 68 | 잔디 블록 | 1 |
| 65~67 | 흙 | 3 |
| 55~64 | 기반암 | 10 |
| 0~54 | 공기(공허) | 55 |

기존 표면 Y=69와 마을·플레이어 앵커 높이를 유지하므로 구조물 좌표를 불필요하게 이동하지 않는다. “10칸 정도”는 구현과 테스트가 모호하지 않도록 정확히 10층으로 고정한다.

## 안전 규칙

- 모든 지형 청크가 동일한 10층 기반암을 생성한다.
- 구조물 프로세서가 Y=55~64를 공기로 교체할 수 없게 한다.
- 벽, 관문, 건물 기초 작업도 안전층을 관통하지 않는다.
- 월드 생성 검증기가 각 준비 청크의 표본 열과 경계 열을 검사한다.
- 플레이어가 Y<54에 도달하면 마지막 안전 체크포인트로 복귀시키는 서버측 failsafe를 둔다.
- 복귀 시 원인 좌표와 차원, 플레이어를 로그에 남기고 연속 발동을 제한한다.

낙하 복구는 기반암을 대신하는 기능이 아니라 예외 상황의 마지막 보호 장치다.

## 마이그레이션

기존 생성 청크는 1층 기반암 상태이므로 데이터팩 또는 모드만 교체해도 자동으로 10층이 되지 않는다. 첫 구현은 생성 버전을 올리고 새 테스트 월드를 사용한다. 기존 월드 보존이 필요해지면 별도의 제한 범위 보강 명령을 설계한다.

## 테스트

1. 마을 내부, 주변 바이옴, 벽, 네 모서리의 청크를 선택한다.
2. 각 청크에서 Y=55~64가 모두 기반암인지 검사한다.
3. Y=54와 Y=65가 각각 공기와 흙인지 검사한다.
4. 구조물 배치 뒤에도 기반암 수가 줄지 않았는지 재검사한다.
5. 강제로 Y=53에 이동해 체크포인트 복구와 로그를 확인한다.
6. 서버 재시작 후 동일한 결과인지 확인한다.

## 완료 기준

- 준비된 모든 청크에 연속 10층 기반암이 존재한다.
- 플레이어와 NPC가 정상적인 게임 동작만으로 안전층 아래로 내려갈 수 없다.
- 예외 낙하 시 체크포인트로 복구되며 무한 텔레포트가 발생하지 않는다.
- 기존 표면 Y와 시작 마을 구조물 높이가 유지된다.
