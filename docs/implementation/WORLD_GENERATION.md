# 세대 월드 8지역 및 체육관 도시 생성

> 관련 요구사항: F-01, F-06, F-07
>
> 적용 후보: 1안 어드벤처, 3안 하이브리드
>
> 설계 상태: 후보 내부 방향 확정 / 최종 아키텍처 미정

## 1 목적

세대 월드 하나를 시작 지역부터 8번째 지역까지 순서대로 연결된 탐험 구조로 만든다. 각 지역은 설정에 지정된 바이옴 풀, 체육관 도시와 제한된 연결 통로를 가지며, 8번째 지역을 완료하면 리그 전환 차원으로 가는 포탈이 활성화된다.

세대 월드는 `ADVENTURE` 모드 전용으로 운영한다. 1안에서는 채광·건축과 별도 서바이벌 공간을 완전히 제외하고, 3안에서만 시작 마을의 플레이어 집 PC를 통해 별도 서바이벌 공간으로 이동한다.

```text
지역 1 → 지역 2 → 지역 3 → 지역 4
  → 지역 5 → 지역 6 → 지역 7 → 지역 8
  → 리그 포탈 → transition의 해당 세대 챔피언로드·리그
```

## 2 확정된 월드 구성

- 세대 월드마다 탐험 지역은 8개다.
- 각 지역에는 하나의 대표 체육관 도시가 있다.
- 체육관 도시는 체육관, 마을, 상점, 회복 시설과 영구 NPC를 하나의 경계로 묶는다.
- 각 지역은 하나 이상의 허용 바이옴 목록을 가진다.
- 지역 사이의 이동은 설정에 정의된 관문·도로·터널·다리·항구 등으로 제한한다.
- 지역 8 완료 전에는 해당 세대의 리그 포탈을 사용할 수 없다.
- 전역 고정 좌표 목록과 일정 간격의 랜드마크 격자는 사용하지 않는다.
- 세대 월드 진입 시 플레이어를 어드벤처 모드로 전환하고 임의 블록 파괴·설치를 금지한다.
- 경계 우회는 어드벤처 모드뿐 아니라 서버 측 지역 좌표와 관문 통과 검사로 차단한다. 단, 정상적인 공중날기 비전머신 탑승은 지역 경계 예외로 인정한다.
- 시작 마을의 플레이어 집에는 별도 서바이벌 공간으로 이동하는 PC를 둔다.

## 3 이 후보에서 사용하지 않는 배치안

다음 방식은 1안과 3안에서 사용하지 않는다. 프로젝트 전체에서 폐기된 것은 아니며, 격자 배치는 [세대 월드 아키텍처 3안 비교](WORLD_ARCHITECTURE_OPTIONS.md)의 2안에서 유지한다.

| 폐기안 | 폐기 이유 |
|--------|-----------|
| `(1000, 1000)` 같은 전역 고정 좌표 | 지형·바다·다른 구조물과 충돌하고 지역 진행 구조를 표현하기 어려움 |
| 일정 청크 간격의 랜드마크 격자 | 지역 순서보다 공간 규칙이 우선되어 플레이 동선을 통제하기 어려움 |
| 무작위 바이옴에서 도시 후보 탐색 | 필요한 지역 순서와 바이옴 조합을 보장하지 못함 |
| 바이옴을 찾은 뒤 가장 가까운 곳에 체육관 배치 | 마을·통로·경계와 분리되어 진행 구조가 깨질 수 있음 |

황혼의 숲 랜드마크 격자는 2안 서바이벌 격자 월드의 핵심 후보로 유지한다.

## 4 구성 계층

```text
세대 월드 설정
  ├─ 지역 1
  │   ├─ 바이옴 풀
  │   ├─ 체육관 도시 프로필
  │   ├─ 포켓몬 스폰 프로필
  │   └─ 지역 2 관문
  ├─ 지역 2
  │   └─ ...
  ├─ 지역 8
  │   ├─ 최종 체육관 도시
  │   └─ 리그 포탈
  └─ 경계·통로 프로필
```

지역의 논리 순서는 선형으로 고정하지만 실제 공간 배치는 직선일 필요가 없다. 지역 셀을 북쪽, 동쪽, 남쪽 등으로 굽혀 배치해 월드가 긴 복도처럼 보이지 않게 한다.

## 5 설정 데이터 초안

세대 월드의 지역 구성은 코드에 직접 넣지 않고 JSON 데이터로 관리한다.

```json
{
  "schema_version": 1,
  "world_id": "generation_1",
  "start_region": "region_1",
  "regions": [
    {
      "id": "region_1",
      "order": 1,
      "biomes": [
        "minecraft:forest",
        "minecraft:plains"
      ],
      "settlement_profile": "generation_1/town_1",
      "gym_profile": "generation_1/gym_1",
      "spawn_profile": "generation_1/region_1",
      "connections": [
        {
          "to": "region_2",
          "gate_profile": "forest_pass",
          "required_badges": 1
        }
      ]
    },
    {
      "id": "region_2",
      "order": 2,
      "biomes": [
        "minecraft:desert",
        "minecraft:swamp"
      ],
      "settlement_profile": "generation_1/town_2",
      "gym_profile": "generation_1/gym_2",
      "spawn_profile": "generation_1/region_2",
      "connections": [
        {
          "to": "region_3",
          "gate_profile": "ruined_causeway",
          "required_badges": 2
        }
      ]
    },
    {
      "id": "region_8",
      "order": 8,
      "biomes": [
        "minecraft:jagged_peaks",
        "minecraft:grove"
      ],

    "destination_dimension": "cobbleverse_overhaul:transition",

```

실제 파일에는 지역 1부터 8까지 빠짐없이 정의해야 한다. 배열 순서만 신뢰하지 않고 `id`와 `order`를 함께 검증한다.

## 6 지역 배치

지역 플래너는 설정의 순서를 실제 월드 공간으로 변환한다.

1. 시작 지역 셀을 월드 중심 주변에 배치한다.
2. 다음 지역 셀의 방향을 시드 기반 후보 중에서 선택한다.
3. 기존 지역과 겹치지 않고 최소 경계 폭을 확보하는지 검사한다.
4. `BiomeSource`가 셀 내부에 설정된 바이옴만 배치하도록 지역 맵을 제공한다.
5. 인접 지역 사이에는 설정된 관문 프로필 하나 이상을 예약한다.
6. 연결되지 않은 외곽은 산맥·협곡·바다·성벽 등의 경계 지대로 생성한다.

지역 순서와 연결 관계는 항상 같지만 지역의 방향, 내부 바이옴 경계와 세부 지형은 월드 시드에 따라 변주할 수 있다.

상세한 청크 사전 생성과 경계 방식은 [월드 초기화 및 지역 경계](WORLD_BOOTSTRAP_REGIONS.md)에서 관리한다.

## 7 체육관 도시 배치

마을과 체육관은 전역 좌표가 아니라 해당 지역 셀 내부에서 위치를 찾는다.

```text
region_id와 지역 경계
  → 바이옴·경사·수면 조건을 만족하는 후보 생성
  → 같은 순서로 후보 평가
  → 도시 앵커 확정
  → 체육관·마을·상점·NPC 조립
  → 지역 관문과 도로 연결
```

도시 후보가 모두 실패하면 다른 지역이나 전역 격자로 이동하지 않는다. 해당 지역의 초기화를 `FAILED`로 기록하고 안전한 대체 지형 생성 또는 관리자 복구를 요구한다.

## 8 구조물 구성

체육관 도시는 여러 구조물 조각을 직소 방식으로 조립한다.

| 구성 요소 | 역할 |
|-----------|------|
| 구조물 템플릿 | 체육관, 센터, 상점, 주택과 도로 조각의 `.nbt` |
| 직소 블록 | 조각의 연결 위치와 방향 표시 |
| 템플릿 풀 | 후보 조각과 선택 가중치 정의 |
| 구조물 정의 | 시작 풀, 조립 깊이와 지형 적응 정의 |
| 프로세서 목록 | 배치 중 블록 교체, 노후화와 테마 변형 수행 |

체육관, 회복 시설, 상점과 관문 도로는 필수 조각으로 보장한다. 주택, 장식과 샛길만 무작위로 선택한다.

구조물 제작 절차는 다음과 같다.

1. 배포 버전과 같은 건축용 인스턴스에서 WorldEdit 또는 Axiom으로 제작한다.
2. 건물을 직소 조각으로 나누고 연결점과 구조물 원점을 지정한다.
3. 프로젝트 네임스페이스의 `.nbt` 구조물로 저장한다.
4. 템플릿 풀과 프로세서 JSON을 작성한다.
5. `/place template`, `/place jigsaw`, `/place structure`로 개별·전체 구조물을 검증한다.
6. 지역별 바이옴과 경계 지형에서 도로 연결과 기초 처리를 확인한다.

## 9 지역 통로와 진행 잠금

지역 연결은 설정에 선언된 통로만 허용한다.

- 관문은 `from_region`, `to_region`과 요구 배지를 검사한다.
- 공용 문이 열렸는지만 확인하지 않고 플레이어별 진행 상태를 검사한다.
- 채굴, 비행, 순간이동과 다른 모드 워프로 경계를 넘으면 서버가 권한을 다시 검사한다. 비행 포켓몬의 공중날기 권한이 확인되면 같은 세대 월드의 지역 이동은 허용한다.
- 정상 통과 후에는 해당 플레이어의 다음 지역 체크포인트를 갱신한다.
- 선택형 지름길은 별도 연결로 선언하고 양방향 여부를 명시한다.

지역 8의 리그 포탈은 8개 배지와 지역 완료 상태를 모두 확인한 뒤에만 `transition` 차원의 해당 세대 리그 입구로 이동시킨다.

## 10 저장 데이터

| 필드 | 설명 |
|------|------|
| `world_profile_id` | 세대 월드 설정 ID |
| `profile_version` | 설정과 생성 규칙 버전 |
| `region_id` | 지역 식별자 |
| `order` | 진행 순서 1~8 |
| `bounds` | 지역 청크 경계 |
| `biome_profile` | 실제 사용한 바이옴 풀과 생성 설정 |
| `city_anchor` | 확정된 체육관 도시 기준 좌표 |
| `gate_anchors` | 이전·다음 지역 통로 좌표 |
| `generation_state` | 계획, 생성 중, 검증, 완료, 실패 |
| `structure_version` | 도시와 관문 구조물 버전 |
| `league_portal_anchor` | 지역 8 리그 포탈 좌표 |

도시 위치는 지역 플래너의 결과로 저장한다. 업데이트 후 지역을 다시 계산해 이미 생성된 도시가 움직이지 않게 한다.

## 11 검증 규칙

설정 정적 검증:

- 지역이 정확히 8개인가?
- `order`가 1부터 8까지 중복·누락 없이 존재하는가?
- 시작 지역이 order 1인가?
- 지역 1에서 지역 8까지 허용 통로만으로 도달 가능한가?
- 지역 8만 리그 포탈의 출발 지역인가?
- 모든 지역에 바이옴, 도시, 체육관과 스폰 프로필이 있는가?
- 모든 연결의 요구 배지가 목적 지역 순서와 일치하는가?

월드 생성 검증:

- 각 지역에 허용된 바이옴만 생성되는가?
- 체육관 도시와 관문이 지역 경계 안에 존재하는가?
- 필수 도로가 경계 지형으로 끊기지 않는가?
- 허용되지 않은 지역 간 직접 이동이 차단되는가?
- 같은 시드와 설정에서 지역 배치와 앵커가 재현되는가?
- 8번째 지역 완료 전후로 리그 포탈 상태가 올바른가?
- 서버 재시작 후 지역, 도시, 관문과 포탈이 중복 생성되지 않는가?
- 블록 설치·파괴, 엔더 진주와 비인가 비행·모드 워프로 잠긴 지역을 우회할 수 없는가?
- 인가된 공중날기 탑승은 지역 경계를 넘되 잠긴 체육관·리그 진행까지 해금하지 않는가?
- 제한 수역은 파도타기 없이 건널 수 없고 정상 탑승 중에는 호흡과 부력이 유지되는가?
- 집 PC를 통한 서바이벌 공간 왕복 후 올바른 게임 모드와 귀환점이 복원되는가?

## 12 미결정 사항

- 세대별 8개 지역의 실제 바이옴 풀은 무엇인가?
- 지역 셀의 최소·최대 크기와 경계 폭은 얼마인가?
- 지역 진행을 완전 선형으로 할지 일부 선택형 지름길을 허용할 것인가?
- 각 지역의 마을과 체육관 건축 테마는 무엇인가?
- 다음 지역 관문은 배지 외에 기술, 아이템 또는 퀘스트 조건을 사용할 것인가?
- 지역 셀 배치 실패 시 월드 생성을 중단할지 대체 레이아웃을 사용할 것인가?
- 서바이벌 공간을 공용 대형 월드, 공유 개인 구획 또는 플레이어별 소형 차원 중 무엇으로 만들 것인가?

## 14 라이선스 주의

외부 건축물과 구조물 파일을 포함할 때는 수정·재배포 권한과 저작자 표시 조건을 기록한다. 공개된 월드 생성 알고리즘은 참고하되 타 모드의 구조물 에셋을 복사하지 않는다.
