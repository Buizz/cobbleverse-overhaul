# 플레이어 집 PC와 개인 농장 접속

> 관련 요구사항: F-01, F-07
>
> 관련 결정: D-13 3안 하이브리드, D-14 1청크 개인 농장, D-15 PC 연출
>
> 적용 아키텍처: 3안 하이브리드 전용
>
> 설계 상태: PC→개인 농장 이동 확정 / AE2식 접속 연출 방식 미정

## 1 목적

3안 하이브리드에서는 세대 월드를 정해진 길과 지역 진행을 체험하는 보호형 서바이벌 공간으로 사용한다. 일반 자연환경은 훼손할 수 없지만 지정 작물과 특수 던전 광물은 채집할 수 있다. 플레이어는 시작 마을에 배정된 자기 집 PC에서 [PC 기반 1청크 개인 농장](PERSONAL_FARM_PLOT.md)으로 이동한다.

넓은 서바이벌 월드, 채광, 허기, 몬스터 사냥과 대규모 자동화는 현재 범위에서 제외한다. 이 문서는 PC 왕복, 게임 모드 전환, AE2식 가상공간 연출과 안전 복구를 담당한다.

```text
세대 월드의 시작 마을
  → 플레이어 집
  → 집 PC 사용
  → 개인 농장 플롯 준비
  → SURVIVAL 모드로 이동
  → 농사·소규모 꾸미기·제한된 보관
  → 귀환 장치 사용
  → 플레이어 집 PC 앞
  → 세대 월드 보호 프로필 복원
```

## 2 확정된 역할 분리

| 공간 | 게임 모드 | 핵심 역할 | 블록 편집 |
|------|-----------|-----------|-----------|
| 세대 월드 `generation_N` | 서바이벌+필드 보호 | 지역 1~8, 체육관, 마을, 스토리와 포켓몬 탐험 | 지정 작물만 예외 |
| 리그·전환 월드 `transition` | 서바이벌+구조물 보호 | 챔피언로드, 리그와 다음 세대 해금 | 설계된 상호작용만 |
| 이름 있는 던전 월드 | 서바이벌+던전 보호 | 퍼즐, 전투, 고정 동선, 광물 노드와 체크포인트 | 광물·작물·퍼즐 예외 |
| 개인 농장 `farm_plots` | 서바이벌+영역 보호 | 규토리·나무열매 농사와 소규모 꾸미기 | 자기 플롯의 허용 블록만 |

세대 월드에서 필요한 상호작용은 블록 파괴에 의존하지 않는다. 문, 스위치, NPC, 전용 도구와 진행 오브젝트가 서버 측 이벤트를 발생시키는 방식으로 만든다.

## 3 서바이벌 모드와 보호 프로필 전환 규칙

게임 모드는 차원 속성이 아니라 플레이어 상태이므로 차원 진입·이탈 이벤트에서 코어 모드가 전환해야 한다.

- 모든 플레이 공간에서 `SURVIVAL`을 유지한다.
- 세대·리그·던전·농장 진입 시 해당 영역의 보호·수확·채굴 프로필을 적용한다.
- 이동 전 출발 차원, 귀환 앵커와 프로젝트가 관리하던 모드를 저장한다.
- 사망, 재접속, 서버 재시작과 명령어 이동 후에도 현재 차원에 맞는 모드를 재검증한다.
- 관리자와 크리에이티브 권한 사용자는 명시적인 우회 권한이 있을 때만 자동 전환에서 제외한다.
- 다른 모드가 게임 모드나 권한 상태를 바꿀 경우 다음 차원 이동이나 재검증 시 서바이벌과 올바른 보호 프로필로 복구한다.

## 4 지역 경계 보안

서바이벌 모드에서는 블록 파괴·설치뿐 아니라 유체, 폭발, 피스톤과 다른 모드 도구로 경계를 훼손할 수 있다. 세대 월드 경계에는 [보호형 서바이벌 필드와 재생 자원](PROTECTED_SURVIVAL_RESOURCES.md)의 행동 권한과 다음 방어를 함께 적용한다.

- 지역 경계를 넘을 때 목적 지역 해금과 통과한 관문을 서버에서 검사한다.
- 엔더 진주, 코러스 열매, 비인가 비행, 탈것과 다른 모드의 순간이동을 같은 검사에 포함한다.
- 공중날기 비전머신이 적용된 비행 포켓몬 탑승은 같은 세대 월드의 지역 경계 통과 예외로 인정한다.
- 잠긴 지역에 들어온 플레이어는 마지막 허용 체크포인트로 되돌린다.
- 연결 통로 안의 허용된 문·다리·터널만 정상적인 경계 통과로 기록한다.
- 블록의 `CanDestroy`·`CanPlaceOn` 예외 아이템은 필요한 퍼즐 구역에만 제한적으로 발급하고 회수한다.

즉, 물리 경계는 세계관과 시각적 안내를 담당하고 서버 측 행동 권한과 위치 검사가 실제 진행 보안을 담당한다.

## 5 집 PC 이동 장치

### 5.1 플레이어 집

- 시작 마을에 플레이어별 집 또는 개인 방을 배정한다.
- 집에는 소유자를 식별하는 PC 상호작용 지점을 둔다.
- 멀티플레이에서 다른 플레이어가 PC를 눌러도 PC 소유자의 개인 공간으로 들어갈 수 없게 한다.
- 집을 실제로 플레이어마다 복제할지, 하나의 공용 건물 안에 개인화된 PC UI만 둘지는 구현 실험으로 결정한다.

### 5.2 PC 사용 흐름

```text
PC 상호작용
  → 소유자·전투·탑승 상태 검사
  → 개인 농장 플롯 준비 상태 검사
  → 귀환 위치를 해당 집 PC 앞으로 저장
  → 목적지 청크 또는 인스턴스 준비
  → SURVIVAL 모드 적용
  → 안전한 스폰 앵커로 이동
```

귀환은 서바이벌 공간의 귀환 PC, 침대 옆 단말기 또는 재사용 대기시간이 있는 귀환 아이템을 사용한다. 단순 `/spawn` 명령만을 필수 경로로 두지 않는다.

## 6 보존된 공간 대안과 선택 결과

아래 대안은 3안 결정 과정에서 검토한 기록이다. 정식 기준은 후보 C를 1청크 농장으로 축소한 공유 차원의 개인 구획이다.

### 6.1 후보 A: 공용 대형 서바이벌 월드

일반 오버월드와 비슷한 넓은 차원 하나를 모든 플레이어가 공유한다.

| 장점 | 주의점 |
|------|--------|
| 바닐라 생존 경험과 다른 모드의 월드 생성 기능을 그대로 사용하기 쉬움 | 자원 고갈과 탐험 반경 증가 |
| 차원 하나만 관리하므로 백업·복구가 단순함 | 도난, 파괴와 영역 분쟁 방지 필요 |
| 공동 건축과 거래가 자연스럽게 발생함 | 신규 플레이어 주변이 이미 개발됐을 수 있음 |
| 자동화·기계·농사 모드 호환성이 상대적으로 좋음 | 월드 크기와 청크 생성량 관리 필요 |

보완책으로 개인 클레임, 시작 구역 보호, 자원 월드 초기화 또는 월드 경계 확장을 사용할 수 있다.

### 6.2 후보 B: 플레이어별 소형 차원

추가 모드 또는 코어 모드가 플레이어마다 작은 생존 차원을 생성하고 수명주기를 관리한다.

| 장점 | 주의점 |
|------|--------|
| 자원과 건축 공간을 독립적으로 보장 | 플레이어 수만큼 차원·저장·백업 대상 증가 가능 |
| 약탈과 공간 분쟁이 거의 없음 | 동적 생성, 재접속, 삭제와 소유권 복구가 복잡함 |
| 크기, 바이옴과 초기 구조를 통제하기 쉬움 | 월드 생성·차원 모드와 자동화 모드 호환성 검증 필요 |
| 개인 기지라는 포켓몬 본가식 연출에 적합 | 공동 건축과 자연스러운 만남이 감소함 |

추가 모드를 선택할 때는 Minecraft·Fabric·Cobblemon 버전, 서버 전용 실행, 차원 데이터 보존, 청크 로딩, 팀 공유와 라이선스를 확인한다.

### 6.3 후보 C: 공유 차원의 개인 구획

하나의 전용 차원 안에 플레이어별 소형 셀을 멀리 떨어뜨려 배치한다. 화면상으로는 개인 차원처럼 보이지만 서버는 차원 하나만 관리한다.

| 장점 | 주의점 |
|------|--------|
| 동적 차원 수를 늘리지 않고 개인 공간 제공 | 셀 경계, 순간이동과 청크 로딩 격리 필요 |
| 백업과 모드 호환성이 개인별 차원보다 단순 | 자연 지형 탐험보다는 플롯·섬에 가까움 |
| 팀 단위 셀과 방문 권한을 구현하기 쉬움 | 셀 간 엔티티·레드스톤 간섭을 검증해야 함 |

### 6.4 FTB Genesis의 AE2 가상공간 연출

[FTB Genesis](https://feed-the-beast.com/modpacks/120-ftb-genesis)의 시뮬레이션 챔버 연출은 팀별 차원을 생성하는 모드가 아니라, [Applied Energistics 2](https://appliedenergistics.org/)의 `Spatial Storage`와 `Spatial IO` 기능을 중심으로 구성된 사례다.

AE2의 Spatial IO는 Spatial Pylon으로 둘러싼 물리 공간을 Spatial Storage Cell과 공간 저장 차원 사이에서 통째로 교환한다. 셀마다 서로 다른 방·지형·설비를 저장해 두고 Spatial IO Port에 셀을 넣어 같은 챔버 안에 다른 환경을 불러올 수 있다. 교환 영역 안에 플레이어가 있으면 플레이어도 공간과 함께 이동할 수 있다.

FTB Genesis에서는 이 기능과 사전 제작된 공간 셀·퀘스트·건축 연출을 조합해 다음과 같은 가상 시뮬레이션처럼 보이게 만든다.

```text
시뮬레이션 제어 장치 사용
  → 환경 데이터가 담긴 Spatial Storage Cell 선택
  → Spatial IO Port 작동
  → 챔버 내부 공간 전체 교환
  → 숲·농장·네더 등 선택한 시뮬레이션 환경 출현
  → 플레이어가 챔버 또는 공간 저장 영역에서 활동
  → 다른 셀을 불러와 환경 교체
```

이 프로젝트에서는 시작 마을의 집 PC를 단순 포탈처럼 만들지 않고, AE2식 공간 데이터 로딩 장치처럼 연출할 수 있다.

| FTB Genesis·AE2 요소 | 프로젝트 적용안 |
|----------------------|-----------------|
| Spatial IO Port | 집 PC의 시뮬레이션 제어 장치 |
| Spatial Storage Cell | 서바이벌 환경 또는 프리셋 선택 데이터 |
| Spatial Pylon 챔버 | 접속·환경 로딩 연출 공간 |
| 공간 저장 차원 | 가상 서바이벌 공간이라는 세계관 설명 |
| 셀 교체 | 생존 프리셋, 농장, 광산 또는 훈련 공간 선택 |

#### 적용 방식 후보

1. **AE2 Spatial IO를 실제로 사용**
   - 집 지하나 별도 시설에 고정 크기의 시뮬레이션 챔버를 만든다.
   - 프로젝트가 준비한 Spatial Storage Cell을 PC UI에서 선택해 챔버 내부를 교체한다.
   - 소형 농장, 훈련실, 자원실처럼 경계가 명확한 공간에 적합하다.

2. **AE2는 연출에 사용하고 실제 서바이벌 차원으로 순간이동**
   - PC와 Spatial IO 작동 애니메이션으로 가상공간 접속을 표현한다.
   - 공간 교환 직후 코어 모드가 공용 또는 개인 서바이벌 차원으로 안전하게 이동시킨다.
   - 넓은 월드 탐험, 안정적인 귀환과 서버 운영에는 이 방식이 더 적합하다.

3. **AE2 방식을 시각적으로만 참고**
   - AE2를 필수 의존성으로 두지 않고 PC UI, 데이터 셀과 공간 로딩 효과를 프로젝트 자체 블록으로 구현한다.
   - 기반 모드팩에 AE2가 없거나 진행 밸런스상 AE2 기계를 노출하기 어려울 때 사용한다.

#### 기술 판단

AE2는 Minecraft 1.21.1 Fabric 배포본과 해당 버전의 Spatial IO 문서를 제공하므로 현재 프로젝트 조사 기준과 맞는다. 따라서 FTB Genesis식 연출을 실제로 시험할 수 있는 유효한 후보로 기록한다.

다만 Spatial IO의 본래 기능은 넓은 개인 월드를 생성하는 것이 아니라 제한된 물리 공간을 공간 저장 차원과 교환하는 것이다. 공식 가이드도 이를 순간이동 수단으로 쓰는 것은 복잡하고 불안정할 수 있다고 설명한다. 플레이어가 출구 없이 공간 저장 차원에 갇힐 가능성도 있으므로 다음 안전장치를 둔다.

- 플레이어의 귀환은 AE2 장치 상태와 무관한 프로젝트 전용 귀환 기능으로 보장한다.
- Spatial Storage Cell을 플레이어가 임의로 반출·분해·교체하지 못하게 보호한다.
- 서버 재시작 중 공간 교환이 중단됐을 때 챔버와 플레이어 위치를 복구한다.
- 자동화 기계, 파이프와 다른 모드 블록이 공간 교환 시 올바르게 이동하는지 검증한다.
- 넓은 서바이벌 월드의 저장 수단으로 직접 사용하기보다 접속 연출과 소형 프리셋 공간에 우선 적용한다.
- 실제 농장 목적지는 AE2와 무관한 공유 `farm_plots` 차원에서 프로젝트가 관리한다.

## 7 현재 운영 방침

개인 공간의 물리 구조는 공유 `farm_plots` 차원에 플레이어별 1청크 플롯을 격리 배치하는 방식으로 확정한다. 공용 대형 서바이벌 월드와 플레이어별 동적 차원은 초기 구현에서 제외한다.

집 PC를 접속 수단으로 사용하는 세계관에서는 일반 포탈보다 AE2식 가상공간 연출이 자연스럽다. 다만 로딩할 실제 콘텐츠는 여러 자원 환경이 아니라 플레이어의 개인 농장 하나로 제한한다.

AE2식 가상공간은 농장 자체를 저장하는 필수 기술이 아니라 PC 접속을 표현하는 선택 연출이다. 프로토타입에서는 자체 PC 이동을 기준으로 구현하고, AE2 연출을 추가했을 때 다음 항목을 비교한다.

- PC 접속이라는 설정과 시각적 일관성
- 1청크 농장과 어울리는 접속·로딩 연출
- 농장 템플릿 생성과 작물 성장 처리
- 플레이어·파티별 소유권과 방문 권한
- 차원 및 공간 셀의 저장 용량과 서버 성능
- 장애 발생 시 귀환·백업·복구 난도

농장 저장, 소유권과 귀환은 AE2 장치 상태와 무관하게 프로젝트가 관리한다.

## 8 인벤토리와 경제 정책

세대 월드와 개인 농장은 하나의 [본가식 가방 인벤토리](BAG_INVENTORY.md)를 공유한다. 농장에서는 열매·규토리·허용 장식 포켓만 노출한다.

- 개인 농장에서 얻은 규토리·나무열매와 장식 아이템의 반입 허용 범위
- 비행·순간이동·굴착 아이템을 세대 월드에서 사용할 수 있는지 여부
- 포켓몬, 치료 장치, PC와 금지된 자동화 설비의 반입 제한
- 리그 도전 중 창고와 서바이벌 월드를 통한 파티 교체 제한
- 차원별 경험치, 사망 시 아이템 손실과 귀환 규칙

차원마다 인벤토리 데이터를 복사하거나 완전히 분리하면 플레이어 혼란과 아이템 유실·복제 위험이 크므로 사용하지 않는다. [본가식 가방 인벤토리](BAG_INVENTORY.md)의 동일한 서버 저장소를 공유하되, 현재 차원이 허용한 포켓과 아이템만 노출한다.

### 8.1 허기 제외와 제한 채집

허기·식사는 핵심 진행 시스템에서 제외하지만 농사와 채굴 자체는 제한적으로 유지한다.

- 세대 필드의 지정 작물은 가방으로 수확할 수 있다.
- 특수 던전의 등록된 재생 광물만 채굴할 수 있다.
- 일반 자연 광맥, 구조물과 지형은 보호한다.
- 개인 농장은 열매·규토리와 제한된 장식 재료의 장기 공급처다.
- 작물과 광물에는 상점·퀘스트·전투 보상 대체 경로를 둔다.
- 허용 범위는 [보호형 서바이벌 필드와 재생 자원](PROTECTED_SURVIVAL_RESOURCES.md)을 따른다.

## 9 프로토타입 합격 기준

- 시작 마을의 집 PC에서 자신의 1청크 농장으로 이동할 수 있다.
- 공유 농장 차원의 개인 플롯 생성·격리와 AE2식 선택 연출의 기술 검증이 완료된다.
- 이동과 귀환 후에도 `SURVIVAL`이 유지되고 목적지의 보호 프로필이 정확히 적용된다.
- 사망, 재접속과 서버 재시작 후에도 목적지·귀환점과 게임 모드가 복구된다.
- 개인 농장에서는 허용된 농사·장식만 가능하고 세대 월드에서는 임의 블록 편집이 불가능하다.
- 엔더 진주나 다른 이동 수단으로 잠긴 지역에 들어가면 허용 체크포인트로 복귀한다.
- 다른 플레이어의 집 PC가 개인 목적지나 소유권을 노출하지 않는다.

## 10 미결정 사항

- 개인 집은 실제 구조물을 플레이어별로 만들 것인가, 공용 시작 집과 개인화된 PC만 사용할 것인가?
- 친구의 개인 농장 방문과 공동 편집을 허용할 것인가?
- 세대 월드로 반입할 수 없는 아이템을 둘 것인가?
- AE2 Spatial IO를 실제 공간 교환에 사용할지 접속 연출에만 사용할지 결정했는가?
