# 스토리·이벤트 작성 흐름 통합

## 범위 고정

1차는 **웹 작성 흐름 통합**이다. CVES AST·컴파일러·게임 실행기는 재작성하지 않는다.
NPC 행동 프리셋, 퀘스트 조건·목표·보상 로직을 그대로 사용한다.

- 사이드바 `스토리 · 이벤트` → `이벤트 라이브러리`, `퀘스트`.
- 퀘스트의 `목록과 목표`, `전역 발동`, `진행 순서`는 같은 작업 영역의 탭이다.
  각 기존 화면을 유지하므로 탭 전환 때 입력을 버리거나 저장하지 않는다.
- NPC 이벤트 입력은 이름·ID·태그·사용 NPC 이름으로 검색하고 목록에서 선택한다.
  문자열을 타이핑하는 것만으로 연결을 바꾸지 않는다. 방향키·Enter·Escape를 지원한다.
- 선택은 NPC의 `event_runtime.script_id`에 반영하고 **NPC 저장 후** 바인딩이 적용된다.
  실제 선택한 script ID로 편집기를 연다. NPC 기본 경로로 대체하지 않는다.
- `이벤트 바로 편집`은 같은 Studio의 캐시된 편집기를 연다. `NPC로 돌아가기`는
  NPC의 저장 전 입력과 스크롤, 편집기의 작업 내용을 유지한다. 저장은 각 화면에서 별도 수행한다.
  다른 이벤트로 바꿀 때에는 저장 전 AST·텍스트·분류 변경을 버릴지 확인한다.

## 권위 원본과 분류 계약

### 프리셋 자동 생성 원본의 UI 노출 정책

- 이벤트 라이브러리와 NPC의 이벤트 선택 목록에는 사용자 정의 원본만 표시한다.
  저장된 NPC 사용처 중 `authoring: preset`이 하나라도 있으면 생성 원본으로 판단해 제외한다.
  이름·폴더·배틀 여부로 숨기지 않으므로 직접 작성한 관장전 등은 그대로 표시한다.
- NPC의 행동 프리셋 모드에서는 스크립트 ID, 연결 선택, 바로 편집, 생성 결과 미리보기를 숨긴다.
  일반 제작자는 행동 프리셋 설정만 저장하면 된다. 별도의 `사용자 정의로 전환` 버튼은 유지한다.
  전환 후 NPC를 저장하면 생성 원본 보호가 해제되고 사용자 정의 목록에 나타난다.
- 자동 생성 파일·메타데이터·바인딩·게임 실행은 보존한다. 내부 라이브러리 API도 전체 파일을 유지해
  새 파일 생성 시 숨겨진 프리셋 경로와의 충돌을 감지한다. 과거 프리셋 직접 링크는 NPC 설정 안내로 처리한다.
- 적용 시점: 전체 134개 중 생성 원본 105개 제외, 사용자 정의 원본 29개 표시.
  아래 초기 분류 집계 134개는 저장소 전체 파일 기준이며, 웹 표시 개수와는 다르다.
- 회귀 검사: `preset_script_visibility.test.cjs`에서 목록, 기본 선택, 직접 링크,
  NPC 모드별 노출·데이터 보존, 이벤트 선택 목록을 확인한다.

실행 원본은 계속 `content/events/<namespace>/<path>.cves`이다.
분류는 `content/event-metadata/<namespace>/<path>.json`에 저장한다.
메타데이터 파일이 없는 기존 이벤트도 즉시 목록에 표시하며, 조회만으로 파일을 만들지 않는다.
파일 이동·기존 V4 변환·기존 이벤트 일괄 덮어쓰기는 하지 않는다.

```json
{
  "schema_version": 1,
  "display_name": "포켓몬센터 치료",
  "description": "간호순의 치료 대화",
  "category": "system",
  "tags": ["시설", "치료"]
}
```

- 분류: `npc`, `quest`, `region`, `common`, `system`.
- 표시 이름 최대 120자, 설명 최대 2,000자, 태그 최대 30개·각 40자.
- 태그는 공백 제거·중복 제거·정렬 후 저장한다. 알 수 없는 필드를 거부한다.
- 이름이 없으면 파일명, 분류가 없는 기존 문서는 사용처가 있으면 `npc`, 없으면 `common`.
- 분류는 작성용 표시 정보이며 발동 조건·보안 권한·런타임 역할이 아니다.
- 분류 저장은 CVES와 별도 버튼·별도 SHA-256 낙관적 잠금을 사용한다.
  `PUT /api/cves/metadata`는 `path`, `metadata`, `expected_digest`를 받는다.
  저장하지 않은 새 트리는 CVES를 먼저 저장해야 분류를 저장할 수 있다.

## 사용처와 보호

`GET /api/cves/scripts`는 메타데이터·저장된 NPC/바인딩/퀘스트 훅 사용처·관리 여부와
`quest_compatible`(인수 없는 quest 진입점 하나 존재)을 반환한다.
`GET /api/cves/script`는 같은 정보를 `library`에 포함한다.

- `managed`는 NPC의 `event_runtime.authoring == preset`에서 계산하며 메타데이터로 변경할 수 없다.
- 동일 NPC의 source와 binding은 한 사용처로 표시한다. 원본과 다른 binding은 별도로 표시한다.
- 자동 생성 이벤트는 AST/텍스트 읽기 전용이다. API도 직접 저장을 거부한다.
  NPC에서 사용자 정의로 전환해 **저장한 후** 다시 열거나 새 경로로 트리를 복사한다.
- 다른 NPC의 자동 생성 이벤트에 직접 연결하는 것도 거부한다. 복사본을 연결해야 한다.
- `복사본 만들기`는 현재 AST를 새 경로의 미저장 문서로 만든다. 원본·기존 NPC 연결은 유지하며
  분류와 사용처는 복사하지 않는다. 경로가 이미 있으면 저장을 거부한다.
- 사용처가 둘 이상인 원본 저장은 사용처 목록 확인을 요구한다. API의 `usage_digest`가
  현재 사용처 해시와 다르면 409로 거부한다. 목록 새로고침 후 다시 확인해야 한다.
- 웹 NPC 저장과 원본 저장은 같은 서버 잠금을 사용한다. 외부 파일 변경에 대한 원본 해시 충돌 검사도 유지한다.
- 퀘스트 훅 사용처에는 퀘스트 ID, 연결 필드 경로, 실행 기준 NPC ID를 포함한다.
  연결된 원본에서 quest 진입점을 삭제하거나 복수로 늘리는 저장은 거부한다.

## 2차 — 퀘스트 실행 훅 (2026-09-02)

기존 `quest_grant`, `quest_check`, `quest_complete`와 QuestService의 상태·조건 평가를 재사용한다.
퀘스트 상태 시스템을 이벤트 실행기로 대체하지 않는다. 기존 퀘스트는 훅이 없으면 이전과 동일하다.
기존 콘텐츠·V4·프리셋 원본은 자동 변환하지 않는다.

### 작성 계약

퀘스트 schema_version 1에 다음 선택 필드를 추가한다. 모든 훅에는 실행할 CVES 원본과
실행 기준 NPC가 필요하다. 현재 V5 대화·배틀·치료 어댑터가 NPC 문맥을 필요로 하므로
가상의 NPC나 플레이어를 NPC 대신 주입하지 않는다.

```json
{
  "event_hooks": {
    "on_accept": {"script_id":"test:event_script/quest/intro", "npc_id":"test:npc/oak"},
    "on_complete": {"script_id":"test:event_script/quest/done", "npc_id":"test:npc/oak"}
  }
}
```

개별 `objectives[]`에도 같은 형태의 `on_complete`를 지정한다. 이 블록은 전체 퀘스트가 아닌
해당 목표의 최초 달성 시 등록한다. 선택하지 않은 훅은 JSON에서 생략한다.

원본에는 인수 없는 `event quest`가 정확히 하나 필요하다. 일반 상호작용·거리 트리거를
퀘스트 발동 시 임의 호출하지 않는다. 같은 파일에 다른 종류의 트리거는 함께 둘 수 있다.

```cves
event quest {
  page default {
    id "quest/intro" say npc "퀘스트를 시작하자!"
  }
}
```

웹 `퀘스트 → V5 이벤트 연결`에서 이름·ID·태그로 검색한 이벤트와 기준 NPC를 선택한다.
목표별 훅은 각 목표 카드에 있다. 자동 프리셋 관리 원본은 연결 대상에서 제외한다.
이벤트 라이브러리에서 트리거 `quest`로 새 원본을 만든 뒤 목록을 새로고침하면 선택할 수 있다.
`이벤트 바로 편집 → 퀘스트로 돌아가기`는 캐시된 화면과 저장 전 입력을 유지한다.
이벤트 저장과 퀘스트 저장은 별도다. 없는 원본·NPC, 잘못된 진입점은 퀘스트 저장 전에 거부한다.

### 실행·지속성 계약

- 플레이어 영속 데이터 `PlayerPersisted.cobbleventureQuestEventHooks`에 JSON 저널을 저장한다.
  수락/목표/완료 키는 `<quest ID>|accept`, `<quest ID>|objective|<objective ID>`,
  `<quest ID>|complete`다. NPC UUID가 바뀌어도 같은 전환을 재등록하지 않는다.
- 상태는 `PENDING → RUNNING → COMPLETED/FAILED`, 실행할 페이지가 없으면 `SKIPPED`다.
  종료 상태도 보존한다. 목표 조건이 거짓→참으로 다시 바뀌거나 반복 확인해도 재등록하지 않는다.
- 훅은 등록 당시 script/NPC ID를 보존한다. 원본의 실행 내용과 페이지 조건은 실행 시 읽는다.
  이미 수락/완료한 퀘스트에 훅을 추가해도 과거 수락/완료를 재생하지 않는다.
  진행 중인 목표에 새 훅을 추가하면 다음 검사에서 참인 조건은 최초 달성으로 등록될 수 있다.
- 같은 플레이어의 대화·배틀·await 등 활성 CVES 세션 또는 Cobblemon 배틀이 있으면 시작을 보류한다.
  다른 플레이어의 세션은 차단하지 않는다. 대기열은 등록 순서이며, 같은 평가에서 목표들은 문서 순서다.
- 현재 차원에 로드된 동일 콘텐츠 NPC 중 가장 가까운 개체를 기준으로 실행한다(동률은 UUID 순).
  해당 NPC가 없으면 FIFO 선두에서 계속 대기한다. 원격 NPC를 강제 로드하거나 소환하지 않는다.
- 기존 EventInterpreter와 대화·선택지·룰렛·배틀·아이템 await 어댑터를 그대로 사용한다.
  기존 세션 키를 발견하면 종료된 세션도 다시 시작하지 않고 저널에 연결한다.
  RUNNING 세션은 이어 실행하지만 WAITING 화면을 재접속 시 새로 띄우는 기능은 추가하지 않는다.
- 원본 누락, 실행 오류, 세션 유실은 실패로 기록하며 자동 재시도하지 않는다.
  훅의 await 제한 시간이 만료되면 실패로 종료하여 다음 훅을 영구 차단하지 않는다.
  제한 시간이 없는 await는 기존 세션 정책을 따른다. 손실된 세션은 기존 관리자 audit/discard로 조사한다.
- 실패/건너뜀은 이미 바뀐 퀘스트 상태를 되돌리지 않는다. 완료 훅의 보상 실패도 퀘스트 완료를
  취소하지 않으므로 중요한 보상은 명령 결과를 검사하도록 작성한다. 재시도 관리 UI는 아직 없다.
- 플레이어 데이터와 SavedData는 별도 저장소다. 정상 저장/재접속의 중복 방지를 제공하지만
  강제 종료 시 두 저장소의 원자적 트랜잭션이나 모든 외부 부작용의 exactly-once를 보장하지 않는다.

- adventure 모듈 Java 전체 테스트: 187개 통과. 새 훅 파싱·저널 순서/재로드·플레이어 격리·
  종료 세션 복구·await 차단/만료 검사를 포함한다.

- 퀘스트 선택/직렬화 및 공통 조건 JS 8개, 기존 작성 흐름/응답 경합 JS 16개 통과.
- 퀘스트 모드 패키징 2개 통과. 훅 JSON은 기존 빌더가 그대로 패키징한다.
- 현재 콘텐츠 전체 검증: 오류 0, 경고 0. `node --check`, `git diff --check` 통과.
- Browser 스킬로 실제 Studio 화면의 훅 입력 배치·목록 로딩·퀘스트→이벤트→퀘스트 복귀와
  미저장 이름 보존을 확인했다. 테스트 중 실제 프로젝트 저장은 하지 않았다.

다음 적용 단계는 실제 퀘스트 하나에 원본과 훅을 명시적으로 연결해 수락→목표→완료,
대화/배틀 중 대기, 두 플레이어 동시 진행을 게임에서 확인하는 것이다.
완료한 웹 통합·런타임 구현을 새 시스템으로 재작성할 계획은 없다.

## 검증

### 스크립트 내부 이벤트 추가와 라이브러리 분류

- 트리 도구막대의 `＋ 이벤트 추가`는 **현재 파일** 끝에 발동 이벤트와 빈 기본 페이지를
  추가한다. 원본 목록의 `＋`(새 파일 생성)와 구분한다. 대사·명령은 기본 페이지에 작성하고
  `CVES 저장`으로 반영한다. 추가창 취소는 AST를 변경하지 않는다.
- 발동 조건 목록과 필수 대상 리소스는 공통 편집기 계약을 사용한다. 범위형 이벤트는
  양수 거리, 대상형 이벤트는 카탈로그 리소스를 직접 선택한다. 세부 설정은 추가 후 속성에서 편집한다.
- NPC 상호작용·퀘스트 훅 런타임의 단일 진입점 계약에 따라 `interact`, `quest`의 중복 추가를 막는다.
  상태별 말 걸기는 한 이벤트 안의 페이지로 구분하며, 거리 진입 이벤트는 여러 개 추가할 수 있다.
- 프리셋 관리 원본, 로딩 중인 문서, 아직 AST에 적용하지 않은 텍스트에는 추가하지 않는다.
- 기존 134개 파일의 분류는 `content/event-metadata/`의 별도 JSON에 기록했다.
  실행 CVES, NPC 설정, 연결 ID와 경로는 변경하지 않는다. 폴더를 이동하거나 재생성 시 덮어쓰는 규칙이 아니다.
  이름은 연결된 NPC 또는 관장 배틀의 한국어 표시 이름을 사용한다.
