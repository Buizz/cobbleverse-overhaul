# 1세대 시작 지역 통합 구현 계획

## 목표

다음 항목을 서로 어긋나지 않게 한 번의 구현 묶음으로 완성한다.

1. 체계적인 바이옴 카탈로그와 지역 판정
2. 마을별 내부·주변 바이옴과 경계 벽
3. 트레이너 타입 분류와 배치용 데이터 계약
4. 마을별 건축 디자인
5. 더 큰 시작 마을과 결정적 배치
6. 10층 기반암과 낙하 안전장치

실제 트레이너 NPC 스폰은 이 묶음의 완료 후 다음 단계에서 구현한다.

- 관련 기능: `WORLD-BIOME-01`, `WORLD-BOUNDARY-01`, `SETTLEMENT-BUILDING-01`, `SETTLEMENT-LAYOUT-01`, `TRAINER-TYPE-01`, `WORLD-SAFETY-01`
- 상태: 구현 대기

## 구현 원칙

- 정규화 JSON이 좌표와 콘텐츠 선택의 단일 기준이다.
- Java 하드코딩 값은 기본값이나 오류 복구에만 사용한다.
- 스키마 → 카탈로그 → 콘텐츠 → 런타임 코드 순으로 구현한다.
- 기존 생성 월드의 청크를 암묵적으로 덮어쓰지 않는다.
- 부분 성공 상태의 지역에는 플레이어를 입장시키지 않는다.
- 각 단계는 독립 커밋과 자동 검증 결과를 남긴다.

## 단계별 실행 계획

### 0. 기준선 고정

- 현재 정상 작동하는 시작 차원·마을 ZIP을 보관한다.
- 시작 마을, 플레이어 시작점, 체육관, 표면 높이의 현재 좌표를 기록한다.
- 생성 버전을 새 버전으로 올릴 준비를 한다.

합격: 기존 빌드와 테스트 방법이 재현 가능하다.

### 1. 스키마와 카탈로그

- 바이옴, 경계, 건축 키트, 전투 성향, 난이도, 마을 역할 스키마를 추가한다.
- `region.schema.json`과 `settlement.schema.json`을 새 참조 구조로 확장한다.
- 교차 참조, 범위 겹침, 알 수 없는 ID 검증을 추가한다.
- Python 관리 웹이 새 필드를 보존하고 편집할 수 있게 한다.

합격: 게임을 실행하지 않고 전체 콘텐츠가 검증된다.

### 2. 좌표와 런타임 계획 통합

- `starter_town.json`을 시작 마을의 유일한 좌표 기준으로 수정한다.
- 부트스트랩의 하드코딩 좌표를 앵커 조회로 교체한다.
- 런타임에서 정규화 데이터를 `RegionPlanRegistry`로 적재한다.
- 시작점, 구조물, 벽, 관문이 같은 계획 객체를 사용한다.

합격: JSON의 중심 좌표를 바꾸면 모든 관련 배치가 함께 이동한다.

### 3. 전용 지형과 안전층

- 전용 `ChunkGenerator`에 표면 Y=69와 10층 기반암을 구현한다.
- 구조물의 안전층 침범을 차단한다.
- Y<54 낙하 복구와 로그를 구현한다.

합격: 준비 영역의 모든 검사 지점에서 Y=55~64가 기반암이다.

### 4. 바이옴 범위, 벽과 관문

- 전용 `BiomeSource`로 마을·주변·경계·외부를 판정한다.
- 시작 마을에 하나의 평원 바이옴만 허용한다.
- 경계 벽과 관문을 청크 생성 과정에서 결정적으로 만든다.
- 경계 겹침과 열린 틈 자동 검사를 추가한다.

합격: 관문만 통과 가능하고 마을 주변에 다른 바이옴이 섞이지 않는다.

### 5. 큰 마을과 건축 디자인

- 시작 마을을 `large` 프리셋으로 전환한다.
- 자체 `starter_plains` 건축 키트와 역할별 구조물을 만든다.
- 필수 시설을 먼저 예약하고 주택·장식을 배치한다.
- 관문부터 광장·센터·체육관까지 경로를 검사한다.

합격: 최소 크기·부지·시설 조건을 매 시드에서 만족한다.

### 6. 트레이너 분류와 후속 배치 준비

- 기존 트레이너 클래스를 유지하며 전략·난이도·역할 카탈로그를 추가한다.
- 전문가 변형과 치터 확률을 런타임 및 RCT 출력에 매핑한다.
- 시작 마을에 필수 슬롯, 배치 구역, 허용 풀, 인구 예산만 정의한다.
- NPC 실제 생성은 기능 플래그로 끈 상태에서 참조 검증까지 완료한다.

합격: 모든 슬롯과 풀을 해석할 수 있으나 NPC는 아직 자동 생성되지 않는다.

### 7. 통합 검증과 CurseForge 빌드

- 새 월드를 여러 시드로 생성한다.
- 중심, 네 변, 네 모서리, 관문, 건물 입구를 자동·수동 검사한다.
- 생성 시간, 청크 수, 메모리와 실패 로그를 기록한다.
- 개발 ZIP과 일반 ZIP을 만들고 새 프로필로 임포트한다.

합격: 아래 통합 완료 조건을 모두 만족한다.

## 통합 완료 조건

- 시작 마을은 지정한 평원 바이옴과 자체 건축 키트를 사용한다.
- 마을 내부는 최소 384×320블록이며 주변에 최소 64블록의 평원 완충 지대가 있다.
- 완충 지대 너머에는 연속된 벽이 있고 명시한 관문만 열린다.
- 지표 아래 Y=55~64에 정확히 10층의 기반암이 있다.
- 마을·체육관·시작점·벽 좌표가 JSON 한 곳에서 파생된다.
- 필수 시설이 정확히 하나씩 존재하고 주요 지점 사이에 보행 경로가 있다.
- 트레이너 네 분류 축과 마을 슬롯 데이터가 검증되지만 자동 NPC 스폰은 아직 실행되지 않는다.
- 새 CurseForge 프로필에서 첫 입장과 재접속이 모두 성공한다.

## 예상 커밋 단위

1. `feat: 지역 및 마을 생성 데이터 계약 확장`
2. `feat: 전용 바이옴 소스와 안전 지형 생성 구현`
3. `feat: 마을 경계 벽과 관문 생성 구현`
4. `feat: 시작 마을 건축 키트와 대형 배치 구현`
5. `feat: 트레이너 타입과 마을 배치 데이터 정규화`
6. `test: 시작 지역 통합 생성 검증 추가`
7. `docs: 시작 지역 구현 결과와 운영 절차 갱신`
