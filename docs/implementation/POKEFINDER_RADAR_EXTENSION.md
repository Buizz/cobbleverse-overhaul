# 포켓파인더 레이더 확장 구현 명세

## 1. 문서 상태

- 상태: 구현 전 설계 확정안
- 기준 버전: CobbleNav `2.3.3`
- 대상 기능: `cobblenav:pokefinder_item`의 HUD 레이더
- 구현 여부: 이 문서 작성 시점에는 구현하지 않음

이 문서는 포켓파인더 확장만 다룬다. 포켓내비의 포켓몬 검색 기능, 도감, 마을지도, NPC 보상 지급 조건은 이 문서의 범위가 아니다.

## 2. 목표

기존 포켓파인더의 외형과 조작감을 유지하면서 다음 정보를 하나의 레이더 안에 자연스럽게 표시한다.

- 주변에 실제로 생성된 포켓몬
- 주변 트레이너와 플레이어별 승리 상태
- 중요 NPC와 관장
- 포켓몬센터와 포켓몬숍
- 카지노를 포함한 특수 건물
- 동굴 입구와 숲 입구
- 마을·도로 사이의 관문
- 현재 진행에 필요한 주요 목표

포켓파인더는 지형을 보여 주는 일반 미니맵이 아니라, 주변의 생명체와 탐험 목적지를 찾는 탐색 HUD로 정의한다.

## 3. 비목표

다음 기능은 구현하지 않는다.

- 지형, 청크, 도로 또는 건물 평면도 렌더링
- 다른 플레이어 위치 표시
- 숨겨진 상자, 아이템 또는 미발견 비밀 표시
- 포켓내비의 서식지·출현 조건 검색 기능 복제
- CobbleNav 원본 JAR 직접 수정
- 1차 구현에서 마커 클릭 이동이나 자동 길찾기 제공

## 4. 확인된 CobbleNav 2.3.3 동작

현재 포켓파인더는 다음 구조로 동작한다.

- 양손 중 한 곳에 포켓파인더를 들고 있을 때 HUD를 렌더링한다.
- 플레이어를 중심으로 크기 128의 AABB를 만들고 `PokemonEntity`를 검색한다. 실질적인 축별 탐색 반경은 약 64블록이다.
- 플레이어의 시야 회전에 맞춰 포켓몬의 X/Z 상대 좌표를 레이더 좌표로 변환한다.
- 포켓몬 필터는 `Pokemon` 객체만 입력받는다.
- 포켓몬 점 렌더링과 설정 화면은 NPC나 장소 마커를 추가하는 공개 확장 지점을 제공하지 않는다.
- 기존 HUD는 Minecraft `Gui.renderTitle` 진입 시점에 렌더링된다.

따라서 건물이나 NPC를 기존 포켓몬 필터로 표현하지 않는다. Cobbleventure가 별도의 범용 마커 계층을 제공하되, 기존 레이더와 같은 위치·회전·축척을 사용한다.

## 5. UX 결정

### 5.1 하나의 레이더로 보이게 한다

화면에 두 번째 패널을 만들지 않는다. 기존 CobbleNav 배경 위의 동일한 레이더 영역에 Cobbleventure 마커를 렌더링한다.

렌더 순서는 다음과 같다.

1. CobbleNav가 기존 레이더 배경과 포켓몬 점을 렌더링한다.
2. Cobbleventure가 같은 좌표계로 NPC·시설·입구·목표 아이콘을 렌더링한다.
3. 우선순위와 겹침 규칙에 따라 중요한 마커를 위에 표시한다.

구현은 별도 렌더 계층이지만 사용자에게는 하나의 포켓파인더 HUD로 보여야 한다. 레이더 밖에 별도의 목록 창이나 미니맵을 상시 표시하지 않는다.

### 5.2 표시 범위

마커 성격에 따라 범위를 분리한다.

| 대상 | 기본 범위 | 범위 밖 처리 |
| --- | ---: | --- |
| 포켓몬 | 기존 CobbleNav 반경 약 64블록 | 표시하지 않음 |
| 일반 트레이너 | 반경 64블록 | 표시하지 않음 |
| 중요 NPC | 반경 64블록 | 현재 목표인 경우에만 가장자리 표시 |
| 관장 | 현재 마을 또는 구역 | 레이더 가장자리에 방향과 거리 표시 |
| 포켓몬센터·포켓몬숍 | 현재 마을 또는 구역 | 레이더 가장자리에 방향과 거리 표시 |
| 카지노·특수 건물 | 현재 마을 또는 구역 | 레이더 가장자리에 방향과 거리 표시 |
| 동굴·숲·관문 입구 | 현재 구역 | 레이더 가장자리에 방향과 거리 표시 |
| 현재 목표 | 현재 구역 | 레이더 가장자리에 방향과 거리 표시 |

장소 마커는 무제한 거리에서 표시하지 않는다. 서버가 판단한 현재 마을·도로·구역에 속한 마커만 전송한다. 구역 판정을 사용할 수 없는 초기 구현에서는 같은 차원, 최대 256블록을 임시 상한으로 사용한다.

### 5.3 차원과 실내 처리

- 현재 플레이어와 다른 차원의 마커는 표시하지 않는다.
- 외부에서는 관장 NPC의 실내 좌표 대신 체육관 입구를 표시한다.
- 체육관 내부에서는 관장 NPC를 표시한다.
- 포켓몬센터, 포켓몬숍, 카지노도 외부에서는 출입구를 표시한다.
- 실내에서는 모든 종업원을 표시하지 않고 진행상 중요한 NPC만 표시한다.

### 5.4 혼잡도 제한

- 단순 대사 NPC는 기본적으로 표시하지 않는다.
- 기본 NPC 대상은 트레이너, 관장, 기능 해금 NPC, 보상 NPC, 현재 목표 NPC로 제한한다.
- 같은 위치에 마커가 겹치면 `현재 목표 > 관장 > 중요 NPC > 시설 > 입구 > 일반 트레이너` 순으로 표시한다.
- 낮은 우선순위 마커는 약간 벌리거나 대표 마커로 합친다.
- 이름은 항상 표시하지 않는다. 가까운 마커, 현재 목표 또는 설정에서 이름 표시를 켠 종류만 출력한다.

## 6. 마커 모델

Cobbleventure 마커는 포켓몬 엔티티와 독립적인 범용 모델을 사용한다.

```text
RadarMarker
  id              안정적인 마커 ID
  type            마커 종류
  dimension       위치한 차원
  position        실제 위치 또는 출입구 위치
  label           표시 이름 또는 번역 키
  icon            아이콘 ID
  priority        겹침 처리 우선순위
  state           플레이어별 상태
  areaId          마을·도로·구역 ID
  localRange      로컬 표시 반경
  edgeTracking    범위 밖 가장자리 표시 여부
```

최소 마커 종류는 다음과 같이 정의한다.

```text
TRAINER
GYM_LEADER
IMPORTANT_NPC
POKEMON_CENTER
POKEMART
CASINO
SPECIAL_BUILDING
CAVE_ENTRANCE
FOREST_ENTRANCE
GATE
OBJECTIVE
```

포켓몬은 이 모델로 복제하지 않는다. 기존 CobbleNav 렌더링을 그대로 사용한다.

`state`는 최소한 다음 상태를 표현할 수 있어야 한다.

- 트레이너: `AVAILABLE`, `DEFEATED`, `REMATCH_AVAILABLE`, `DISABLED`
- NPC: `AVAILABLE`, `COMPLETED`, `INACTIVE`
- 시설·입구: `AVAILABLE`, `LOCKED`, `INACTIVE`
- 목표: `PRIMARY`, `SECONDARY`, `COMPLETED`

## 7. 데이터 소유권

### 7.1 서버 권위 데이터

NPC, 시설, 입구와 진행 상태는 서버가 판정한다. 클라이언트가 카탈로그 파일을 읽어 실제 월드 좌표를 추측해서는 안 된다.

| 정보 | 기준 데이터 |
| --- | --- |
| 포켓몬 | 기존 CobbleNav가 클라이언트의 실제 `PokemonEntity` 사용 |
| 건물과 출입구 | `BuildingRuntimeSystem`의 실제 배치 인스턴스와 출입구 좌표 |
| 숲 입구와 관문 | `WorldGateSystem`이 계산한 실제 통과 지점 |
| 동굴 입구 | 월드 생성 계획 또는 생성 완료 후 저장된 실제 입구 좌표 |
| 일반 트레이너 | 로드된 EasyNPC와 서버의 트레이너 분류 |
| 트레이너 승리 상태 | 해당 플레이어의 `cv_npc_defeated` 계열 상태 |
| 관장과 중요 NPC | NPC 역할 분류와 현재 이벤트·진행 상태 |
| 현재 목표 | 진행 시스템이 선택한 플레이어별 목표 |

건물 카탈로그의 구조물 ID와 분류는 마커 종류를 결정하는 보조 자료로만 사용한다. 실제 위치는 런타임 배치 결과를 사용한다.

### 7.2 클라이언트 데이터

클라이언트는 서버가 보낸 현재 스냅샷과 표시 설정만 보관한다.

- 현재 차원·구역의 마커 스냅샷
- 종류별 표시 여부
- 이름과 거리 표시 여부
- 색상·아이콘 접근성 설정

클라이언트는 건물 블록 검색이나 EasyNPC 전체 스캔을 매 프레임 수행하지 않는다.

## 8. 권장 구현 구조

포켓파인더 연동은 전용 모듈로 분리하는 것을 우선안으로 한다.

```text
projects/cobbleventure-pokefinder
├─ common marker model
├─ server RadarMarkerService
├─ marker snapshot network packet
├─ client RadarMarkerSnapshot
├─ CobbleNav HUD integration
└─ PokéFinder settings integration
```

월드 생성 모듈은 실제 배치 정보에 대한 읽기 전용 조회 기능을 제공한다. 전용 모듈이 어렵거나 의존성 순환이 발생할 경우 네트워크와 렌더링은 클라이언트 기능 모듈에 두고, 월드 런타임 쪽에는 공급자 인터페이스만 둔다. `cobbleventure-player-menu`에 넣지는 않는다. 포켓파인더는 플레이어 메뉴와 독립적으로 동작하는 아이템 HUD이기 때문이다.

### 8.1 서버 흐름

```text
실제 건물 배치 ─┐
관문·동굴 위치 ─┼─ RadarMarkerService ─ 마커 필터링 ─ 스냅샷 패킷
NPC·진행 상태  ─┘
```

서버는 다음 경우에 스냅샷을 갱신한다.

- 플레이어 로그인 또는 차원 이동
- 마을·도로·구역 변경
- 일정 거리 이상 이동
- 트레이너 전투나 NPC 이벤트 상태 변경
- 건물, 관문 또는 입구 활성 상태 변경

동적 NPC 위치는 최대 10틱 주기로 갱신할 수 있다. 정적 시설과 입구는 구역 진입 시 한 번 보내고 상태가 바뀔 때만 다시 보낸다. 매 틱 전체 월드를 검색하지 않는다.

### 8.2 클라이언트 렌더링

- 기존 포켓파인더를 손에 들었는지 확인한다.
- CobbleNav와 동일한 왼쪽·오른쪽 배치 기준을 사용한다.
- 기존 배경 렌더 이후 Cobbleventure 마커를 그린다.
- 플레이어 yaw를 사용해 월드 X/Z 차이를 레이더 좌표로 회전한다.
- 로컬 마커는 레이더 내부에, 추적 마커는 경계선에 고정한다.
- Y 차이가 큰 경우 위·아래 보조 표시를 사용하되, 1차 구현에서 필수는 아니다.

CobbleNav 내부의 비공개 메서드에 직접 의존하는 Mixin은 최소화한다. 우선 `Gui.renderTitle`에서 기존 CobbleNav 렌더 뒤에 동작하는 독립 계층을 사용하고, 기준 좌표와 축척을 한 곳의 호환성 어댑터에 격리한다.

```text
Cobblenav233LayoutAdapter
  radarOrigin(...)
  radarBounds(...)
  worldToRadar(...)
```

이렇게 하면 CobbleNav 버전 변경 시 어댑터만 다시 검증할 수 있다.

## 9. 설정 화면

HUD만 확장하고 설정을 별도 명령어나 일반 설정 파일에만 두면 덧붙인 기능처럼 느껴질 수 있다. 따라서 포켓파인더 설정 화면 안에서 Cobbleventure 마커 설정으로 진입할 수 있어야 한다.

권장 구성은 다음과 같다.

- 기존 포켓몬 필터 화면은 유지한다.
- 같은 화면에 `탐색 정보` 버튼 또는 탭을 추가한다.
- 탐색 정보 화면은 기존 포켓파인더 화면의 배경·버튼 스타일을 따른다.
- 종류별 토글: 트레이너, 중요 NPC, 시설, 입구, 목표
- 세부 토글: 이름 표시, 거리 표시, 승리한 트레이너 표시

기존 화면 주입이 버전 변화에 지나치게 취약하면 포켓파인더 사용 시 통합 화면을 여는 대체 방식으로 전환한다. 단순히 별도 키 설정만 추가하는 방식은 최종안으로 사용하지 않는다.

## 10. 아이콘 규칙

- 포켓몬: CobbleNav 기본 점 유지
- 일반 트레이너: 배틀을 연상시키는 단색 아이콘
- 승리한 트레이너: 같은 아이콘을 어둡게 표시하거나 체크 표시
- 관장: 배지 또는 강조된 트레이너 아이콘
- 포켓몬센터: 센터 전용 아이콘
- 포켓몬숍: 상점 전용 아이콘
- 카지노: 코인 또는 카드 아이콘
- 동굴: 동굴 입구 아이콘
- 숲: 나무 아이콘
- 관문: 문 또는 게이트 아이콘
- 현재 목표: 별 또는 깃발 아이콘

색상만으로 상태를 구분하지 않는다. 아이콘 형태나 보조 기호를 함께 사용한다. 작은 HUD에서 식별할 수 있도록 5~7픽셀 기준으로 제작하고 실제 게임 UI 배율 1~4에서 확인한다.

## 11. 구현 단계

### 1단계: 호환성 골격

- CobbleNav 2.3.3 의존성과 아이템 판정 확인
- 기존 레이더 기준점·회전·축척을 재현하는 어댑터 작성
- 테스트 마커 하나를 레이더 내부와 가장자리에 렌더링
- 주손·보조손과 GUI 배율별 정렬 검증

### 2단계: 정적 장소

- 포켓몬센터와 포켓몬숍
- 체육관 입구와 카지노·특수 건물
- 동굴 입구, 숲 입구, 관문
- 서버 런타임 위치 조회와 정적 스냅샷 전송

### 3단계: NPC와 플레이어별 상태

- 일반 트레이너와 관장 분류
- 플레이어별 승리·재대결 상태
- 중요 NPC와 현재 목표
- 상태 변경 시 부분 또는 전체 스냅샷 갱신

### 4단계: 통합 설정과 마감

- 포켓파인더 설정 화면에 탐색 정보 탭 추가
- 종류별 필터와 이름·거리 옵션
- 마커 겹침, 우선순위, 접근성 처리
- 실제 마을·실내·관문·동굴에서 통합 검증

마커 선택 후 지속 추적, 발견 여부 시스템, 상세 정보 패널은 후속 단계로 남긴다.

## 12. 완료 기준

다음 조건을 모두 만족해야 1차 구현이 완료된 것으로 본다.

- 포켓파인더를 들지 않았을 때 추가 HUD가 보이지 않는다.
- 기존 포켓몬 점과 필터가 이전과 동일하게 동작한다.
- 추가 마커가 기존 레이더 안에 정렬되어 별도 패널처럼 보이지 않는다.
- 주손과 보조손에서 레이더 위치가 올바르다.
- 플레이어 회전 시 모든 추가 마커가 포켓몬 점과 같은 방향으로 회전한다.
- 센터, 상점, 체육관, 카지노, 동굴, 숲, 관문이 실제 출입구 좌표를 가리킨다.
- 다른 차원의 NPC나 시설이 표시되지 않는다.
- 체육관 외부에서는 입구를, 내부에서는 관장을 가리킨다.
- 트레이너 승리 상태가 플레이어별로 다르게 표시된다.
- 일반 NPC가 과도하게 표시되지 않는다.
- 화면을 닫거나 포켓파인더를 내렸을 때 추가 렌더링 비용이 발생하지 않는다.
- 클라이언트가 건물이나 NPC 전체를 매 프레임 검색하지 않는다.
- UI 배율 1, 2, 3, 4에서 아이콘이 레이더 밖으로 벗어나지 않는다.
- CobbleNav가 없을 때의 실패 방식이 명확하다. 모드팩 필수 의존성으로 유지한다면 시작 시 의존성 오류를 명확히 내고, 선택 의존성으로 바꾸면 관련 기능만 비활성화한다.

## 13. 테스트 항목

### 단위 테스트

- 월드 좌표에서 레이더 좌표로의 회전 변환
- 반경 내부·외부 판정과 경계 고정
- 마커 우선순위와 겹침 처리
- 구조물 ID에서 마커 종류로의 분류
- 플레이어별 트레이너 상태 변환
- 차원과 구역 필터링

### 통합 테스트

- 두 플레이어에게 같은 트레이너의 상태가 다르게 전송되는지 확인
- 마을 입장 시 정적 장소 스냅샷이 한 번 생성되는지 확인
- 관문 통과와 차원 이동 후 이전 마커가 제거되는지 확인
- 건물 재배치 또는 월드 재생성 후 실제 출입구 위치를 가리키는지 확인
- CobbleNav 포켓몬 필터 변경이 추가 장소 필터에 영향을 주지 않는지 확인

### 시각 검증

- 포켓몬과 트레이너 아이콘이 겹친 상황
- 시설이 레이더 범위 밖에 있는 상황
- 관장이 별도 실내 차원에 있는 상황
- 마을 중심처럼 마커가 많은 상황
- 좌우 손 전환과 모든 GUI 배율

## 14. 호환성 원칙

- 최초 구현은 CobbleNav 2.3.3을 명시적으로 지원한다.
- CobbleNav 내부 클래스 의존 코드는 호환성 어댑터와 설정 화면 Mixin으로 제한한다.
- 일반 마커 모델, 서버 조회, 네트워크 코드는 CobbleNav 클래스에 의존하지 않는다.
- 버전 업데이트 시 HUD 기준점, 아이템 클래스, 설정 화면, 렌더 호출 시점을 우선 회귀 검증한다.
- CobbleNav 전체 포크는 공개 확장 지점 추가가 반드시 필요한 상황이 확인되기 전까지 사용하지 않는다.
