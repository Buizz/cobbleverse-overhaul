# 월드 초기화 및 지역 경계

> 관련 요구사항: F-01, F-06, F-07
>
> 적용 후보: 1안 어드벤처, 3안 하이브리드
>
> 설계 상태: 기술 조사 진행 / 최종 아키텍처 미정

## 1 목적

1안 또는 3안을 선택할 경우 세대 월드가 처음 만들어질 때 지역 1부터 8까지 필요한 청크를 미리 생성하고, 지역 셀·체육관 도시·도로·관문·경계를 결정론적으로 배치한다. 지역 사이의 이동로를 제한하고 8번째 지역 이후 리그 포탈로 연결한다. 1안은 채집·건축을 제외하고, 3안은 이를 별도 서바이벌 공간으로 분리한다.

## 2 사전 생성과 상시 로드의 차이

필요한 청크를 **사전 생성한 뒤 언로드**하는 방식을 사용한다. 전체 지역을 `forceload`로 계속 유지하지 않는다.

| 방식 | 결과 | 판단 |
|------|------|------|
| 청크 사전 생성 | 지형과 구조물을 디스크에 미리 생성한 뒤 메모리에서 해제 | 권고 |
| 청크 상시 로드 | 플레이어가 없어도 메모리와 틱 대상에 계속 남음 | 핵심 거점 일부 외 금지 |
| 플레이 중 즉시 생성 | 첫 방문 시 지연과 구조물 배치 실패 가능 | 외곽 자유 탐험에만 허용 |

사전 생성 반경은 면적으로 증가한다. 반경을 두 배로 늘리면 대상 청크 수는 대략 네 배가 되므로 세대 월드 전체를 무작정 생성하지 않는다. 실제 콘텐츠 셀과 연결 통로 주변만 직사각형 선택 영역으로 생성한다.

## 3 월드 초기화 수명주기

```text
월드 시드와 콘텐츠 버전 확정
  → 지역 그래프 계획
  → 지역 셀·마을·관문 앵커 저장
  → 필요한 청크 사전 생성
  → 구조물·경계·통로 배치 확인
  → 연결성과 안전 좌표 검증
  → 월드 READY 전환
  → 플레이어 입장 허용
```

초기화 중에는 일반 플레이어의 해당 세대 차원 입장을 막는다. 실패하면 마지막 단계부터 재개할 수 있도록 단계별 상태와 결과를 저장한다.

| 상태 | 설명 |
|------|------|
| `PLANNED` | 지역 그래프와 앵커 계산 완료 |
| `PREGENERATING` | 필요한 청크 생성 중 |
| `PLACING` | 필수 구조물과 경계 설치 중 |
| `VERIFYING` | 연결성, 충돌과 누락 검사 중 |
| `READY` | 플레이어 입장 가능 |
| `FAILED` | 복구 또는 관리자 확인 필요 |

## 4 지역 그래프

세대 월드를 무작위 바이옴 덩어리로만 보지 않고 순서가 있는 지역 셀 8개와 제한 통로로 구성된 그래프로 관리한다.

```text
[지역 1·시작 도시]
       │ 관문 1→2
[지역 2·체육관 도시]
       │
      ...
       │ 관문 7→8
[지역 8·최종 체육관]
       │ 리그 포탈
[transition·챔피언로드와 리그]
```

각 지역의 기본 이웃은 이전·다음 지역이며 모든 바이옴이 서로 직접 연결되지 않는다. 진행에 필요한 통로는 고정하고 선택형 지름길은 설정에 명시된 경우에만 배지, 아이템 또는 이벤트로 해금한다.

어드벤처 모드가 블록 파괴·설치를 막더라도 순간이동과 탈것을 통한 월경은 가능할 수 있다. 코어 모드는 플레이어가 지역 경계를 넘는 순간 출발 지역, 목적 지역, 관문 ID와 개인 진행 상태를 검사하며 비정상 진입은 마지막 체크포인트로 되돌린다. 공중날기 비전머신이 적용된 포켓몬의 정상 비행 탑승은 같은 세대 월드 안에서 이 경계 검사의 허용 예외로 처리한다.

| 필드 | 설명 |
|------|------|
| `region_id` | 지역 식별자 |
| `generation_id` | 소속 세대 월드 |
| `chunk_bounds` | 청크 단위 지역 경계 |
| `biome_profile` | 지역의 지형·바이옴 구성 |
| `village_anchor` | 마을 또는 도시 기준 좌표 |
| `neighbors` | 직접 연결된 지역 목록 |
| `gates` | 연결 통로와 관문 정의 |
| `boundary_profile` | 산맥, 협곡, 바다, 성벽 등 경계 외형 |
| `spawn_profile` | 세대 중심 혼합 스폰 프로필 |

### 4.1 바이옴 배치 제어 수준

마인크래프트 기본 바이옴은 완전한 무작위가 아니라 월드 시드와 온도, 습도, 대륙성, 침식, 기이도와 깊이 등의 노이즈 값으로 결정된다. 같은 시드와 생성 설정에서는 같은 좌표에 같은 바이옴이 생성된다.

바이옴을 통제하는 방법은 세 단계로 나뉜다.

| 수준 | 방법 | 보장 범위 |
|------|------|-----------|
| 바닐라 기후 조정 | `multi_noise` 매개변수와 `spawn_target` 수정 | 시작점이 원하는 기후에 가까워질 가능성을 높임 |
| 거리 기반 모드 | 중심점에서의 최소·최대 거리별 바이옴 풀 지정 | Core Keeper식 동심원 지역을 빠르게 구현 |
| 커스텀 `BiomeSource` | 좌표, 거리, 각도와 지역 그래프를 코드로 판정 | 시작 바이옴과 인접 지역을 결정론적으로 보장 |

`spawn_target`은 바이옴 ID를 직접 고정하는 기능이 아니라 시작점 탐색에 사용할 기후 목표값 목록이다. 비슷한 기후 매개변수를 공유하는 바이옴이 있거나 지형이 부적합하면 원하는 바이옴을 강하게 보장하기 어렵다.

프로젝트에는 커스텀 `BiomeSource`를 권고한다.

```text
월드 좌표
  → region planner의 지역 셀 조회
  → 경계까지의 거리와 관문 마스크 계산
  → 지역 내부·경계 지대·통로 판정
  → 높이와 기후 노이즈로 세부 바이옴 선택
  → 실제 바이옴 반환
```

이를 통해 다음과 같은 배치를 시드와 무관하게 보장할 수 있다.

```text
중앙: 시작 평원·마을
동쪽: 숲 지역
북쪽: 산악·설원 지역
남쪽: 해안 지역
서쪽: 경계 지대와 다음 진행 지역
```

지역 안의 세부 경계에는 노이즈를 더해 같은 배치 규칙이어도 시드마다 해안선, 숲 가장자리와 산맥 모양이 달라지게 한다. 즉 콘텐츠의 상대 위치는 고정하고 지형 모양은 절차적으로 변주한다.

### 4.2 시작 스폰 보장

시작 스폰은 다음 순서로 결정한다.

1. `starter_region`을 평원 중심 바이옴 풀로 고정한다.
2. 지역 안에서 수면, 경사, 충돌과 구조물 조건을 검사한다.
3. 시작 마을 앵커와 안전 스폰 좌표를 함께 확정한다.
4. 청크 사전 생성 후 지형과 마을 연결성을 검증한다.
5. 검증된 좌표를 해당 세대 차원의 월드 스폰으로 저장한다.

이 방식은 바닐라가 자동으로 선택한 월드 스폰에 의존하지 않는다. 실패 시 같은 순서로 다음 후보를 검사하므로 같은 시드와 설정에서 항상 같은 결과를 얻는다.

### 4.3 기존 월드와 호환성

바이옴 소스를 바꾸면 이미 생성된 청크는 변경되지 않고 새 청크만 새 규칙을 사용해 경계에 심한 이음새가 생길 수 있다. 따라서 세대 차원은 생성 전에 바이옴 소스와 지원 바이옴 목록을 고정하고, 변경 시 새 차원 버전으로 이관하는 것을 원칙으로 한다.

다른 바이옴 모드가 자체 방식으로 바이옴을 주입하면 프로젝트의 위치 보장을 깨뜨릴 수 있다. 호환 모드의 바이옴을 무조건 자동 수용하지 않고 세대별 허용 목록과 지역 프로필에 명시적으로 등록한다.

## 5 경계 표현 방식

### 5.1 자연 경계

산맥, 깊은 협곡, 바다, 거대한 강, 울창한 숲과 절벽으로 지역을 나눈다. 일반적인 포켓몬 세계 분위기와 가장 잘 맞고 시야에서도 자연스럽다.

### 5.2 인공 경계

성벽, 폐허, 방벽과 검문소를 청크 경계에 반복 구조물로 배치한다. 세계관상 이유가 명확한 도시권, 격리 구역이나 리그 구역에만 선택적으로 사용한다.

### 5.3 논리 경계

물리 경계를 넘어가더라도 서버가 진행 조건을 검사해 되돌리거나 허용된 관문으로 이동시킨다. 블록 파괴, 비인가 비행, 순간이동과 다른 모드를 통한 우회를 막는 최종 안전장치다. 인가된 공중날기는 지역 이동만 허용하고 체육관·리그 등 콘텐츠 해금 상태는 변경하지 않는다.

권고안은 다음처럼 세 계층을 조합한다.

```text
자연 산맥·협곡으로 방향 유도
  + 관문·터널로 허용 통로 표현
  + 서버 측 진행 검사로 우회 차단
```

모든 바이옴 사이에 동일한 거대 성벽을 두면 반복감이 크고 건축·채굴·비행 우회 대응이 어려워진다. 인공 벽은 테마가 맞는 일부 지역에 사용하고 대부분은 자연 경계로 처리한다.

### 5.4 Core Keeper식 경계 지대

Core Keeper는 중심부를 굴곡진 대장벽이 감싸 진행을 잠그고, 바이옴 경계에는 참호와 서로 다른 단단한 지형 블록을 사용한다. 이 아이디어를 마인크래프트에 적용할 때는 경계를 한 줄짜리 벽이 아니라 폭을 가진 별도의 `boundary biome`으로 취급한다.

```text
평원 지역
  → 고대 성벽·절벽 경계 지대
  → 관문·터널·폐허 통로
  → 숲 지역
```

경계 지대는 양쪽 바이옴과 구별되는 지형, 블록, 안개, 식생, 구조물과 포켓몬 스폰을 가진다. 단순 장애물이 아니라 탐험 가능한 소규모 콘텐츠 구역으로 만든다.

| 경계 프로필 | 어울리는 지역 연결 | 통과 방식 |
|-------------|--------------------|-----------|
| 고대 대장벽 | 시작 지역 ↔ 외부 고난도 지역 | 보스·배지 완료 후 관문 활성화 |
| 산맥 지대 | 평원 ↔ 설원·고원 | 산길, 터널 또는 케이블카 |
| 대협곡 | 숲 ↔ 사막·황무지 | 다리, 동굴 또는 비행 이동 |
| 거대 뿌리숲 | 평원 ↔ 깊은 숲 | 베기 기술, 미로 또는 숲길 |
| 수정·운석 지대 | 일반 지역 ↔ 특수 생태 구역 | 퍼즐·키 아이템·던전 |
| 해협·절벽 해안 | 대륙 ↔ 섬·해안 | 배, 항구 또는 해저 터널 |

논리 경계는 청크 셀에 맞추되 눈에 보이는 외곽선은 저주파 노이즈로 좌우에 변위를 줘 직선과 계단 모양을 숨긴다. 경계 폭도 일정하게 하지 않고 넓고 좁은 구간을 섞는다.

```text
청크 셀 경계: 충돌·보호·진행 판정용
노이즈 경계선: 실제 산맥·벽·협곡의 중심선
경계 폭 함수: 시각적 두께와 탐험 공간 결정
관문 마스크: 허용된 통로만 경계 지형을 절단
```

경계 바이옴에는 전용 포켓몬과 희귀 자원을 소량 배치해 플레이어가 벽을 단순한 로딩 장치로 느끼지 않게 한다. 다만 필수 보상은 관문 밖에서 채굴·비행으로 접근할 수 없도록 구조물과 진행 상태로 보호한다.

## 6 청크 경계와 생성 순서

지역 셀의 외곽을 청크 좌표에 맞추면 반복 벽 조각, 보호 범위와 충돌 검사가 단순해진다. 실제 마인크래프트 바이옴 경계는 청크 경계와 일치하지 않으므로 두 개념을 분리한다.

- `region_id`와 진행 경계는 청크 셀 기준으로 관리한다.
- 시각적 바이옴은 셀 안쪽에서 자연스럽게 혼합한다.
- 경계 구간은 산맥·협곡·벽 전용 바이옴 또는 구조물 조각을 사용한다.
- 관문 청크만 통과 가능한 낮은 지형과 도로를 생성한다.

사전 생성 후 대규모 벽을 사후 설치하면 플레이어 건축물 훼손, 잘린 구조물과 지형 이음새가 생길 수 있다. 가능하면 지역 계획 데이터를 월드 생성기가 읽고 해당 청크 생성 과정에서 경계와 마을을 함께 배치한다. 사후 설치는 복구와 프로토타입에만 사용한다.

## 7 마을과 관문 배치

각 지역의 마을과 관문은 무작위 구조물 탐색에 맡기지 않고 계획 단계에서 앵커를 확정한다.

1. 지역 셀 안에서 평탄도, 수면과 충돌 조건을 만족하는 마을 후보를 찾는다.
2. 같은 순서로 후보를 평가해 마을 앵커를 결정한다.
3. 이웃 지역 방향을 기준으로 관문 청크를 결정한다.
4. 마을과 관문을 잇는 도로 회랑을 예약한다.
5. 청크 생성 시 마을, 도로와 경계 구조물을 배치한다.
6. 사전 생성 완료 후 실제 보행 경로가 연결됐는지 검사한다.

관문은 플레이어별 진행 조건을 검사한다. 멀티플레이에서는 공용 문이 열렸다는 사실만으로 통과를 허용하지 않는다.

## 8 도구 후보

### 8.1 Chunky

Chunky는 Minecraft 1.21.1 Fabric을 지원하며 사각형·원형 등 선택 영역을 사전 생성할 수 있다. 커스텀 월드 생성도 Chunky가 직접 지형을 만들지 않고 서버 생성기에 요청하므로 프로젝트 차원과 구조물 검증에 적합하다.

권고 용도는 배포 서버의 최초 초기화와 개발용 반복 성능 측정이다. 사전 생성 작업은 운영 플레이와 분리하고 완료 후 청크를 상시 로드하지 않는다.

### 8.2 Fabric Chunk Pregenerator

Fabric 전용 대안이며 1.21.1을 지원한다. 사각형 반경 기반의 단순한 사전 생성에는 사용할 수 있지만 다중 영역, 작업 재개와 자동화 요구를 비교한 뒤 선택한다.

### 8.3 Biome Rings

Biome Rings는 Minecraft 1.21.1 Fabric에서 월드 중심으로부터의 최소·최대 거리와 가중치로 바이옴 풀을 강제하는 모드다. Core Keeper식 동심원 배치의 빠른 개념 검증에는 적합하다.

모드 설명상 다른 커스텀 바이옴·지형 생성 모드와의 호환성이 거의 검증되지 않았으므로 정식 의존성으로 바로 채택하지 않는다. 다음 항목을 확인하는 프로토타입 또는 커스텀 `BiomeSource` 구현 참고 사례로 사용한다.

## 9 프로토타입

첫 실험은 세대 전체가 아니라 세 지역만 만든다.

```text
region_plains  ── gate_forest ── region_forest
                                      │
                                 gate_mountain
                                      │
                                region_mountain
```

1. 각 지역을 작은 청크 사각형으로 계획한다.
2. 평원·숲·산악 프로필과 마을 앵커를 하나씩 지정한다.
3. 연결되지 않은 경계에는 굴곡진 경계 바이옴을, 연결부에는 관문을 배치한다.
4. Chunky로 세 지역과 통로 주변만 사전 생성한다.
5. 마을, 도로, 경계와 관문 연결성을 검증한다.
6. 허용되지 않은 경계의 채굴·비인가 비행·텔레포트 우회를 시험한다.
7. 인가된 공중날기 탑승은 지역 경계를 통과하지만 콘텐츠 잠금은 유지되는지 시험한다.
7. 생성 시간, 디스크 크기와 최대 메모리를 기록한다.

## 10 검증 항목

- 같은 시드와 콘텐츠 버전에서 지역 그래프와 앵커가 동일한가?
- 모든 필수 마을과 관문이 사전 생성 영역 안에 존재하는가?
- 허용된 통로만으로 모든 필수 지역에 도달할 수 있는가?
- 자연 경계와 구조물 벽에 잘린 청크 이음새가 없는가?
- 초기화 완료 후 불필요한 강제 로드 청크가 남지 않는가?
- 월드 업데이트가 기존 경계와 플레이어 건축물을 덮어쓰지 않는가?
- 세대별 사전 생성 시간과 디스크 사용량이 운영 한도 안인가?

- 기존 월드에 새 지역 셀을 추가할 때 어떤 확장·이관 절차를 사용할 것인가?
