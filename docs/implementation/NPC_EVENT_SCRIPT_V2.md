# NPC 이벤트 스크립트 V2 구현 계획

> 상태: 구현 계획 확정 전 설계안
>
> 작업명: `NPC-EVENT-V2`
>
> 적용 범위: NPC 이벤트 원본, 콘텐츠 관리 웹, 이벤트 런타임, EasyNPC 변환기

## 1. 목적

현재 NPC 이벤트 원본은 EasyNPC의 대화 라벨, 조건 태그와 명령 액션을 사람이
직접 다루는 형태에 가깝다. 이 때문에 실제 이야기의 흐름보다 변환 대상의 제약이
먼저 노출되고, 조건이 늘어날수록 라벨과 이동 명령을 따라가야 전체 흐름을 알 수
있다. 룰렛, 배틀, 아이템 획득 연출처럼 대화창이 닫혔다가 다시 열리는 작업은
NPC UUID와 후속 라벨을 기능마다 별도로 전달하고 있어 확장과 복구도 어렵다.

V2의 목표는 다음과 같다.

- 제작자는 EasyNPC 태그와 SNBT 구조를 편집하지 않는다.
- RPG Maker XP의 이벤트 명령처럼 위에서 아래로 읽히는 전용 스크립트를 사용한다.
- 일반 조건 분기와 선택지는 중첩 트리로 표현하고 라벨을 요구하지 않는다.
- 대화, 선택지, 배틀, 룰렛과 아이템 획득 연출은 같은 실행 모델로 중단·재개한다.
- 명령 결과와 계산 값을 타입 변수로 보관하고 현지화 대사 안에서 사용할 수 있다.
- 플레이어와 NPC의 상대 이동부터 마을·차원 간 안전 이동까지 이벤트 명령으로 표현한다.
- 웹 편집기, 검증기와 게임 런타임이 하나의 의미 모델을 공유한다.
- EasyNPC는 NPC 엔티티 표현과 호환 출력 어댑터로 한정한다.

## 2. 현재 구조의 문제

### 2.1 흐름과 출력 형식의 결합

`branch → label → dialogue → goto`가 EasyNPC의 명명된 대화와 조건 태그로 바로
변환된다. 제작자가 읽는 원본에도 변환 대상의 라벨 개념이 노출되며, 대화 순서를
바꾸면 여러 이동 대상과 결과 라벨을 함께 수정해야 한다.

### 2.2 조건 분기의 가독성

조건의 참·거짓 경로가 같은 명령 목록의 서로 다른 라벨로 흩어진다. 웹에서도
명령이 평면 목록으로 보이기 때문에 중첩 조건, 선택지별 결과와 반복 대화의 범위를
한눈에 확인하기 어렵다.

### 2.3 기능별 후속 대화 연결

현재 스타팅 룰렛은 명령에 NPC와 후속 대화 라벨을 숨겨 전달하고, 배틀은 별도의
콜백 명령을 만들며, 아이템 지급은 다음 대화를 생성기가 추론한다. 모두
“외부 작업이 끝나면 다음 명령부터 계속 실행한다”는 같은 문제지만 기능별 코드로
분리되어 있다.

### 2.4 상태와 보상의 안전성

대화 도중 재접속, NPC 언로드, 차원 이동이나 중복 콜백이 발생했을 때 어느 명령까지
완료했는지 공통으로 기록하지 않는다. 지급 명령이 다시 실행되면 보상이 중복될 수
있고, 반대로 후속 대화만 유실될 수 있다.

## 3. 핵심 결정

### `NPC-EVENT-V2-D01` 전용 언어

전용 언어 이름은 `CVES`(CobbleVenture Event Script)로 한다. NPC 외형 문서는
스크립트 리소스 ID만 참조하고, 이벤트 본문은 다음 위치의 `.cves` 파일로 분리한다.

```text
content/source/npcs/professor_oak.json
content/event_scripts/story/professor_oak.cves
```

웹 API와 Python 도구는 `.cves`를 AST로 파싱하고 안정적인 포매터로 다시 저장한다.
게임은 원본 문법을 직접 해석하지 않고 빌드가 생성한 실행 IR만 읽는다.

### `NPC-EVENT-V2-D02` 트리 우선 제어 흐름

`if`, `else`, `choice`, `repeat`는 자식 명령 블록을 가진다. 평범한 분기에는 라벨과
`goto`를 사용하지 않는다. 라벨, `jump`, 공통 루틴 호출은 복잡한 연출을 위한
고급 명령으로 남기되 웹의 기본 도구 상자에서는 접어 둔다.

### `NPC-EVENT-V2-D03` 전용 런타임

전용 이벤트 런타임이 프로그램 카운터, 지역 변수, 호출 스택, 대기 중 작업과 완료된
일회성 작업을 관리한다. EasyNPC는 다음만 담당한다.

- NPC 외형, 충돌, 이동과 상호작용 감지
- 전용 런타임을 시작하는 단일 진입 명령
- 전환 기간 동안 대화창을 표시하는 렌더러

진행 조건, 보상, 콜백과 다음 대화 결정은 EasyNPC 태그가 아니라 전용 런타임이
소유한다.

### `NPC-EVENT-V2-D04` 자동 중단·재개

결과를 기다리는 명령은 모두 같은 `await` 계약을 구현한다. 컴파일러는 대기 지점과
재개 주소를 자동 생성하며 제작자가 후속 라벨을 지정하지 않는다.

### `NPC-EVENT-V2-D05` 타입 변수와 대사 템플릿

명령 결과, 플레이어 상태와 계산 값은 타입이 있는 변수로 다룬다. 룰렛 결과는 표시
문자열 하나가 아니라 포켓몬 종 ID, 폼, 레벨과 현지화 가능한 이름을 가진
`pokemon_selection` 값이다. 대사는 `${...}` 템플릿으로 변수를 참조하고, 실제
표시 언어와 한국어 조사는 클라이언트의 언어 설정에 맞춰 렌더링한다.

원본 변수에는 `파이리` 같은 번역 결과를 저장하지 않는다. `cobblemon:charmander`와
같은 안정 ID를 저장하고 출력 시점에 현재 언어의 이름을 조회한다.

### `NPC-EVENT-V2-D06` 이동과 위치 타입

이동은 임의 문자열 명령이 아니라 타입이 구분된 목적지로 표현한다.

- `relative`: 현재 위치 기준 상대 이동
- `position`: 현재 또는 지정 차원의 절대 좌표
- `anchor`: 건물 출입구, 포켓몬센터 내부 등 등록된 앵커
- `settlement`: 특정 마을의 기본 또는 역할별 앵커
- `route`: 도로 체크포인트와 관문
- `dimension`: 특정 차원의 등록된 도착 앵커
- `space`: 건물 내부, 동굴과 숲 등 인스턴스 공간

걷기 연출과 순간이동을 분리하고, 순간이동은 청크 준비, 안전 바닥, 배리어층 제외,
충돌 공간과 페이드 완료까지 하나의 비동기 이동 작업으로 처리한다.

## 4. CVES 문법 초안

오박사 이벤트는 다음처럼 읽혀야 한다.

```cves
event interact(range: 4) {
  page when flag("cobbleventure:flag/story/pokedex_received") {
    say npc "이미 첫 포켓몬을 골랐구나. 그 아이와 함께 멋진 모험을 해 보렴!"
  }

  page when flag("cobbleventure:flag/story/starter_received") {
    say npc "좋은 포켓몬을 골랐구나!"
    say npc "그럼 이것도 받아라. 포켓몬 도감이란다."
    give_item "cobblemon:pokedex_red" count 1 notify
    set_flag "cobbleventure:flag/story/pokedex_received" true
    say npc "포켓몬 도감은 만난 포켓몬과 잡은 포켓몬의 정보를 자동으로 기록해 준단다."
  }

  page default {
    say npc "어서 오너라! 나는 포켓몬을 연구하는 오박사란다."
    say npc "이제 너와 함께 모험할 첫 포켓몬을 정해 보자꾸나!"
    await starter_roulette -> starter
    say npc "${starter.name|josa:을/를} 골랐구나!"
    say npc "그럼 이것도 받아라. 포켓몬 도감이란다."
    give_item "cobblemon:pokedex_red" count 1 notify
    set_flag "cobbleventure:flag/story/pokedex_received" true
    say npc "도감은 만난 포켓몬과 잡은 포켓몬의 정보를 자동으로 기록해 준단다."
  }
}
```

파이리가 선택되면 위 대사는 한국어에서 `파이리를 골랐구나!`로 표시된다. 영어
클라이언트에서는 같은 `starter.species_id`를 사용해 `You chose Charmander!`처럼
언어별 대사 템플릿을 렌더링한다.

`page`는 RPG Maker의 이벤트 페이지에 해당한다. 위에서 아래로 조건을 검사해 처음
일치한 페이지 하나를 실행한다. 웹에서는 우선순위를 명시적으로 표시하며
`default`는 항상 마지막에 둔다.

내부 조건과 선택지는 다음처럼 중첩한다.

```cves
if money() >= 500 {
  choice "무엇을 할까?" {
    "구입한다" {
      take_money 500
      give_item "cobblemon:poke_ball" count 5 notify
      say npc "잘 사용하렴."
    }
    "그만둔다" {
      say npc "다음에 다시 오렴."
    }
  }
} else {
  say npc "돈이 부족하구나."
}
```

### 4.1 1차 명령 집합

| 분류 | 명령 | 실행 성격 |
|------|------|-----------|
| 흐름 | `if`, `choice`, `repeat`, `stop` | 즉시 |
| 대화 | `say`, `narrate`, `show_choices` | 플레이어 입력까지 대기 |
| 상태 | `set_flag`, `set_variable`, `unlock_feature`, `set_level_cap` | 즉시 |
| 보상 | `give_item`, `give_loot`, `give_money`, `take_money`, `grant_badge`, `grant_field_move` | 결과 확인 또는 획득 연출까지 대기 가능 |
| 전투 | `await battle` | 승리·패배·포기 결과까지 대기 |
| 특수 UI | `await starter_roulette`, `await map_selection` | UI 결과까지 대기 |
| 이동 | `await move`, `await teleport`, `await enter_space`, `face` | 경로 이동 또는 페이드와 서버 이동 완료까지 대기 |
| 연출 | `fade`, `wait`, `sound`, `effect` | 지정 완료 조건까지 대기 |
| 고급 | `label`, `jump`, `call`, `return` | 고급 모드에서만 노출 |

명령의 결과는 `-> result`로 지역 변수에 받을 수 있다. 결과가 필요 없는 명령은
변수를 생략한다. `await`를 생략할 수 있는 명령은 컴파일러가 자동 대기 경계를
삽입하지만, 텍스트 보기에서는 실행 성격을 명확히 보여주기 위해 표시한다.

### 4.2 변수와 표현식

1차 타입은 다음으로 제한한다.

| 타입 | 예 | 용도 |
|------|----|------|
| `bool` | `true` | 조건과 성공 여부 |
| `int`, `decimal` | `500`, `1.5` | 돈, 수량, 좌표와 배율 |
| `string` | `"안녕하세요"` | 직접 작성한 짧은 값 |
| `resource_id` | `cobblemon:charmander` | 포켓몬, 아이템과 콘텐츠 ID |
| `position` | 차원 + x/y/z + 회전 | 절대 위치 |
| `location_ref` | 마을·도로·앵커 참조 | 콘텐츠 기반 이동 위치 |
| `pokemon_selection` | 종 ID, 폼, 레벨 | 룰렛과 포켓몬 선택 결과 |
| `battle_result` | 승패, 포기, 상대 | 배틀 결과 |
| `item_result` | 지급 수량, 남은 수량 | 아이템 지급 결과 |
| `movement_result` | 도착 여부, 실패 원인 | 걷기와 순간이동 결과 |

변수 범위는 기본적으로 현재 이벤트 세션이다.

```cves
let reward = level_cap() * 20
let player_name = player.name
give_money reward
say npc "${player_name}, ${reward|number}원을 받거라."
```

영구 상태는 지역 변수 대입으로 만들지 않고 `set_flag` 또는 명시적인
`set_player_variable`을 사용한다. 이를 통해 임시 연출 값과 저장 데이터의 수명을
구분한다.

### 4.3 현지화 대사 템플릿

각 `say`는 언어별 템플릿을 가질 수 있으며 변수 참조 구조는 모든 언어에서 같아야
한다. 지원 필터의 1차 범위는 다음과 같다.

- `name`: 리소스 ID를 현재 언어의 표시 이름으로 변환
- `number`: 현재 언어의 숫자 표기 적용
- `josa:은/는`, `josa:이/가`, `josa:을/를`, `josa:과/와`: 한국어 받침에 맞는 조사 결합
- `fallback`: 값이 없을 때 안전한 기본 문자열 사용

```cves
say npc {
  ko_kr: "${starter.name|josa:을/를} 골랐구나!"
  en_us: "You chose ${starter.name}!"
}
```

템플릿은 명령 실행, Minecraft 선택자와 임의 코드 실행을 허용하지 않는다. 파서는
필드 존재 여부와 필터의 입력 타입을 빌드 시 검증한다.

### 4.4 이동 명령

상대 이동과 콘텐츠 기반 이동은 다음처럼 작성한다.

```cves
# 관문 대화가 끝난 뒤 플레이어를 현재 위치 기준 뒤로 걷게 한다.
await move player relative(x: 0, y: 0, z: -4) {
  mode: walk
  speed: 0.9
  lock_input: true
  collision: stop
} -> moved

# 등록된 마을의 포켓몬센터 내부 앵커로 안전하게 이동한다.
await teleport player settlement("cobbleventure:settlement/pallet_town") {
  anchor: "pokemon_center/interior"
  fade: black
  safe_landing: required
} -> arrival

# 다른 차원의 등록 앵커로 이동한다.
await teleport player dimension("cobbleventure:forest") {
  anchor: "entrance/south"
  fade: black
  preload_chunks: true
} -> forest_arrival
```

`move`의 `mode: walk`는 목표까지 서버 권위의 연출 이동을 수행하고 장애물, 낙하와
시간 초과 시 `movement_result`를 실패로 돌려준다. `mode: offset_teleport`는 짧은
상대 이동이지만 안전 위치 검사 후 한 번에 이동한다. 차원·마을 이동은 항상 등록된
앵커를 우선하며 웹에서 존재하지 않는 앵커를 선택할 수 없게 한다.

이동 실패가 별도 흐름을 가져야 하면 결과 분기를 중첩한다.

```cves
await teleport player settlement("cobbleventure:settlement/cerulean_city") -> travel
if !travel.arrived {
  narrate "안전한 도착 지점을 찾지 못했다."
}
```

### 4.5 세분화된 이벤트 트리거

상호작용과 단순 범위 진입 외에 다음 트리거를 단계적으로 지원한다.

| 트리거 | 발동 시점 |
|--------|-----------|
| `interact` | 플레이어가 NPC에게 말을 걸 때 |
| `proximity_enter`, `proximity_exit` | NPC 주변 범위에 들어오거나 나갈 때 |
| `region_enter`, `region_exit` | 마을, 도로 또는 등록 영역의 경계를 넘을 때 |
| `anchor_step` | 관문선, 문, 특정 타일 앵커를 밟을 때 |
| `building_enter`, `building_exit` | 건물 내부 공간을 출입할 때 |
| `dimension_enter`, `dimension_exit` | 차원을 이동할 때 |
| `flag_changed` | 지정 진행 플래그 값이 바뀔 때 |
| `item_used` | 지정 아이템 사용이 서버에서 확정됐을 때 |
| `battle_finished` | 연동된 배틀 결과가 확정됐을 때 |

플레이어의 매 틱 좌표를 스크립트마다 검사하는 임의 `on_move`는 제공하지 않는다.
지역 인덱스와 앵커 판정기가 경계 변화만 이벤트 런타임에 전달해 성능과 중복 발동을
통제한다. 트리거에는 `once`, 재발동 대기 시간, 플레이어별/월드별 실행 범위를
지정할 수 있다.

## 5. 실행 모델

### 5.1 세션 키

실행 세션은 기본적으로 다음 키를 사용한다.

```text
player UUID + NPC UUID + event resource ID + trigger instance
```

동일 플레이어가 같은 NPC 이벤트를 두 번 동시에 시작하지 못하게 한다. 공유 이벤트나
협동 이벤트는 별도의 `session_scope`을 선언해 파티 또는 인스턴스 단위로 확장한다.

### 5.2 저장 상태

런타임은 최소한 다음을 저장한다.

- 스크립트 리소스 ID와 컴파일 버전
- 현재 명령 주소와 호출 스택
- 지역 변수와 마지막 비동기 결과
- 대기 작업 종류, 작업 토큰과 만료 시각
- 이미 완료한 `once` 작업 ID
- NPC UUID, 플레이어 UUID와 시작 위치
- 이동 중 입력 잠금, 원래 위치와 목적지 참조

`give_item`, 돈 지급과 배지 기록처럼 중복 실행되면 안 되는 명령은 컴파일 시 안정적인
작업 ID를 받는다. 런타임은 지급 성공과 프로그램 카운터 이동을 같은 서버 틱의
트랜잭션성 처리로 기록한다.

### 5.3 비동기 명령 계약

모든 대기 명령은 다음 상태를 따른다.

```text
READY → STARTED → WAITING → COMPLETED → RESUME
                    └──────→ FAILED/CANCELLED
```

- `STARTED`: 런타임이 일회성 작업 ID를 예약한다.
- `WAITING`: UI, 배틀, 이동 또는 획득 연출의 완료 콜백을 기다린다.
- `COMPLETED`: 결과와 부작용을 기록한다.
- `RESUME`: 다음 명령을 실행한다.
- `FAILED/CANCELLED`: 스크립트에 결과 분기가 있으면 해당 블록을 실행하고, 없으면
  안전하게 종료한다.

기능별로 “후속 대화 라벨”을 넘기지 않는다. 콜백은 세션 토큰과 결과만 반환하고
런타임이 저장된 다음 명령을 재개한다.

### 5.4 재접속과 NPC 언로드

- 플레이어가 나가면 세션을 일시 정지한다.
- 재접속 시 자동 재개 여부는 명령별 정책으로 결정한다. 배틀과 룰렛은 기본적으로
  NPC에게 다시 말을 걸면 복구 안내 후 재개한다.
- NPC가 언로드되면 외형 참조만 잃은 것으로 처리하고 세션은 보존한다.
- NPC가 삭제되었으면 이벤트를 종료하되 이미 완료한 보상은 되돌리거나 다시 주지 않는다.
- 스크립트가 빌드 사이에 바뀌면 source map의 안정 ID로 재배치하고, 불가능하면
  진단 메시지와 함께 안전 종료한다.

## 6. 컴파일 파이프라인

```text
.cves source
   │
   ├─ lexer / parser
   ├─ semantic validator
   ├─ tree AST
   └─ control-flow + await lowering
          │
          ├─ runtime IR JSON + source map
          ├─ EasyNPC entity/renderer preset
          └─ web editor AST
```

### 6.1 실행 IR

생성 위치는 다음으로 한다.

```text
data/cobbleventure/event_script/<namespace path>.json
```

IR에는 연속 명령 주소, 조건식, 대기 명령, 안정 작업 ID와 원본 줄·열 source map을
포함한다. IR은 빌드 산출물이며 사람이 직접 편집하지 않는다.

### 6.2 EasyNPC 어댑터

생성된 EasyNPC 프리셋은 복잡한 조건 태그를 갖지 않는다.

```text
ON_INTERACTION
  → /cobbleventure_event start <player> <npc> <script> interact
```

전환기에는 `say`와 `choice`를 기계 생성 라벨의 EasyNPC 대화로 출력할 수 있다.
버튼은 다음 이야기 라벨이 아니라 세션 토큰을 재개하는 명령만 가진다. 장기적으로
자체 대화 화면을 도입하더라도 CVES와 실행 IR은 변경하지 않는다.

### 6.3 검증

빌드는 다음을 오류로 처리한다.

- 존재하지 않는 아이템, 배틀, 플래그 정책 또는 기능 ID
- 템플릿에서 존재하지 않는 변수 필드 또는 타입에 맞지 않는 필터 사용
- 존재하지 않는 마을·차원·공간 앵커와 허용되지 않은 이동 대상
- 결과 변수를 잘못된 타입으로 사용하는 경우
- `default`보다 아래에 있는 이벤트 페이지
- 끝나지 않는 반복문과 도달할 수 없는 필수 명령
- `await` 결과의 미처리 실패가 금지된 명령
- 같은 이벤트 안에서 충돌하는 안정 작업 ID
- EasyNPC 어댑터가 표현할 수 없는 기능을 호환 출력으로 요구한 경우

## 7. 웹 편집기 설계

### 7.1 화면 구성

```text
┌ 이벤트 페이지 ┐ ┌──────── 명령 트리 ────────┐ ┌ 속성 ┐
│ 1 도감 수령 후 │ │ 대화                     │ │ 화자 │
│ 2 스타터 수령  │ │ 대화                     │ │ 내용 │
│ 3 최초 만남    │ │ 룰렛 [완료 대기]         │ │ ...  │
│ + 페이지       │ │ └ 성공 후                │ │      │
└───────────────┘ │   ├ 대화                  │ └──────┘
                  │   ├ 아이템 지급 [완료 대기]│
                  │   └ 대화                  │
                  └────────────────────────────┘
```

- 왼쪽: 트리거별 이벤트 페이지와 페이지 조건
- 가운데: RPG Maker식 세로 명령 목록과 중첩 분기 트리
- 오른쪽: 선택한 명령의 속성 편집기
- 상단: 저장, 검증, 테스트 실행, 텍스트 보기, 변환 미리보기

속성 편집기의 대사 입력에는 현재 지점에서 사용할 수 있는 변수와 필드 자동 완성을
제공한다. 이동 명령은 월드맵, 마을, 차원과 앵커 카탈로그에서 목적지를 선택하며
선택한 도착 지점을 간단한 미리보기로 표시한다.

### 7.2 트리 조작

- `if`를 추가하면 `조건 충족`과 `그 외` 자식 블록을 자동 생성한다.
- `choice`의 각 선택지는 독립 자식 블록이다.
- 명령은 드래그 또는 위·아래 버튼으로 같은 블록 안에서 이동한다.
- 다른 블록으로 옮길 때 실행 범위를 삽입선과 배경색으로 표시한다.
- 접힌 노드는 조건 요약, 자식 명령 수와 주요 결과만 보여준다.
- 라벨과 점프는 `고급 흐름`을 켠 경우에만 표시한다.

### 7.3 비동기 표현

룰렛, 배틀, 아이템 획득, 이동과 페이드는 시계 아이콘과 `완료 대기` 배지를 표시한다.
그 아래의 명령은 자동으로 후속 실행되므로 `완료 후 대화 ID` 필드를 제공하지 않는다.
성공·실패·취소가 서로 다른 흐름을 가져야 할 때만 결과 분기 자식 블록을 표시한다.

### 7.4 분석 도구

- 선택한 플레이어 플래그를 가정한 실행 경로 미리보기
- 지급 아이템·돈·배지의 경로별 합계
- 도달 불가 명령과 중복 보상 경고
- 원본 CVES와 EasyNPC/IR 변환 결과의 읽기 전용 미리보기
- 명령별 중단점과 모의 실행 로그

## 8. 기존 V4 마이그레이션

### 8.1 자동 변환

`npc-event-script.schema.json` V4 문서를 읽어 다음 순서로 변환한다.

1. 이벤트별 라벨과 이동으로 제어 흐름 그래프를 만든다.
2. 단일 진입·단일 합류 조건은 중첩 `if/else`로 복원한다.
3. 선택지 결과와 배틀 결과는 자식 블록으로 복원한다.
4. `give_item` 뒤의 대사, 룰렛 후속 대사와 배틀 콜백을 순차 명령으로 합친다.
5. 반복 대화 조건은 이벤트 페이지로 올린다.
6. 변환된 `.cves`와 차이 보고서를 생성한다.

구조화할 수 없는 순환 점프나 여러 진입 라벨은 `legacy_flow` 블록으로 보존하고
수동 정리 경고를 표시한다. 자동 변환이 원본 파일을 바로 덮어쓰지 않으며
`build.bat npc-migrate --check`와 `--write`를 분리한다.

### 8.2 전환 정책

- V4와 V5를 읽는 기간을 한시적으로 둔다.
- 새 NPC는 V5/CVES만 생성한다.
- V4 편집 화면은 읽기 전용과 `V5로 변환` 버튼만 제공한다.
- 같은 NPC에 V4와 V5가 동시에 있으면 빌드를 실패시킨다.
- 오박사 → 아이템 지급 NPC → 일반 트레이너 → 관문 NPC → 체육관 관장 순으로 옮긴다.
- 모든 운영 콘텐츠가 옮겨진 뒤 V4 생성기와 평면 명령 UI를 삭제한다.

## 9. 구현 단계

### 0단계: 계약 고정

- CVES 문법 EBNF와 타입 체계 작성
- 이벤트 페이지 우선순위와 세션 범위 확정
- 명령별 성공·실패·취소 결과 표 작성
- 내장 변수, 결과 객체 필드와 언어별 템플릿 필터 계약 확정
- 이동 목적지 타입, 안전 도착 정책과 세분화 트리거 목록 확정
- `.cves` 포매팅 기준과 안정 ID 규칙 확정

완료 기준: 오박사, 아이템 지급 NPC, 일반 트레이너와 관문 차단 이벤트를 문법만으로
표현하고 별도 후속 라벨이 남지 않는다.

### 1단계: 도구 코어

- Python lexer, parser, AST, formatter 구현
- 표현식 타입 검사, 템플릿 검사와 스키마 교차 참조 구현
- V4 → V5 읽기 전용 변환기 구현
- AST와 텍스트의 왕복 테스트 추가

완료 기준: parse → format → parse 결과가 의미적으로 같고, 오류가 원본 줄·열을
정확히 가리킨다.

### 2단계: 실행 IR과 서버 런타임

- IR 컴파일러와 source map 구현
- 세션 저장소, 프로그램 카운터와 일회성 작업 저널 구현
- 변수 환경, 표현식 평가기와 현지화 템플릿 렌더러 구현
- `say`, `choice`, 상태와 보상 명령 구현
- 재접속, 중복 콜백과 NPC 언로드 복구 구현

완료 기준: 아이템 지급 직후 서버를 재시작해도 아이템은 한 번만 지급되고 다음
대화부터 재개된다.

### 3단계: 비동기 어댑터

- 룰렛, 배틀, 아이템 획득 연출, 텔레포트와 페이드 어댑터 구현
- 상대 걷기, 마을·도로·공간·차원 앵커 이동 어댑터 구현
- 지역·앵커 경계 판정기와 세분화 이벤트 트리거 연결
- 모든 콜백을 공통 세션 토큰으로 통일
- 기능별 후속 대화 라벨 전달 코드 제거

완료 기준: 각 비동기 기능 뒤에 대사를 배치하기만 하면 자동 재개되고, 실패·취소
분기도 트리의 해당 자식 블록으로 들어간다.

### 4단계: 웹 트리 편집기

- 3열 이벤트 편집 화면과 페이지 목록 구현
- 중첩 조건·선택지 편집, 이동과 접기 구현
- 비동기 배지, 경로 미리보기와 진단 구현
- 변수 자동 완성, 템플릿 미리보기와 이동 목적지 선택기 구현
- CVES 텍스트 보기와 안정적인 저장 구현

완료 기준: 라벨을 한 번도 입력하지 않고 오박사 이벤트 전체를 웹에서 만들고
저장·재열기·게임 변환까지 완료할 수 있다.

### 5단계: 콘텐츠 이전과 제거

- 우선순위에 따라 V4 콘텐츠를 변환하고 수동 검수
- V4/V5 이중 생성 결과의 대사, 조건, 보상 회귀 비교
- V4 편집기, EasyNPC 흐름 추론 코드와 임시 스타터 후속 연결 제거
- 운영 문서와 샘플 갱신

완료 기준: 저장소의 운영 NPC가 모두 CVES를 사용하고 EasyNPC 프리셋에는 사람이
작성한 조건 태그나 이야기 라벨이 존재하지 않는다.

## 10. 테스트 전략

### 단위 테스트

- 문법 토큰, 파서 오류 복구와 포매터 왕복
- 조건식 타입과 리소스 교차 참조
- 트리 AST에서 IR 주소로의 결정적 컴파일
- 안정 작업 ID와 source map 재현성

### 런타임 테스트

- 대화 → 아이템 → 대화
- 대화 → 룰렛 성공/취소 → 대화
- 룰렛 결과의 종 ID를 한국어·영어 이름과 올바른 조사로 출력
- 대화 → 배틀 승리/패배/포기 → 서로 다른 자식 블록
- 획득 직전·직후 로그아웃과 서버 재시작
- 같은 콜백의 중복 수신과 만료 토큰
- NPC 언로드, 삭제와 차원 이동
- 상대 걷기 중 충돌·낙하·시간 초과와 입력 잠금 해제
- 마을·차원 앵커 이동의 청크 준비, 안전 바닥과 배리어층 제외

### 편집기 테스트

- 분기 추가·삭제·이동 후 자식 보존
- AST와 CVES 텍스트 왕복
- 실행 경로와 보상 합계 분석
- V4 변환 미리보기와 원본 비파괴 보장

## 11. 최종 합격 기준

- 제작자가 EasyNPC SNBT, 태그, UUID 매크로와 후속 라벨을 알 필요가 없다.
- 일반 이벤트는 위에서 아래로 읽히고 조건의 두 경로가 같은 화면에 중첩 표시된다.
- 룰렛, 배틀, 지급 연출과 이동 뒤의 대화가 별도 기능별 연결 코드 없이 재개된다.
- 보상은 재접속, 서버 재시작과 중복 콜백에서도 정확히 한 번 적용된다.
- 웹에서 만든 이벤트와 텍스트로 작성한 이벤트가 같은 AST와 IR을 만든다.
- 비동기 결과와 계산 변수를 언어별 대사에 안전하게 삽입할 수 있다.
- 상대 이동, 마을·도로·건물·차원 이동을 등록된 위치 타입으로 작성하고 검증할 수 있다.
- EasyNPC를 다른 NPC 표현 모드로 교체해도 CVES 원본은 변경되지 않는다.

## 12. 이번 계획에서 제외하는 항목

- 퀘스트 전체 시스템과 컷신 타임라인을 CVES 하나로 통합하는 작업
- 임의 JavaScript, Python 또는 Minecraft 명령의 무제한 실행
- 여러 플레이어가 동시에 선택지를 투표하는 협동 이벤트
- 실행 중인 운영 서버에서 임의 스크립트를 무중단 교체하는 기능

이 항목들은 기본 이벤트 런타임과 권한·복구 모델이 안정된 뒤 별도 설계한다.
