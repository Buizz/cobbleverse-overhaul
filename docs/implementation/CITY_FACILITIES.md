# 도시 포맷과 세대별 특수 시설

> 관련 요구사항: 세대 월드의 8개 체육관 도시, 월드 생성 설정, 스토리 랜드마크
>
> 관련 문서: [세대 월드 8지역 및 체육관 도시 생성](WORLD_GENERATION.md), [공용 인스턴스 차원과 상태 변화 건물](INSTANCED_SPACES.md)
>
> 설계 상태: 시설 분류와 세대별 유일성 기준 확정 / 실제 세대별 배치 미정

## 1 목적

각 체육관 도시는 하나의 고정된 건물 목록을 복제하지 않는다. 먼저 도시 포맷이 일반 시설의 규모와 후보를 정하고, 그 위에 세대별 고유 시설과 스토리 랜드마크를 추가한다.

```text
지역의 체육관 도시
  → 도시 포맷 선택
  → 필수 공통 시설 배치
  → 포맷별 선택 시설 조립
  → 세대별 고유 시설 할당
  → 스토리·빌런 랜드마크 할당
  → 도로·입구·NPC·진행 상태 연결
```

## 2 도시 포맷

도시 포맷은 기존 마을 샘플처럼 도시마다 백화점이 있거나 없는 차이를 만든다.

| 포맷 예시 | 공통 성격 | 선택 시설 예시 |
|-----------|-----------|----------------|
| 작은 마을 | 주택과 기본 보급 중심 | 소형 상점, 공원, 농장 |
| 일반 도시 | 체육관과 표준 편의 시설 | 전문점, 키우미 관련 시설 |
| 상업 도시 | 상점과 오락 중심 | 백화점, 카지노, 광장 |
| 대도시 | 큰 도로와 다층 랜드마크 | 백화점, 방송 시설, 대형 공원 |
| 항구 도시 | 해안·선박 이동 중심 | 등대, 선착장, 수산 시설 |
| 연구 도시 | 연구·복원 콘텐츠 중심 | 화석 연구소, 박물관 |

모든 포맷은 체육관, 회복 시설, 기본 상점, 주요 도로와 진행 NPC를 필수로 가진다. 백화점, 주택 변형, 장식과 소규모 편의 시설은 포맷의 가중치 풀에서 선택할 수 있다.

## 3 세대별 고유 시설

다음 다섯 시설은 각 세대 월드에 종류별로 정확히 하나씩 존재한다. 도시 조립 과정에서 우연히 뽑지 않고 월드 생성 설정이 어느 지역·도시에 배치할지 지정한다.

| 시설 ID | 시설 | 기본 역할 | 배치 특성 |
|---------|------|-----------|-----------|
| `fossil_lab` | 화석 연구소 | 화석 감정·복원과 연구 퀘스트 | 연구 도시 또는 박물관 인접 |
| `day_care` | 키우미집 | 포켓몬 위탁·육성 관련 기능 | 외곽 도로와 넓은 마당 |
| `casino` | 카지노 | 오락, 교환소와 선택형 보상 | 상업 도시 또는 대도시 |
| `safari_zone` | 사파리 | 별도 포획 규칙을 가진 대형 구역 | 도시 외곽 입구와 전용 필드 |
| `park` | 공원 | 휴식, 이벤트, 포켓몬 출현과 수집 | 도시 내부 또는 인접 녹지 |

사파리와 공원은 단일 건물이라기보다 입구 건물과 경계가 있는 시설 구역으로 취급한다. 하나의 도시에 여러 고유 시설을 몰아넣을 수는 있지만, 기본 배치기는 서로 다른 도시에 분산하는 쪽에 높은 우선순위를 둔다.

## 4 스토리 랜드마크

스토리 랜드마크는 세대마다 필요한 종류와 개수가 다르다.

| 분류 | 예시 | 배치 기준 |
|------|------|-----------|
| 빌런 본부 | 로켓단 타워, 세대별 빌런 기지 | `faction_id`와 세대 스토리 설정으로 선택 |
| 방송 시설 | 라디오타워 | 대도시·상업 도시의 중심 랜드마크 |
| 항해 시설 | 등대 | 해안 지역과 항구 도시 |
| 사건 시설 | 점령된 회사, 발전소, 연구 기지 | 퀘스트 단계와 지역 진행에 연결 |

코드에서 로켓단을 특별 취급하지 않는다. `rocket`, `magma`, `aqua` 같은 조직은 모두 동일한 `faction_id` 기반 빌런 프로필로 정의하고, 세대별 데이터가 건물 템플릿, NPC, 적 팀, 대사와 완료 상태를 연결한다.

스토리 진행에 따라 내부, NPC와 장식이 바뀌는 시설은 월드 전체 건물을 반복 덮어쓰지 않는다. 외부는 고정하고 내부 인스턴스 또는 상태별 템플릿을 사용하며, 자세한 방식은 [공용 인스턴스 차원과 상태 변화 건물](INSTANCED_SPACES.md)을 따른다.

설정은 월드 생성 전에 확정하고 월드 메타데이터에 사본과 해시를 저장한다. 생성이 끝난 뒤 설정을 바꾸었다고 기존 건물을 자동 이동하거나 덮어쓰지 않는다. 변경은 새 월드 생성 또는 관리자 마이그레이션 절차로만 적용한다.

## 7 생성과 검증 규칙

1. 8개 도시의 포맷과 크기를 먼저 확정한다.
2. 다섯 고유 시설의 `region_id`와 `city_id`가 실제 도시를 가리키는지 검사한다.
3. 같은 `facility_id`가 세대 안에 두 번 선언되거나 누락되면 월드 초기화를 중단한다.
4. 시설 템플릿의 크기, 입구 방향, 도로 연결점과 지형 조건을 검사한다.
5. 빌런 랜드마크의 `faction_id`와 스토리 프로필이 해당 세대에 존재하는지 검사한다.
6. 도시 앵커와 시설 부지가 모두 확보된 뒤 구조물을 배치한다.
7. 사파리처럼 큰 시설은 도시 경계 밖의 예약 구역까지 포함해 충돌을 검사한다.
8. 생성 후 모든 입구까지 실제 보행 경로가 연결되는지 확인한다.

필수 고유 시설이나 스토리 랜드마크의 배치가 실패하면 조용히 생략하지 않는다. 설정된 대체 템플릿 또는 대체 부지를 시도하고, 모두 실패하면 해당 세대 월드를 `FAILED`로 표시한다.

## 8 첫 프로토타입

- 작은 마을 포맷과 상업 도시 포맷을 하나씩 만든다.
- 공통 체육관·센터·상점과 선택 백화점의 조립을 확인한다.
- 화석 연구소와 키우미집을 서로 다른 도시에 고정 배치한다.
- 로켓단을 예시로 `faction_id` 기반 빌런 건물 하나를 배치한다.
- 설정 중복·누락·부지 충돌 시 월드가 `READY`로 전환되지 않는지 검증한다.
- 스토리 완료 전후로 빌런 건물 내부 상태가 플레이어별로 올바르게 달라지는지 검증한다.

## 9 미결정 사항

- 첫 세대의 다섯 고유 시설을 8개 지역 중 어디에 배치할 것인가?
- 카지노의 실제 플레이 기능과 보상 경제를 어떻게 구성할 것인가?
- 사파리를 세대 월드의 보호 구역으로 만들지 별도 인스턴스로 만들 것인가?
- 공원은 일반 포켓몬 출현 구역, 이벤트 장소와 수집 시설 중 어떤 역할을 맡는가?
- 빌런 건물의 외부 상태까지 바꿀 것인가, 내부 인스턴스만 바꿀 것인가?
- 라디오타워와 등대가 없는 세대에서는 대체 랜드마크를 반드시 지정할 것인가?
